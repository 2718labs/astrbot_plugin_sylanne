# Embodiment 3.0：角色机制与计算组织深化稿

状态：设计提案，尚未实现或完成行为验收。承接 `embodiment-3-system.md` 的十二个系统，进一步定义它们如何产生长期、复杂且可修正的行为。用户允许发布 ZIP 约 10 MB；本稿不通过包体积推断能力或运行成本。

后续深化：[社会现场与持续生活](embodiment-3-ecosystem.md)、[记忆引擎](embodiment-3-memory.md)、[研究依据和何时回忆](embodiment-3-memory-theory.md)。这些补充细化本稿的领域合同，不改变现有底座切片的验收范围。

## 1. 架构选择

| 组织方式 | 优势 | 主要代价 | 本方案定位 |
| --- | --- | --- | --- |
| 单一大模型携带全部角色状态 | 语言组织直接，原型容易 | 状态隐含在上下文中，长期一致性、纠错与因果归属难检查 | 不作为权威状态组织方式 |
| 大量常驻子 Agent 分别掌管人格、情绪、记忆 | 分工直观，可以产生不同意见 | 重复上下文、调度开销、互相等待，以及多份状态之间的争议 | 仅在有价值的任务中临时调用不同视角 |
| 共享原子状态图与声明式算子，按需生成认知任务 | 状态统一，可表达复杂内部机制，计算可局部化 | 前期需要认真设计类型、所有权、依赖与执行合同 | 推荐作为全插件计算基础 |

运行结构包括事件接入、角色状态、认知任务、连续/离散演化、行动执行、观测创作六个协作部分。它们有反馈，但不要求每个事件顺序经过所有模块。

## 2. 七张相互关联的图

这些图是同一权威存储的类型化视图，不是七份独立数据库，也不是七层递归调用。

| 图 | 节点与边的含义 | 不允许的混同 |
| --- | --- | --- |
| 证据与来源图 | 观测、陈述、引用、解释、派生关系、撤销 | 别人说过某事，不等于某事已被确认 |
| 信念与视角图 | 角色相信什么、竞争假设、他者可能知道什么 | 对他者的推断不冒充他者真实内心 |
| 需求与问题图 | 需求、重要事项、冲突、未解决问题、解决条件 | 一次短暂激活不自动升级为长期目标 |
| 社会关系图 | 对象、具体领域的信任、共同经历、群体角色与边界 | 对某人的专业信任不直接等于情感亲近 |
| 动力耦合图 | 数值状态块、驱动、恢复、允许的耦合 | 情绪标签不是一个可任意赋值的总开关 |
| 目标与行动图 | 愿望、承诺、计划、行动资格、执行和结果 | 想过、计划过、尝试过和完成过必须分开 |
| 算子依赖图 | 读写关系、失效传播、可重算单元与执行顺序 | 数据依赖与动力耦合不能直接当成同一种边 |

每个节点都有稳定标识、类型、所有者、版本、有效时间和来源。带不确定性的状态还必须声明其含义：经验概率、区间、未校准分数或定性等级；不能把它们混算成一个看似精确的置信度。

存储角色分为源记录、已提交状态、可重建投影与可淘汰缓存。原始事件/设定版本是源记录；经过注册算子提交的人格、信念等是当前权威状态；检索索引、摘要展示和图布局属于投影或缓存。工作台、摘要和历史回放不能绕过算子与事务反写权威状态。

## 3. 持续问题是各系统之间的重要连接对象

增加 `Concern` 类型，表示角色当前在意而尚未解决的事项，例如一次尚未澄清的误解、一项未兑现的承诺、一段关系的边界分歧或尚未完成的创作。

字段包括：对象、源事件、涉及的需求和价值、竞争解释、关联情绪、相关目标、已有行动、当前状态、解决条件、下次重新关注条件。它引用原子状态，不另存一套情绪或关系真值。

生命周期为：出现 → 活跃 → 暂缓/等待 → 重新评估 → 解决/放弃。归档是独立的存储状态，不能等同于问题解决。重新激活需要新证据、明确时间条件、计划步骤或新情境；不能因为求解器多运行几轮而反复增加问题强度。

`Concern` 可以跨对话存在。新建聊天清理的是对话现场，不能顺带删除一项仍在生效的承诺。多个 Concern 通过资源、价值和关系发生竞争，例如“想继续安慰对方”与“当前需要休息”同时存在。

身份键由所有者、对象、事项类型和锚定事件/承诺组成。语义相似只能提出合并候选，不能直接把两个对象的问题合并。合并或分裂保留原标识和来源映射，已有证据贡献不会重复消费。解决与放弃均释放活跃注意预算和唤醒订阅，但关联情绪进入自己的恢复过程，关联承诺按其状态机履行、改约或明确取消，不能静默消失。重开需要记录触发原因与新版本。

## 4. 人格是一组会发生张力的长期结构

人格分为设计者设定、长期特质、价值优先级、习得互动策略、自我认知和自传解释。各部分有独立来源与更新规则。

- 价值冲突具有情境：诚实与体贴、自主与亲近、守约与现实能力可以同时重要。
- 社会角色影响表达策略：同一角色面对熟人、陌生人、群体或合作伙伴，表现可以不同，但需能追溯到共同的价值和经历。
- 自我认知可以与行为证据不一致：认为自己擅长安慰，与一次安慰实际失败需要分别记录，触发反思，而不是立即整体改写人格。
- 成长由多个独立经历、明确的更新时间和变化条件驱动。一次重复回放不能累计成多次学习。
- 用户修改角色设定生成新设定版本；历史经历保留其当时版本，不被重写成“她一直如此”。

行为验收：相同措辞在不同价值冲突和社会场景下可产生不同策略，同时保留长期人物特征；新会话不重置这些特征。

## 5. 情绪过程以事件、对象与阶段组织

一个情绪过程记录：源事件、解释版本、对象、评价结构、当前反应、持续影响、调节策略、表达历史和终止条件。多个过程可以并行，不必先合并成一个总分。

评价至少涉及目标相关性、期望偏差、责任归属、可控性、损失/收益预期、价值一致性、关系含义与证据可信度。各维度的作用算子必须有明确定义。

例如角色可以对一个人的失约感到不满，同时担心这个人的处境；对其某项能力保持信任，同时暂时降低对其守约性的预期。这些状态不能用一次正负相抵消成“中性”。

区分以下时间过程：

1. 事件发生时的即时反应。
2. 对特定对象或事项的持续情绪。
3. 较广泛的心境与资源负荷。
4. 对自身情绪与表达的再次评价。
5. 恢复、重评、表达克制和关系修复。

调节不是无成本抹除情绪。它可以消耗注意和精力，也可以改变表达资格而暂时不改变内在感受。恢复速率与触发条件属于待验证建模假设，不能直接宣传为心理规律。

不同情绪过程之间使用显式耦合：共享的疲劳资源、注意竞争、同一事件的不同解释或共同对象。是否合并、分裂或结束一个过程由状态机与证据决定。

每类情绪过程还必须定义行为读出合同。例如担心可影响关怀/求证候选，不满可影响边界表达/重新协商候选；它们分别输出候选资格、倾向和表达要求，不先压成一个正负总分。读出函数声明输入、适用情境、方向约束和数值敏感性，再由执行系统联合仲裁。

验收先检查行动合同，再检查语言。固定证据、对象和其他状态，仅干预不满分量，应观察到所声明的边界表达倾向变化；关怀和事实依据不应出现合同外变化。自由模型说出“我既担心又不满”本身不能证明情绪机制生效。若模型故意生成与行动合同无关的回复，验证链路必须能发现或降级处理。

## 6. 误会被纠正，不等于此前经历从未发生

把纠正的目标拆开：

| 对象 | 新证据到来后的处理 |
| --- | --- |
| 对事实的判断 | 撤销或降级受反证影响的信念 |
| 由错误解释直接导出的评价与关系更新 | 按来源修订或撤销对应贡献 |
| 已实际发生的内部负荷 | 按模型保留真实提交过的经历及恢复过程 |
| 已发送的话、已执行的行动 | 保留原始历史与外部结果 |
| 对过去经历的解释 | 新增解释版本，保留当时相信什么与现在怎样理解 |
| 修复关系的责任 | 根据已发生行动新增澄清、道歉或重新协商的候选 |

这里的“实际内部负荷”仅指模型在真实推进过程中提交过的状态经历，不包括数值迭代、设想分支或未提交候选。不能把一次求解的中间迭代当成反复受伤。

完整版本明确保留两类对象：不可被新解释倒改的 `ExperienceRecord`，以及由当前有效解释计算的状态贡献视图。前者记录当时真实提交的过程、时间区间、解释版本与资源消耗；后者可因证据纠正而失效和重建。零时长的数值精修不产生额外经历时长或消耗。

非线性耦合下不假定每项贡献都能直接相减；使用带来源的检查点和受影响子图重算，或者执行合同规定的修订算子。反事实回放独立保存，不覆盖真实经历账本。当前小切片的撤销驱动重放仅验证较窄的纠错合同，后续实现需要采用上述双层语义。

## 7. 关系是分领域、分场景、分阶段的结构

同一对象的关系包含不同领域的信任、亲近与距离、共同承诺、边界协商、互动惯例和仍未解决的问题。关系身份与会话身份分离。

群聊中还需要事件可见范围、在场对象、公开承诺、私下信息与角色定位。对 A 的失望不能转移为对同群 B 的评价；私下共享信息也不能仅因为处于同一 Bot 下就进入另一场景的表达依据。

修复是过程：发生分歧 → 识别影响 → 提供解释 → 澄清事实 → 调整预期或承诺 → 观察后续行为。道歉可以触发修复，但不必瞬间恢复所有关系状态。

跨关系分面的影响必须由注册的传播算子声明，并有相应证据。总体相处预期可以是依赖多个分面的派生读出，但不能反写所有分面。守约证据缺失不能自动改写专业能力判断；只有新证据确实关联另一个领域，才启用相应更新。

行为验收：能够表达“我相信你的能力，但这次约定仍需要重新安排”；也能在事实澄清后修正指责而保留对已发生沟通失误的责任。

## 8. 记忆区分经历、当时解释与现在解释

事件事实、原始表达、当时信念、后续解释、自传摘要分别记录。摘要是可重建的派生视图，不能成为失去来源的新事实库。

记忆检索由当前问题、对象、目标和时间共同决定。情绪可以影响哪些经历更容易被关注，但不能授权系统编造经历。检索结果保留来源和不同解释版本。

巩固需要区分：重复收到同一消息、独立发生的相似经历、同一经历被反复回想。三者不能产生相同的学习权重。

忘记分为检索降权、摘要压缩、归档与按规则删除。未完成承诺、关键来源及必要修订链不能被普通容量淘汰策略悄悄清掉；归档后证据分辨率降低也必须显式可见。

角色可以重新理解一段经历，形成新的自我叙事，但不能把后来想通的解释写成当时就知道的事实。

解释失效时，依赖图继续传播到摘要、自我认知、习得策略与长期目标。仍有其他有效来源的部分保留，其余部分标记失效并重建；不能一边撤回错误事实，一边继续使用完全由它支持的“我总被这样对待”叙事。当前行动不可读取已知失效的旧摘要，后台重建完成后才能发布新版本。

## 9. 认知任务与反事实分支

推理任务由当前问题生成：澄清歧义、比较解释、理解对方立场、检查自身归因、推演行动后果、修复计划等。每个任务声明输入快照、预算、停止条件、结果类型和依赖。

反事实分支读取同一快照，在隔离分支中演化。分支结果带 `simulated` 来源，只能为计划选择提供预测，不能直接写入已发生事件、关系经历或人物自传。

她可以设想“对方可能拒绝这次邀请”，但不会因为设想过，就把对方记成已经拒绝过自己。拟发送一段温柔的话，也不能在发送前给自己增加关系奖励。

预期结果可以影响当前的担忧与行动准备，但这类影响必须标记为预期驱动，与实际受伤、实际拒绝和关系违约分别结算。这样既能表达期待、担心和犹豫，也不让想象产生虚假的现实责任。

记录两个独立维度：该情绪过程是否在现实运行中实际提交，以及其对象事件是已观测、转述、假设还是模拟。因设想而实际产生的担忧可以留下恢复史，但设想中的拒绝仍不得结算为对方责任或真实共同经历。

分支预算应按当前决策的影响与不确定性分配。简单问候不启动完整反事实树；重要承诺、强冲突或较大外部行动才可能展开多个分支。

内部视角可以提出不同候选，例如关怀、边界、好奇与责任。它们是读取同一状态的计算任务，不能各自私藏一份永久角色真值。

## 10. 行动选择同时考虑多个目标

行动候选包含：对象、交流意图、支持证据、预计影响、资源成本、前置条件、承诺变化与外部副作用。先过滤不具资格的候选，再比较合格候选对当前目标的贡献。

硬约束与可权衡偏好必须分开。事实不足时，不允许仅因一个加权总分更高就把猜测作为事实输出；已经明确的用户设置也不是能被某个情绪权重抵消的软偏好。

可权衡目标之间保留冲突说明，例如“关心对方”和“明确约定”同时成立。表达合同允许一个行动承载多个意图，而不是强迫整段回复只有一种情绪或语气。

决策分数的数值误差需要由相应评分算子传播。求解器给出的状态误差不能未经推导就转称为行动选择置信度。若数值精修不会改变当前选择，应停止数值投入；若关键不确定性来自语义，应求证或暂缓，而不是增加求解迭代。

## 11. 生活线、成长线与关系线共同推进

持续活动拥有目标、阶段、资源消耗、产出和未完成事项。生活调度推进实际活动，产生经历，再进入记忆、需求、自我认知和行动系统。

例如一个持续创作项目可以经历兴趣、开始、困难、暂停、恢复和完成。它会改变注意与精力，产生值得分享的真实内部进展，并影响之后的日程。主动消息必须引用已经发生或明确计划中的事件，不能先随机生成一篇日记再把内容补写成经历。

多个长期线索可以竞争时间，并在共同事件上交汇：答应别人完成一件事、自己的兴趣项目与休息需求相互影响。重启和长时间离线需要明确的追赶策略，不无限补跑每个错过的 tick，也不假定所有计划都已完成。

## 12. 算子编译、循环与执行

算子注册信息至少包含：输入/输出类型、所有者规则、读写集合、时间语义、更新条件、证据来源限制、可取消点、费用估计、精度要求与失败策略。

时间合同必须指出算子消费物理时间差、离散事件还是固定问题的数值精修；源事件时间、接收时间与提交时间分别作为元数据记录。生活进度使用显式映射的角色生活时间，不能借用推理轮次推进。数值联合求解块还要声明可检查的适用域、不变量与证书条件；越界或缺乏证书的结果标记为未验证/未收敛，不能提交成已证明稳定或唯一的结果。

装配阶段检查引用、类型、权限和写入冲突，并分析算子依赖图中的强连通分量。循环分为三类：

1. 可证明满足指定条件的联合求解块，使用相应求解器与误差检查。
2. 明确跨物理时间或离散事件延迟的反馈，按其因果时间推进。
3. 未定义求解或延迟语义的循环，拒绝装配并给出诊断。

复杂情绪可以采用受限线性块、离散阶段转换、受限参数更新和经定义的非线性算子组合。线性块的误差证书不自动覆盖模式切换、非线性反馈或整个系统的稳定性；这些必须分别建立适用条件和验收。

运行时基于脏节点和必要耦合边界建立局部任务。冻结快照、暂停、续算、取消和候选提交属于任务生命周期，不能悄悄改变事件时间或再次消费同一证据。

跨所有者事务验证完整读集后共同提交。外部调用不放在数据库事务中；使用持久化意图、版本检查和外部结果记录连接两者。并发候选过期时重新装配，不能把旧结果直接套在新状态上。

第一笔事务可以提交内在状态、行动意图、完整读集引用与待执行 outbox；不能提前提交依赖实际执行结果的成功结算。发送资格认领另有持久化状态，外部执行后再由带证据等级的结果事件提交相应承诺、活动或关系结果。结果未知时保留不确定性，不自动重发，也不结算为成功；与外部执行无关、已有证据支持的内在关系更新不必等待投递。

多假设分支采用冻结基线与稀疏覆盖层，分支数量、展开深度、存活时间和持有快照均受预算限制。读写有向无环的部分按拓扑执行；动力耦合块进入对应联合求解器，不通过模块之间递归调用求解。证书不足的算子只能输出明确的候选或失败状态，不能把“残差小”自动视为语义正确或一般非线性问题的全局保证。

## 13. 四种预算与四类误差分别管理

预算分为：前台延迟、CPU/内存、模型调用成本、后台吞吐与积压。物理经过时间、离散事件序号、数值精修次数保持独立。

误差分为：离散系统求解误差、时间离散误差、局部截断误差、语义及模型误差。前几类也需要在单位与传播条件相容时才可合成；语义误差不能直接加进一个数值残差。

资源紧张时，优先暂停不影响当前交互的维护和推演，保留权威状态及恢复信息。内存中的活跃工作集与长期持久化容量分开；淘汰缓存不能导致角色身份、承诺或关键关系遗失。

预算耗尽、恢复阻塞、模型不可用和证据不足都应形成可解释状态。不能用静默随机值伪装正常演化。

## 14. 工作台也需要达到重型产品的深度

- **角色创作**：背景、价值张力、关系倾向、需求与节律、习惯、表达偏好、成长规则。
- **当前内在活动**：正在关注的问题、竞争解释、混合情绪、目标冲突、等待中的承诺。
- **关系档案**：分领域预期、共同经历、边界、未完成修复与跨会话连续性。
- **记忆时间线**：事实、当时解释、后续修订与自传摘要的来源关系。
- **行为解释**：为什么选择求证、为什么暂缓、哪些证据影响了本次表达。
- **情境实验室**：在隔离快照上比较角色方案与假设，不污染正式经历。
- **运行诊断**：计算与模型费用、局部/全量计算差异、失效范围、任务阻塞与恢复。

普通使用展示角色体验和可理解的解释；算子、事务及误差细节放在高级诊断中。

## 15. 深度验收场景

| 场景 | 必须观察到的能力 |
| --- | --- |
| 失约后解释原因，但证据仍不完整 | 不满与担心并存，保留假设，能选择求证 |
| 新证据证明之前误会了对方 | 修订信念和相关关系贡献，保留已发生表达并考虑修复 |
| 对同一人专业信任高、守约预期低 | 分领域关系不坍缩为一个好感总分 |
| 想继续帮助对方，但已疲劳且有未完成承诺 | 多目标冲突产生可解释的行动与安排 |
| 想象一次邀请遭拒，现实中尚未邀请 | 预测分支不污染真实关系与记忆 |
| 同一事件被重复转发、反复回忆 | 不被当成多个独立外部证据学习 |
| 新建对话并切换回来 | 人格与适用关系延续，对话局部状态按规则重置 |
| 撤销一条支撑多个摘要和目标的错误信息 | 依赖失效传播完整，已发生行动历史不被删改 |
| 长时间离线后恢复一个生活项目 | 进度与资源按明确策略恢复，不虚构完成记录 |
| 相同输入在不同历史与需求下出现 | 行为差异能由状态及证据解释，同时角色保持连续 |
| 降低计算预算或暂停后继续精修 | 同一模型误差要求下结果一致，物理时间不被精修推进 |
| 模型输出与既定行动合同冲突 | 表达被修订、降级或暂缓，不另造权威角色状态 |

这些是待实现的验收要求，不是已经通过的实验结果。

## 16. 后续设计包

下一步分别细化五个设计包：状态类型与所有权、情绪评价与动力算子、Concern/信念/关系机制、记忆与长期执行、表达与工作台。每个设计包都需要字段、操作合同、生命周期、纠错与恢复行为、可观察场景；然后才能进入相应模块实现。

当前基础代码继续作为数值与事务行为的测试设施。此次深化设计不意味着已有代码已经具备多所有权、混合情绪、长期 Concern、反事实分支或完整生活系统。

## 17. 共同对象与跨模块协议

领域模块通过以下对象协作，不能只传一段自由文本后各自重新解释：

| 对象 | 必备信息 | 合法变化 |
| --- | --- | --- |
| EvidenceUnit | 原始事件、来源主体、观测方式、引用关系、独立性来源、有效时间 | 新增反证、受控脱敏/删除、来源失效 |
| Belief | 命题、主体视角、支持与反对证据、替代解释、不确定性类型 | 更新状态、撤销、分裂假设、暂缓结论 |
| Concern | 在意事项、对象、相关价值/需求、情绪过程、目标、解决条件 | 激活、等待、重评、解决、归档 |
| AffectEpisode | 事件/对象、评价版本、状态块、阶段、调节与表达历史 | 演化、调节、分裂/合并、结束、修订归因 |
| RelationshipFacet | 角色/对象/领域/场景、适用边界、预期、来源贡献 | 有依据的更新、边界协商、修复 |
| Commitment | 主体、对象、内容、期限、条件、授权来源、执行与表达状态 | 提议、作出、履行、改约、撤回、失败结算 |
| Activity/Plan | 目标、步骤、资源、依赖、阶段、进展证据、放弃条件 | 调度、暂停、继续、完成、重规划 |
| ActionContract | 对象、意图、事实引用、表达/工具约束、状态读集、副作用 | 批准、过期、尝试、已知结果、未知结果、补救 |

同一来源被检索、摘要、反复回忆或多轮模型复述，不能因此变成多个独立证据。不同来源之间的独立性未知时，也不能直接当作多次确认。人格、关系和知识更新需要消费明确的来源单位，记录已消费的贡献。

来源类别与断言状态使用不同字段。平台观测、角色设定、内部过程、模型推断和模拟分支描述来源；已确认、转述、争议与未知描述断言状态。角色背景中的设定经历可以参与自我叙事，但不能冒充与真实用户共同发生过的经历。收到一句话这一观测，可以确定；这句话声称的内容，仍可能未知。

承诺与计划要有状态语义：内部打算、准备表达、已尝试表达、可确认已作出、实际履行分别记录。平台仅返回“接口已接受”时保留这一证据等级，不能把它扩大成对方已经阅读、同意或满意。

除了三条独立推进轴，还记录源事件时间和接收/提交时间。迟到的新证据可以改变现在的判断与历史解释视图，但不能改变过去实际发送的内容。历史回放结果和当前权威状态要在 API 与工作台中清楚区分。

## 18. 设计包的具体验收产物

| 设计包 | 必须先交付的设计产物 | 实现后的验收重点 |
| --- | --- | --- |
| 状态与运行图 | 所有权矩阵、原子类型目录、算子合同、时间语义、事务与循环分类 | 局部更新和全量参照一致；跨所有者无部分提交 |
| 人格与情绪 | 价值/需求模型、评价维度、过程状态机、算子适用域、纠错贡献规则 | 混合情绪、调节代价、人格连续性和来源归属 |
| 信念与关系 | 假设竞争规则、Concern 生命周期、关系领域、边界与修复协议 | 暂缓判断、分领域信任、关系修复轨迹和不误伤其他对象 |
| 记忆与执行 | 分层记忆、源证据去重、巩固/归档、目标承诺状态机、生活调度 | 跨会话延续、重复输入不重复学习、离线恢复不虚构经历 |
| 表达与工作台 | 行动合同、实现与一致性检查、交互原型、情境实验协议 | 自然表达可追溯；诊断不取代真实行为验证 |

每个包都附典型场景、反例、失败/降级行为、成本测量口径和迁移边界。较大的产品规模通过这些机制和验收产物逐步兑现，而非仅靠更多模块名称。

## 19. 一个问题跨数日推进的设计示例

以下是目标行为示例，不是已经产生的运行记录。

1. **形成约定**：角色与用户约好第二天讨论一个共同项目。记录承诺、项目步骤、相关对象和适用期限；生活日程预留对应活动。
2. **约定未发生**：时间事件确认当前尚无履约记录，但不直接得出对方故意失约。生成 Concern，激活失落、担心与对后续安排的不确定性。
3. **内部产生冲突**：角色重视守约，也重视体谅；她想继续项目，但当前疲劳且还有另一项承诺。执行系统比较等待、询问、改期和先做独立部分。
4. **规划但尚未行动**：隔离分支预测直接质问、温和询问、暂时等待的可能后果。这些预测影响候选比较，不作为用户真实行为进入关系账本。
5. **实际表达**：提交一个兼顾关心与安排的行动合同。语言可以表达“我有些担心，也想确认我们的安排”，并根据表达合同限定事实与承诺。
6. **获得解释**：用户说明发生了意外。事件日志记录其陈述，信念图按证据状态更新；担心、失落、体谅以及具体领域的预期可以分别变化。
7. **发现先前误判**：若后续证据证实解释，修订不成立的归因与相关关系贡献。之前说过的话、真实消耗的精力和需要澄清的责任保留。
8. **后续履约**：双方重新约定并完成项目。实际进展进入关系修复、自传记忆、活动成果与新的日程；一次完成不自动清除所有其他未解决事项。
9. **相似情境再次出现**：系统检索已修订经历，而不是只检索最初的不满摘要。她可以保持在意守约的特征，同时更愿意先求证。

这一条线同时调用人格、需求、情境、信念、情绪、关系、记忆、规划、表达和生活机制。深度来自状态之间有持续后果，而执行仍然只唤醒当时相关的节点。

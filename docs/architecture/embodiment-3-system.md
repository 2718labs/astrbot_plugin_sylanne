## 1. 产品规模与执行效率分别设计

Sylanne 3.0 的目标是具有人格连续性、复杂情绪、长期关系、自传记忆、认知活动、行动意图与日常生活的持续角色系统。聊天只是它与外界交互的一种方式。

重型意味着有丰富且相互作用的内部机制，有长期行为后果，有完整的配置、观测与维护能力。计算组织采用原子状态、依赖图、事件调度和增量求解，消除每条消息都穿越多层全量处理的浪费。不能把少量情绪数值、三个语义标签或固定回复模板升级为最终产品定义。

当前 `rewrite/` 实现是验证计算与因果合同的工程底座。二维系统、单状态作用域、全量时间分段重放和显式命令均属于试验切片。

## 2. 十二个协作系统

| 系统 | 持有的主要状态 | 必须形成的行为后果 |
| --- | --- | --- |
| 主体与人格 | 身份、自我叙事、价值优先级、特质、偏好、自我评价、长期边界 | 同一角色跨对话保持连续；人格变化有历史依据 |
| 身体与内在需求 | 模拟精力、疲劳、紧张、休息需求、社交饱和、活动负荷与节律 | 改变注意力、情绪恢复、行动成本和生活安排 |
| 世界与情境 | 实体、事件、时间、场景、事实、假设、角色之间的信息差 | 区分事实、转述、猜测，以及谁知道什么 |
| 情绪评价与演化 | 事件评价、对象化情绪、混合情绪、情绪残留、调节过程和元情绪 | 同一事件因目标、关系、人格和当前需要产生不同反应 |
| 社会关系 | 对具体对象的信任、亲近、距离、依赖、边界、互惠历史及群体关系 | 不把不同用户、群体和人格的经历压进同一条好感曲线 |
| 多层记忆 | 工作记忆、事件记忆、语义知识、关系经历、程序习惯、自传片段 | 检索、巩固、遗忘、纠错和叙事组织有不同机制 |
| 注意与认知 | 显著性、注意预算、解释假设、归因、反事实、冲突与不确定性 | 决定哪些事件值得深思，哪些判断需要暂缓 |
| 动机与执行 | 需求、愿望、目标、承诺、计划、行动候选、执行进度 | 行为由目标与约束共同决定，不能仅由情绪阈值触发 |
| 对话与表达 | 话题轨迹、交流意图、语气、节奏、表达边界、修复策略 | 最终语言遵守同一份角色状态及行动合同 |
| 生活与主动行为 | 日程、兴趣、活动、习惯、事件机会、行动后果 | 离线期间能有有限且可追溯的发展，而不是定时随机生成独立日记 |
| 运行与持久化 | 原子图、版本、依赖、任务预算、事务、事件日志、投递记录 | 可暂停、恢复、纠正、回放；避免重复处理与失控并发 |
| 工作台与角色创作 | 人格方案、模块配置、关系视图、记忆浏览、因果轨迹、成本与健康状态 | 用户能创作角色、理解反应、纠正解释和维护长期运行 |

这些系统不是每轮都启动的十二个 Agent，也不是必须依次执行的十二层。它们通过共享状态和有声明的算子依赖协作。

模拟身体状态必须标明来源和假设。没有传感数据时，不把内部变量描述为真实生理测量。

## 3. 情绪系统需要重新建模

情绪不是语言模型返回一个标签后给分数加减。一次完整的情绪过程至少包括：

1. **对象与情境建模**：谁对谁做了什么；直接表达、第三方转述和引用不能混同。
2. **事件评价**：与当前目标的相关性、期望偏差、可控性、责任归属、关系意义、规范或价值冲突；保留未知与解释竞争。
3. **受限输入装配**：根据证据可信度、人格、关系和需求，把评价转换为对应状态块的驱动。模型只能提议合同允许的自由度。
4. **多时间尺度演化**：即时反应、持续心境、紧张积累、恢复和对象化情绪相互影响。耦合可以丰富，但必须声明方向、作用域和数学条件。
5. **调节与元情绪**：重新评价、注意转移、克制表达、对自己反应的评价等过程，通过明确算子改变状态或行动资格。
6. **行动责任**：情绪影响关注、回避、求证、表达和计划；一次已经发送的行动及其结果不能被后来的解释改写成没有发生。

愤怒、恐惧、内疚、羞耻、感激、骄傲、嫉妒、依恋等可以形成不同的对象化过程。是否建立独立状态、如何耦合，需要语义定义和行为实验支持，不能为了显得复杂机械堆维度。

线性耗散块是当前已实现的一类算子。非线性调节、门控、长期参数更新、符号状态转换需要各自的定义与验收；不能继承线性块的稳定性结论。

## 4. 原子图承载整个系统

每个原子携带：类型、语义、所有者、来源证据、版本、有效时间、可信度、依赖与可写算子。原子可以是数值块、结构化事实、关系边、记忆索引或行动状态，不要求把所有信息塞进一个数值向量。

所有权至少区分：

- Bot/角色：人格、自我与长期需求；新建聊天不应清空。
- Bot/角色/对象：关系、对象化情绪与共享经历；能在明确定义的身份映射下跨会话延续。
- 对话/场景：话题、临时注意和当前交流意图。
- 事件/证据：不可混淆的观测、解释版本、纠正与撤销关系。
- 活动/计划：生活任务、承诺及其执行结果。

不能靠扩大一个 `session` 字符串代替上述模型。跨所有者的依赖读和原子提交，需要新事务合同：完整读集、精确写集、权限、版本及共同提交边界。当前 Store 的单 Scope 候选事务尚未建立这一能力。

算子声明读哪些原子、写哪些原子、适用条件、数值或语义约束、计算成本与误差要求。事件进入后，仅激活受影响的依赖子图；长期低频过程和即时对话使用不同调度优先级。

局部求解必须保留必要的耦合边界与残差核查。当前求解器执行完整小系统验证；尚不能宣称已经实现大型图的稀疏局部精修。

## 5. 一个具体情境

用户失约后解释自己遇到了意外。世界模型先区分已确认的失约、用户的新陈述和未证实原因。记忆提供以前是否经常失约；关系系统提供当前信任与边界；价值系统判断承诺的重要程度；需求系统提供角色当时的负荷。

情绪系统可能同时保留失落、担心和未消除的不满。认知系统维护不同解释及不确定性。执行系统在求证、安慰、表达受伤、调整下一次约定之间选择行动，表达系统实现与该行动一致的语句。

如果之后发现误会，系统撤销相应解释的后续影响，更新记忆和关系依据，同时保留已经表达过不满的历史与可能需要修复关系的责任。角色的变化因此有连续的因果链。

## 6. 语言模型在多个位置工作，但不形成另一份权威状态

模型可参与情境理解、受限评价提议、记忆摘要、计划候选和语言实现。相关工作可合并请求、复用上下文并缓存；深度思考只在歧义、冲突或后果需要时触发。

最终表达合同应包含交流意图、对象、可引用事实、必须表达或回避的承诺、情绪允许范围、语气和动作资格。语言实现需经过合同一致性检查；失败时降级为已知合格的表达，或者暂缓行动。固定模板目前只是证明合同生效的测试方法。

输入构造、状态演化、解释的真实合理性、最终语言一致性是不同验收层。数值误差证书不证明模型理解正确，也不证明自由语言忠实。

## 7. 重型系统的预算与运行

分发体积以完整候选包的实测结果为准。模块完整性、原生内核、工作台、角色预设与必要资源按产品需求纳入打包，不以追求极小安装包为由裁减已确定的能力。当前尚未生成并测量正式安装包。

打包验收需报告目标平台、压缩后大小、解压后大小及主要组成。运行时用户数据、缓存、开发环境与无关构建中间产物不进入发布包。安装体积与内存、CPU、响应延迟、模型调用费用分别制定和验证预算；分发体积验收不代替运行资源约束。

前台对话、后台记忆巩固、关系修正、生活活动、诊断回放分别受预算和优先级控制。每种任务声明时限、可中断点、重试资格、缓存条件、计算量和模型调用成本。

重型系统可以做很多事，但不要求每轮做所有事。先交付当前交互必须的结果，允许不影响已提交行动的后台维护继续；任何会改变当前行动依据的后台结果，都必须重新检查版本。

持久化日志记录收到事件、接受解释、状态提交、行动授权、发送尝试和外部结果。崩溃恢复不能凭超时就把未知投递当成失败重发。开发切片当前保守地保留未完成 claim，并阻止同一目标继续处理；正式产品需要可观测且受验证的恢复流程。

## 8. 实施顺序与验收

1. **底座与退役**：保留现有数值/事务/调度/宿主探针，移除旧运行入口、旧核心和旧发布路径。完成新入口的本地验证。
2. **多所有权原子图**：类型注册、分层作用域、跨所有者事务、依赖失效、事件与参数版本、增量结果和全量参照一致性。
3. **主体—情绪—关系主闭环**：人格/价值/需求、丰富评价、对象化情绪、关系更新、调节与行动合同。建立具体情境回放与行为评价集。
4. **记忆—认知—执行闭环**：分层记忆、假设管理、归因、目标/承诺、规划与对话连续性。验证纠错传播及长期角色连续性。
5. **生活与主动性**：活动日程、习惯、需求、主动行为与外部结果进入同一状态和因果基础，验证空闲成本及长期行为。
6. **完整产品**：角色工作台、创作预设、诊断恢复、数据迁移、原生二进制分发、真实平台测试和长期成本/质量比较。

每一阶段都交付可运行的纵向场景。模块数量、类数量、代码行数与公式复杂度不作为质量指标；角色能力的覆盖与深度，以及正确性、可解释性、长期成本和可维护性共同决定验收。

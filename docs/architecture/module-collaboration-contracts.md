# Sylanne 3.0 全系统协作合同（设计 v1）

日期：2026-09-27。适用当前本地 D01–D13 完整设计，不代表实现。本文协调公共语义；各域主规格负责领域规则；D06/D07 已完成合同继续生效。D13 详细耦合见[十三域总装](sylanne-3-thirteen-module-coupling.md)。冲突在主任务显式裁决，不能静默选一份更方便的规则。

## 2. 共用执行与来源合同

- 全部权威对象进入 D11 共享图；Owner 是 Bot/persona 等隔离域，模块是写者能力。模块包不等于常驻 Agent，模型不固定名称，按任务能力与宿主配置选择。
- D03 稳定实体/世界事件、D06 来源家族、D07 Concern、D08 目标/承诺、D10 活动实例各有身份且互相引用，不能为了去重把它们压成同一个 ID。
- 稳定 activity/effect + 冻结输入 attempt + phase operation + 实际调用 call_id；技术重试不是新人物经历，换 attempt 不重置父预算。未知提交先核实原收据，不能新 ID 重放。
- 所有候选带 schema、合法写者、用途/受众/供应商政策、来源、现实性、时间、完整读集和查询域/访问/删除 epochs、父预算及截止时间。当前读集、长期语义失效依赖、历史成因引用、数值耦合分别表示；所有内容引用参加权限和删除闭包。
- 事实资格、角色主观确信、实际内部活动、模拟内容是分立维度。真实想象可以引发当前感受，想象的拒绝不能算作对方实际拒绝；模型文字不是提交或执行证明。
- 一次合法采用所必需的领域状态、体验/选择、资源实际结算、贡献去重和 outbox 在同一角色命名空间一致提交。跨角色分享走 D06 transfer，不宣称全局事务。回忆唯一组合提交按 D06 C04，普通认知按 D07 C04，不能双记。
- D02 分项角色资源与 D11 实际调用费用分账；已发生劳动按 call/component 去重，技术核查不伪装角色劳动；人物区间按实际角色片段并集，暂停空隙不计劳动。父子共享预算，不因跨模块另领免费额度。
- D08 定义行动所需 RequiredCheck，D03/D05/D06/D08/D11 提供基础回执；声称社会角色授权或义务的行动必须包含 D03 `RoleBindingResolution`（主体、对象/群体/场景、行动类、purpose、binding/norm/read-set 版本与有效期）。主动联系还强制要求 D10 ContactPolicyCheck（同意范围、静默、频率、无回应闸门及配额版本），D06 统一装配既有提供者，不新建社会角色库。提供者目录可版本化扩展，调用方不能删掉行动 schema 的必需项。缺一个必需回执不得签发该行动资格；无绑定、覆盖不足、冲突、失效或规范未知均不构成通过。注意回避、好感、情绪、人格都不能跳过硬条件。
- D09 生成受限表达，D08 行动意图经 D11 最终 admission 重验后派发；D10 主动机会不授权发送。平台已交接/结果未知不能保证追回，也不能宣称 exactly-once 外部效果。
- D13 只在模型调用显式需要同会话近期对话脉络时提供 `ShortContextSliceV1`；D03 原有 `ContextFrame` 保持世界视角语义，D11 独立组成最终 `ModelInputFrameV1`。D13 压缩调用不注入自身历史带，已选槽次数不回写 D06/D07/D09；块和原文至迟按最早来源受信 UTC+72h 停止自动进入提示词。异步预制属 D11 技术费用，不制造 D02 角色劳动或 D06 回忆。
- D01 只把 `RoleBindingResolution` 用于情境人格/策略投影；D05 单独裁决 BoundaryRule；D09 可以据回执选择不夸张的语言，却不能把它变成内容、承诺、发送或访问许可。D03 是唯一绑定/规范适用权威，消费者不得缓存为旁路社会角色状态。
- 来源更正先阻断无效当前读出再重建；保留历史不等于允许旧错误继续驱动。删除依 D06 独立写前日志/最新恢复水位执行，覆盖全部派生、作业、缓存、历史内容与导入；旧备份不得复活。
- 跨域引用每次外送/采用/投递同步核验所有源授权，异步通知仅作清理。私密抽象默认仍受来源约束，不以“只表达心情”自动去密。
- 无依据的离线时间不生成生活、反思或社交经历。允许的连续推进须有参数、区间及真实时间映射；未观测外部结果仍未知。

## 3. 总装裁决：时间、交流、执行历史与搬迁

**时间。** D03 拥有外部事件/日历表达的时间语义解析（UTC/时区/区间/精度）；D10 提出角色生活时钟政策及推进候选；D11 唯一登记、版本化签发 CharacterClockMapping 和执行片段。D03 可引用该版本生成 ContextTimeView，不另写生活倍率。D02/D04/D07 消费同一映射。D08 DeadlineSpec 保存约定时区/instant 或明确 floating rule，宿主换时区不能静默改已协商期限；改变承诺须合法 plan revision。

**多段交流。** D08 communication_action 与 D10 contact_id 对应一次获准联系，携带不可变的有限 segment/effect 清单或限定子资格；每段独立 effect/dispatch/admission，段重试不重复消费。主动联系配额按 contact_id 原子占一次；任一段已交接或 unknown 就保留占用与对象无回应闸门。零段交接且全部可证明未执行才能释放。后续每段仍核验同意、静默、受众及当前版本；扩段要重新决策，不能换 contact 规避同一对象闸门。机会 expiry 只清候选，无回应闸门仅由合法相关回应/明确授权变化解除。

**执行历史。** D11 在外部交接前把 effect、冻结命令摘要、dispatch generation、执行序号耐久写入独立执行日志；观测追加、真实动作的 unknown 也有记录。该日志及最新恢复水位独立于可回滚业务备份。旧库恢复先合并全部执行收据/未决 effect，缺最新性证明就隔离，不自动重放；删除清理其中敏感内容，必要无内容身份用于阻止重复执行。

恢复不能只挡原 effect：独立日志在交接前还保存各域验证的最小恢复约束足迹，覆盖原 contact/对象闸门/配额占用、冲突域与未决资源账。D10 按 contact 去重恢复限制，D02 保留未知劳动承诺和 reservation_shortfall，D11 恢复真实费用/父额度；足迹不给发送或成功资格。无法从合法保留元数据定位限制域时阻断该 namespace 新派发，不借新 ID 越过。取消/到期只释放确证未用且已失去执行资格的部分；未知不能作为退款或新增可用余额。

**搬迁。** D11 单一迁移权威签发 activation_generation；不只是写入，所有内容读取、模型外送、下载、订阅、采用、投递和重启都要核验当前代际。旧代际/无法核验时只有无内容诊断，不能源/目标各自超时激活。搬迁同时交接删除和执行日志的最新性证明，普通静态导出不继承运行资格。

## 4. 设计默认值与未验证边界

用户已授权完整设计全部模块；没有逐项确认的工程和角色默认值必须标作可修订选择。具体角色初始设定是 D12 产品配置，不应成为模块设计缺口，也不得声称用户选定某种人格。

每域可配置数值、容量与权重，但必须有合法域、预算及失败语义；这些不是性能测量或心理学定律。不运行代码/模型测试来装饰文档交付。每域记录当前源码依据，未来实施按编译、必要合同/故障验证、语义/纵向、真实宿主逐层验收。

本文后续由主任务补充提供者接受矩阵、总装顺序与联合场景，最终完成状态由全系统审计记录证明。

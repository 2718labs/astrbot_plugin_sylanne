# Sylanne 3.0 全域联合场景与交付闸门

日期：2026-09-23。这里列的是**未来要执行**的联合验收，不是本轮已通过测试。模块内 R/T/C 见 [索引](sylanne-3-design-index.md)，公共身份和提交语义见 [协作合同](module-collaboration-contracts.md)。本轮完整设计的证据只证明合同写全并通过文档/独立审查，不能证明真实角色已具备这些能力。

## 1. 设计层必须贯穿的十六个联合场景

| ID | 输入与变化 | 联合接受条件 |
| --- | --- | --- |
| S01 | 熟悉的人发来一句含糊短回复 | D03 仅记录话语/视角；D07 允许竞争解释，D04 可有失落，D05 不新记对方恶意行为，D06 同一来源家族，D09 不能把猜测说成事实 |
| S02 | 后来用户解释并非故意冷淡 | D07 修订归因，D04 感受可残留，D05 不必立即恢复信任；先阻断旧无效读出，D08 若先前已发不满则考虑补救，已发历史保留 |
| S03 | 她想起同一往事两次，心境不同 | D06 两次实际回忆可有不同重建/感受，外部事件次数保持一次；D07 两次选择有活动收据，D02/D11 只结实际劳动/费用，不冒充新证据 |
| S04 | 她答应明晚发作品但疲劳增加 | D08 仍持有约定义务及 DeadlineSpec，D02 shortfall 阻断新增劳动但不删除承诺；D10 可另排可做步骤，D09 只表述合格改约意图，时区变化不自动改期限 |
| S05 | 共同项目中 A 未确认分工，B 催促 | D08 仅对已确认参与者建立义务；D03 保留每人可知范围，D05 分对象关系，D07 对 A 缺回应保留未知，不让 B 的抱怨证明 A 违约 |
| S06 | A 私下说明困难，B 在群里抱怨 | D03/D06 允许内部获得私聊信息但公开视图受限；D04 可同时担心/不满，D09/D11 不泄露私聊原因，即使只输出抽象感受仍复核源权限 |
| S07 | 首段已发送，后段尚未发送时出现更正或插话 | D09 每段独立 effect，D08 有限批意图仍可重验，D11 仅停止过期后段；首段不重发，补救为新意图 |
| S08 | 主动分享首段结果 unknown，之后又出现新里程碑 | D10 contact 配额/无回应闸门保持，机会过期不解除；原有限段可逐段现行核验，不能换 contact 无限追问；D11 执行日志阻旧备份重发 |
| S09 | 生活项目离线跨过多个日程点 | D10 只推进可确定步骤及来源化产出；D11/D03 时钟映射一致，D02/D04 被动状态有界推进；未观测工具、对方回应、创意反思保持未知 |
| S10 | 设计者在工作台改变角色价值/休息参数 | D12 预览差异并编译，D01/D02/D04 各自接收合法候选，D11 切换方案/算子并重验未提交作业；历史仍记录旧设定，不伪称角色自然成长 |
| S11 | 角色想象被拒绝，现实后来接受邀请 | D07 模拟内容不成外部拒绝；实际想象和 D04 担忧可留真实内部经历；D08/D05 不从想象结算责任，现实结果单独入账 |
| S12 | 身体余额恶化，仍有未核实角色劳动预留 | D02 明示 gross/encumbered/available/shortfall，阻新片段但不释放未知预留；核实已超支才进 overrun，D11 实际费用另记 |
| S13 | 用户撤回私聊访问，正有模型请求与未发消息 | D11 在读取、外送、采用、投递同步验源撤权；先撤权即挡派发，已交接诚实列在途边界；D06/D07/D09 缓存失效，不能靠通知延迟允许继续 |
| S14 | 删除来源后从旧备份恢复，快照早于首次主动联系claim | D06 独立删除水位先挡读，D11 审独立执行水位并据恢复约束足迹合并未决effect、D10 contact配额/对象闸门及未决资源；限制域不可定位则阻断namespace新派发；D12隔离预览/恢复，任一最新性不可证则无内容服务，不复活被删记忆或借新ID重发 |
| S15 | 整角色跨设备搬迁，源端旧备份又启动 | 单一权威签发 activation_generation；源端所有内容读、外送、订阅、写与发送均被旧代际挡住，只允许无内容诊断；新端必须持两类最新独立日志 |
| S16 | 旧用户数据迁移/升级或降级失败 | D12 预览/损失/冲突/操作一次确认，D11 目录和原生 ABI 检查、隔离/回退且不回滚删除/执行记录；没有 Rust 开发工具的普通用户可安装支持平台构件 |

每个场景记录原始来源、域版本、候选和采用资格、实际收据/费用、结果未知范围、可见语言及拒绝原因。虚拟/fixture 可先测一致性，真实平台和自然语言质量必须独立验证。结构化机制干预应产生声明的行为差异；仅靠一句漂亮台词或仅通过数值核均不算通过。

### 1.1 OPS-10 连续完整顺序轨迹（未来验收）

此轨迹把 S05/S06/S07/S09 及纠错、重启语义串为一次可回放的端到端验收；它不是新增的已通过场景。固定同一角色、共同项目、A、B、私聊与群聊权限、初始方案版本和时钟映射，逐步注入下列输入。每一步均保存本步前后权威版本、输入来源、读写集、候选及采用/拒绝资格、可见文本、实际 effect/outbox/执行收据、资源费用和明确的 unknown；不能以生成台词、模拟结果或仅有计划替代其中任一收据。

| 顺序 | 注入与所需参与域 | 将来可执行断言 |
| --- | --- | --- |
| 1. 建立项目与身份边界：D01 载入角色身份、价值和旧版本自传；D03 建立 A/B、群聊/私聊、时区和各自视角；D05 建立按对象/场景隔离的关系；D12 固定角色方案及隔离验收快照。 | 共同项目、参与者、可见范围和方案版本均有来源化记录。D08 只能创建“待 A 确认”的责任候选，不能把角色或 B 的期待升级成 A 的承诺；D06 只写入相应来源家族，D11 给出可审计初始版本。 |
| 2. B 在群内催促、A 尚未确认：D03/D05/D07/D08/D09 形成竞争解释与表达候选，D04 形成对象化的担心/不满，D02 记录当时可用资源。 | 群聊抱怨的事实资格仅限 B 的转述；A 的分工、困难和违约保持 unknown。表达如采用，只能陈述资格已满足的事实/请求，不得把推测写成事实、关系定论或责任结算。 |
| 3. A 私下说明困难：D03/D06 接收受限来源，D07 重新归因，D04 可保留混合感受，D05 只更新相关对象/领域，D08 重算计划与承诺资格，D09/D11 重验任何未发送段。 | 私聊原因不得进入群聊可见文本或 B 的视图。新的解释可改变未来候选，但不倒改先前体验、已发送内容、实际费用或送达未知；已失效候选及其依赖都必须留下撤销原因。 |
| 4. 协作计划获确认并推进：D08 建立各方确认后的承诺、前置条件和 DeadlineSpec；D10 排入活动/日程；D02/D04 影响可承接负荷和调节；D07 以当前证据选择步骤；D01 以版本化价值/边界约束候选。 | 每项承诺明确是谁确认、何时到期、是否仅计划或已实际履约；预算不足只能阻断新增劳动或触发合格改约，不能删除承诺。D06 记录计划与实际事件的不同类型，D11 的事务收据不得把计划冒充完成。 |
| 5. 中断中的多段表达：D09 生成分段蓝图；D08 给出有限批意图；D11 持久化 effect、claim、outbox 和结果；D03/D06/D07 在每段发送前重验来源、时间和版本。 | 首段若已有送达尝试收据，后段因更正/插话失效时只撤销未发送段；outbox 保留首段的实际结果或 unknown，重启/重试不得重发。补救必须是新意图、新 effect 和新资格检查。 |
| 6. 离线跨日与完成：D10 仅推进可由确定时钟、既有计划和已观测结果支撑的活动；D11 回放队列、claim 和执行收据；D02/D04 只作有界被动演化；D03 保持未观测回应/工具结果未知。 | 协作任务只有在对应真实结果事件和执行收据到达后才可标为完成；D08 结算承诺，D06 写入实际完成来源，D05 更新关系贡献。没有收据的计划、内部模拟或外部 unknown 绝不能变成完成、履约或关系证据。 |
| 7. 错误转述与来源更正：向角色输入“B 曾称 A 拒绝协作”的可追溯转述，随后输入原始来源/权限合格的更正，证明该转述错误；D03 区分原话、转述与更正，D06 版本化保存并建立失效链，D07 修订解释，D04/D05/D08/D09/D10/D11/D12 共同处理后果。 | 更正不删除历史转述、当时感受、已发 effect、实际完成收据或已发生资源费用；但凡依赖错误转述的当前归因、关系贡献、策略候选、未执行计划、表达蓝图、outbox 未发送段和主动联系资格，均须被标为失效、重建或拒绝采用。验收应能从每个撤销项回溯错误来源与更正版本；若来源/权限/时间资格不足，仍不得采用更正。 |
| 8. 跨会话关闭、重启与续谈：关闭会话后以新会话和恢复的持久化状态继续；D01 保持身份/价值与自传版本，D02/D04 保持有界内在状态，D03 重建新会话的可知范围，D05 保留分面关系，D06/D07 以更正后的合格记忆和活动恢复，D08/D10 恢复未决承诺/活动，D09 生成当前受众合格表达，D11 恢复事务/outbox/执行水位，D12 只读展示因果轨迹。 | 新会话不得把旧错误转述重新激活为事实或关系定论，不得丢失已确认承诺、实际完成、已发/unknown effect、撤销记录和权限边界；也不得把旧会话的私聊知识泄露给群聊。恢复后同一 effect 的幂等键、claim 和执行收据必须阻止重复执行；任何无法证明最新性、来源资格或权限的内容/派发均拒绝并记录原因。 |

这条轨迹通过的最低证据是：逐步回放在同一冻结输入下可重现上述资格、撤销与恢复结论；删去更正来源或撤去私聊权限会使依赖项按合同失效；在完成、错误更正和重启三处分别注入崩溃后，收据和 unknown 边界仍一致。它还需要独立的真实平台与自然语言质量验收，不能由 fixture 回放单独宣布 OPS-10 完成。

## 2. 多层验收与测量

先核合同：类型/写者、读集/负查询、活动幂等、真实/模拟、权限/删除、跨域事务和失败路径。随后测每域语义与数值：D04/D11 分开报告非线性方程残差、时间离散、局部截断和模型/语义误差；D06/D07 检查主观确信与来源资格分离、必查遗漏率、反例覆盖和误触发。

纵向角色测试跨数日/多会话，包括安静生活、作品、误会、道歉、长期合作、边界和删除。保留合理的多种角色轨迹；人工评审不知道被干预的域，结构化收据用来解释差异。未知真实行为不得用虚构台词掩盖。

质量/成本对照固定同一历史、模型/调用额、权限、硬件和冻结参数，比较固定摘要+向量 top-k、混合检索、事件图始终深搜、事件图按需触发。消融事件关系、反证、触发和后台整合；先过安全/责任门槛，再报告质量/延迟/成本。不复制论文指标作为产品结果。

规模档至少 1k/10k/100k 来源记录，并叠加高重复、纠错、跨场景、多承诺；记录 P50/P95 检索和写入、索引追赶、重建峰值内存、每日模型费用及队列积压。预算阈值需在目标宿主/供应商选定后事前冻结，不能以允许约 10 MB 包体积推断运行成本。

真实平台矩阵分别验私聊/群聊可见性、工具与附件、送达/阅读区别、部分失败/unknown、平台重连及重启。目标原生包需记录源码版本、hash、系统/架构/ABI、压缩与解压尺寸、必要内容、签名/校验及缺库诊断；普通用户不应为安装而编译 Rust。未来发布仍需单独授权和真实证据。

## 3. 设计交付边界

设计完成需十三域主稿/合同/验收、公共合同、逐需求覆盖、联合场景、独立交叉审查及文档检查全部成立。D13 在 2026-09-27 后加入，新增高风险场景见[十三域耦合总装](sylanne-3-thirteen-module-coupling.md)与[D13 验收](../modules/13-short-context-acceptance.md)；本文件原有场景编号保持不变。实现完成需编译和功能/故障/纵向/真实平台分层证据；发布完成还要实际构件和目标平台资格。三个状态不互相替代。本轮文档更新不构成运行测试、包构建或平台发送。

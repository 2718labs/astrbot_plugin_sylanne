# WebUI 高级配置

AstrBot 插件配置页提供本机运行许可、Authority 配置档、原生主 LLM 选择、独立 WebUI 监听入口以及 D01–D13 模块开关。默认 WebUI 监听 `0.0.0.0:2718`；Docker 映射 `2718:2718` 后，通过宿主机地址访问。各模块的具体高级设置统一位于工作台的「设置」。版本化的辅助模型选择对象由真实 AstrBot 配置保存，在原生配置页隐藏。模块开关限制新工作，已有工作的终态、结算、恢复和安全维护仍走原协议。

工作台地址：

```text
/api/v1/plugins/extensions/astrbot_plugin_sylanne/workbench
```

使用实际同源 HTTP 或 HTTPS 入口，先登录 AstrBot Dashboard。Host 配置不要求另一个 Owner 身份；角色领域配置仍需要当前签名 Owner 会话和实际 Graph 权限。填写一个 profile、persona 或 provider 名称不会取得授权。未启用 Dashboard TLS 时，HTTP 支持真实后台登录、配置读写及原 Owner 挑战/签名/会话链；HTTP 传输未加密，密码、验证码、Cookie、Owner token 和业务内容可能被链路观察者读取或被主动干预者篡改。启用 TLS 时独立端口复用 AstrBot 的实际证书与私钥；证书加载失败不自动降级成 HTTP。已有 HTTPS 安装来源不会自动迁移为 HTTP，Owner 操作仍要求正式登记的精确 workbench_origin。

## 配置分组

| 分组 | 实际可配置内容 | 保存与生效 |
|---|---|---|
| 基本与工作台 | 浏览器界面显示名、主题；本机运行许可与 profile | 界面偏好只保存非秘密值并立即作用于 UI；Host 配置通过 SDK 保存，下次重载采样 |
| 模型策略 | 主模型、共享辅助模型、十个工作流覆盖项；当前 SDK 和安装匹配状态 | 真实 SDK 配置保存并重新读取；正式安装身份单独核验 |
| 角色与场景 | 人格方案、身体方案、场景规则 | 当前 Owner 的正式草稿 CAS，不覆盖已采纳方案 |
| 注意与表达 | 注意策略、表达字符上限等实际 typed policy | 正式草稿保存；编译、预览和采纳分别确认 |
| 记忆与关系 | 编码投影和关系方案 | 正式草稿保存，不扩大 Source 或跨场景访问权 |
| Life 与行动 | 活动配方、行动规则 | 正式草稿保存，不自动启动循环、付费或主动发送 |
| 资源与安装 | 已安装模型上限、实际权限、当前安装状态和功能缺口 | 上限及绑定只读；不能用普通表单改写签名预算、租约或安装身份 |

界面显示名与 D01 人格名称属于不同数据。浏览器不会保存 Owner 私钥、会话、CSRF、签名或原始模型配置。

## Host 和模型设置

读取显示实际保存值与本次启动值。保存使用原来的 `AstrBotConfig.save_config()`，校验当前 revision，完成后独立读取确认。读回没有确认、发生并发冲突或返回未知结果时，不显示保存成功，不自动重新提交。

当前模型页保留主回复和十个可编辑工作流覆盖项。V6/V7 安装另外显示关系认知与成长认知，共十三个模型观察行；V8 按其正式定义再显示通用成长认知 `general_growth_cognition`，共十四行。这三个命名辅助槽没有独立覆盖键，使用共享辅助 Provider，并逐项核对实际模型、配置摘要和安装身份。保存选择后仍需正式安装匹配。未知工作流版本、缺行、顺序错误或摘要不匹配的响应继续拒绝。

主模型使用原生 provider 选择。可选工作流按显式覆盖、共享辅助选择、已有安装 slot 身份解析；没有安装也没有选择的工作流保持未选。此解析不会创建工作流或授予调用资格。已安装工作流若与启动选择不符，业务阻断并要求正式绑定；未安装的可选选择不会自动启用该工作流。

模型状态分别表示：

- `selected`：已观察到真实 SDK 模型，尚无匹配安装绑定。
- `pending`：未选择、当前配置变化或存在安装匹配问题。
- `installed`：provider、模型和配置摘要与实际已安装 slot 匹配。实际执行仍重新检查当前任务、Source、Owner、grant、lease、reservation、quote 和预算。

更改选择不改写当前安装 bundle，也不将旧 grant 或 PASS 转到新包。当前正式 Linux 组合仍要求单一 provider-cache adapter 覆盖全部已安装工作流，包含 Life content/numeric。多 provider 的组合清理及现有安装在线重新绑定不能由普通配置保存替代。

## 角色领域草稿

配置页从当前已授权 namespace 发现真实 draft_ref、revision、摘要、Graph revision、访问与删除 epoch。用户不需要手填 opaque draft_ref。权限按钮来自实际会话、Graph grant 和安装端口观察；正式提交会重新核验。

十个可编辑字段为人格、身体、场景、情感、关系、记忆编码、注意、行动、表达、生活配方。已有 `d04.authored_root` 原件只读，其变更走专属 Owner/资源协议。普通保存不修改或删除它。

「从结构示例开始」只在用户点击后填入未保存的编辑内容。示例不是当前实际值，也不是人格或数值校准结果。审阅和修改后提交；后端按真实领域编译器验证，拒绝未知字段和错误类型。

保存检查整套当前版本和 epoch，并在现有 W01 Owner 写 fence、单一 Graph 事务中 CAS。没有自动合并。操作 UUID、请求摘要、回执和未知完成恢复沿用正式原件。成功后重新读取草稿，确认字段、revision 和摘要；成功状态固定为 `draft_saved_not_adopted`。

保存、编译、预览、采纳属于不同阶段。首次草稿只创建 draft，不伪造 active head。现有首次 head 0 的预览与采纳继续拒绝；现有安装采纳链按实际支持的 D09 单域原件执行。不能将十项草稿保存称为十项运行策略已激活。预览使用实际预算引用和当前签名 D11 约束；预算引用本身不授予预算。

## 与 Embodiment 2.5.1 的对应

参考固定为 `Embodiment-2.5.1` / `72de068bf6f97a70086abdddc8cc487933350c5c` 的 66 项配置，原 schema SHA256 为 `70fc400e5165085a3e5cef365d848cfb7824d3a5f59d710ee2219e528138cc2a`。另一个更早的 `v2.5.1` tag 有不同的 101 项 schema，不作为本次基线。

| 旧配置类别 | 本次对应 |
|---|---|
| 人格名字、人设、锁定 prompt、人格创生 | 界面显示名与实际人格草稿分开；不提供任意 prompt 覆盖或以 paid-opt-in 代替授权 |
| 主模型、辅助模型、评估和生活模型 | 逐工作流真实选择、SDK 观察、安装匹配及明确生效阶段 |
| WebUI host/port/token、alpha 数据目录 | 独立入口默认监听 `0.0.0.0:2718`，复用 AstrBot TLS、Dashboard 与正式 Owner 验证；任意 token 或数据库路径不替代正式安装身份 |
| 注意、表达、记忆、关系、生活 | 接新版真实 typed 领域配置；不把旧开关的语义强加到新权威数据上 |
| Owner ID、跨群和可见范围 | 保留正式签名 Owner、主体绑定和当前 Source/access 规则；字符串或全局 bool 不能获取权限 |
| 首句 streaming、补刀、软沉默、夜间打字节律、忙后回聊、犹豫、旧主动桥、emotion_spirit、非文本转述、SDK embedding、Qzone | 新版没有这些旧功能的完整消费者；列为真实功能缺口，不放可保存而无效的开关 |

旧版还存在八个无业务消费、仅展示或写而未读的入口：主动 scheduler、embedding top-K、夜间巩固、Life 记忆写开关、分享强度、旧主评估器 bool、后台队列 bool、最大 worker 数。不能按它们的数量声称旧功能已经实现。

## 安装与手动核验

旧进程上传新代次后若提示 `runtime_restart_required`，新文件已留存；结束并重新启动整个 AstrBot 进程或实际容器。插件 reload 不能替代这一冷启动。

1. Docker 将默认独立端口映射为 `2718:2718`。未配置 Dashboard TLS 时打开 `http://服务器IP:2718/`；已配置 TLS 时使用证书匹配的 `https://域名:2718/`。核对 `/webui/status` 的实际 `scheme`、`state=listening`、端口与绑定地址。HTTP 同样提供后台登录、配置读写和原 Owner 验证链；它按已明确授权的未加密模式运行。证书加载失败不降级。
2. 选择「高级配置 / LLM」，登录当前端口的 AstrBot 后台，或核对已存在的后台会话。确认基本、模型策略、角色与场景、世界与时间、习惯、长期计划、注意与表达、记忆与关系、Life 与联系、资源与安装十组，以及真实 SDK 模型选项、当前值与启动值。V7 安装显示十三个模型观察行，V8 显示十四行；没有独立安装槽的版本不补造观察行。读取失败时应显示未读取并禁止保存，不能显示默认模型或把协议不兼容变成空页。
3. 修改界面别名和主题，确认当前显示变化及刷新后保留；D01 原件不随别名变化。
4. 保存 Host 选择，确认独立读回及待重载状态；重载后核对启动采样。同时核对 AstrBot 插件配置页的 `webui` 和 `modules` 原保存值仍在：SDK `save_config` 会合并高级配置四项，不替换整份配置。更换未正式绑定模型应出现明确 pending/阻断，不能悄悄使用另一个模型。
5. 用具备实际 creator 权限的当前 Owner 读取草稿，编辑实际字段并保存；核对真实读回摘要。Owner 操作要求当前实际 HTTP 或 HTTPS 来源与已安装 `workbench_origin` 精确一致；协议、域名或端口变化须由管理员通过正式安装登记；后台登录成功不代表 Owner 已解锁。并发旧版本和失效身份应拒绝。
6. 核对 readonly authored root、head 0、预算缺失或权限缺失时按钮保持不可执行。没有确认的提交不要换 UUID 重试。
7. 核验实际浏览器的桌面/窄屏滚动、键盘焦点、主题、CSP、会话失效和导航后的旧响应清理。源码 ASGI、DOM/SFC 测试不替代此项。

Numeric、Contact/C09、D04 完整验收和生产 Host 独立身份继续以各自原件保持 HOLD。此配置包不代表 2.5.1 全部业务语义已等价迁移，不运行真实付费模型或 sender，也不直接修账。

## alpha2 候选身份

alpha2 使用独立的 `3.0.0-alpha2` / `alpha2-candidate` / `alpha2-local` 包身份，绑定 v3 四份实际设计输入和当前源码、native、前端清单。资源契约声明为整进程组 2 CPU / 2,000,000,000 字节，app 硬上限 1280 MiB、软边界 1024 MiB；声明不代替测量。旧 alpha1 快照的运行结果只属于原 manifest。每个 alpha2 候选包均须绑定独立源码清单、manifest 与本包实际验证收据；构包和源码编译不能代表完整运行验收。服务器运行资格使用独立本地 scope，生产 Host、Contact/C09 与 D04 的完整资格必须另有各自原件，历史快照的 PASS 不转移到新包。


HTTP 浏览器的 UUIDv4 使用原生 CSPRNG getRandomValues，SHA-256 使用锁定的构建内实现，保持既有摘要字节和操作重试身份。Owner 私钥不进入浏览器；签名仍在本机生成后粘贴。HTTP 登录网关只适配实际 SDK JWT Cookie 的 Secure 属性，保留真实认证、HttpOnly、原路径及其他属性；Owner Cookie 保留 HttpOnly/SameSite Strict，Secure 随实际绑定协议。Origin、CSRF、CAS、当前凭据和 grant/lease 检查不变。

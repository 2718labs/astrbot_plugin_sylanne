## 2. 未来验收场景

每项需保留版本化输入、实际图状态/回执、资源分项、区间和来源；不能只看台词。数值容差、成本上界与语义判据在实现前冻结，不能根据结果临时放宽。下表不表示已通过。

| ID | 场景 | 接受条件 |
| --- | --- | --- |
| T01 | 数字角色配置无饮食能力；文本声称已经吃饭 | 返回不适用/无事件依据，不生成进食经历 |
| T02 | 11 域各自读写接入，非所有者写身体 | 只有 D02 候选可提交；其余以公开合同合作 |
| T03 | 心情愉快但疲劳未恢复；高精力但持续负荷 | 多轴独立，有来源的耦合可解释；不会快乐即满能量 |
| T04 | a/b/dt 边界和长区间解析推进 | 数值在域内；a+b=0 正确；负数/NaN/无穷拒绝 |
| T05 | 相同驱动一次推进与多次切段、改变请求起点但固定节律网格 | 在冻结误差限一致，速率采样不随请求改变，不因调用频率产生更多疲劳 |
| T06 | D04 反馈/参数切换/数值错误 | 前态或获准联合块；参数边界切段；错误不污染最后有效状态 |
| T07 | 休息、创作、联系需求并存 | D08 可比较并延期，最大 urgency 不绕过边界/承诺 |
| T08 | 时区改变、休息中打断、拟人配置与三域时间协作 | D03 解析、D10 提案、D11 唯一签发；D02/D04 同版，仅影响未来节律，真实片段决定效果，不伪造睡眠 |
| T09 | 重复报价、预留但没启动、完成结算 | 报价不扣；预留仅占用；实际组件恰好结算一次 |
| T10 | 两并发活动争余额；预留后状态恶化/修正；未来预计恢复 | 新占用不超额；gross E/encumbered/available/shortfall 明确，reservation_shortfall 阻断新片段，未知预留不释放、不虚构恢复 |
| T11 | 三组件完成两项后取消再重试 | 两项已用保留，新 attempt 不重复扣，未用释放 |
| T12 | 固定/按时混合收费和连续恢复 | 同成本类别不能双记；恢复不使原组件可重复结算 |
| T13 | 同片段被三模块引用、主焦点重叠、后台/暂停 | 并集时长；非法重叠拒绝；暂停/纯技术后台不记角色劳动 |
| T14 | 预留到期时回执未知，期间请求被动恢复，随后迟到成功 | 待核实上界不提前释放，确定身体游标停在未知区间前，核实后按真实顺序结算一次 |
| T15 | 错误上界导致真实超额 | 留精确待结算项并阻断新工作，不负余额/不删费用 |
| T16 | D06/D07 组合事务逐步故障注入 | 认知/回忆采用与必要身体结算一致；重启不双扣 |
| T17 | 供应商调用失败、纯数据库重试 | D11 真实费用存在；无合法劳动不写身体疲劳 |
| T18 | 离线两天无已执行活动 | 仅合法被动推进，不编造作品/社交/梦境 |
| T19 | 离线边界超过 256、途中重启 | partial 游标真实可续，不假称全部区间完成 |
| T20 | 墙钟回拨/时间映射缺失 | 停在可靠边界并报缺口，不负 dt 扣费 |
| T21 | 劳动回执迟到/压力来源被纠正 | 核实后有版本重算，旧驱动先屏蔽，不重演活动 |
| T22 | 私密活动负荷进入群聊表达 | 受众/来源闭包有效，抽象描述不自动去密 |
| T23 | 删除混合负荷来源、旧备份恢复 | 清理/合法重算或隔离重建，独立删除水位阻止复活 |
| T24 | 工作台精确数值与角色身体自述 | 角色不自动获审计知情，表达不反写身体 |
| T25 | 父预算耗尽、容量超限、提高配置上限 | 明确延期/分批，新配置不追溯扩大旧租约 |

| T28 | 多日项目→疲劳→休息→继续并有聊天打断 | 状态影响选择与节奏，成本可追溯，休息不抹人格/关系 |

## 3. 当前源码差距

只读核对的当前文件：`rewrite/sylanne3/graph_types.py` 有 Owner/TypeRegistry/版本；`graph_store.py`、`graph_runtime.py` 提供共享存储与运行基础；`contracts.py` 有基础 Event/Scope；`native.py` 的结果含 energy_delta；`semantics.py` 明确是 support/pressure/neutral 的未校准 fixture。上述不是完整身体模型。

| 当前基础 | 可以复用 | 仍需实现 |
| --- | --- | --- |
| 图类型/Owner/版本 | 隔离与注册框架 | D02 类型、写者能力、轴语义和配置迁移 |
| 数值原生调用/fixture | 数值调用通道和异常框架 | 多轴有界算子、合法参数域、时间映射、数值证据 |
| 运行调度/存储 | 事务与作业基础 | 报价预留/分项结算、并集时段、取消未知、超额修复 |
| 记忆来源和回忆切片 | 内容资格/隔离基础 | D06/D07 完整组合提交、劳动/体验区分 |
| 现有消息路径 | 未来接入点 | 所有 11 域正式闭环及真实宿主/工作台验收 |

本轮未执行运行测试，既有 Python/Rust/SDK 测试只能说明历史切片，不能支持 T01–T28 已通过。未来手工验收需从工作台检查 T28 的真实状态、资源和回执，同时观察实际对话；不能只询问模型“你累了吗”。

## 4. 实施顺序和完成条件

1. 与 D11 注册公共写者/版本/时钟/区间和 D02 类型，编译通过后做字段和权限必要检查。
2. 实现连续算子、需求/节律、参数边界和离线游标，做数值边界与分段一致性。
3. 实现报价→原子预留→分项结算→取消/核实，验证并发、故障和身体/真实费用分账。
4. 接入 D06/D07 组合提交、D04 反馈、D08/D10 活动，验证联合语义和来源修订。
5. 接入 D12 配置/诊断/迁移与 D09 表达；完成删除/恢复和独立多日角色场景，实宿主再验收。

设计完成条件为 R01–R20 有主规格、操作及验收依据并通过冲突审查；实现完成则还需全部相关 T 场景的真实证据。两者不得混用。本地设计不授权编码、PR、推送或发布。

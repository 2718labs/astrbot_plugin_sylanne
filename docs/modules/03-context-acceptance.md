## 2. 未来验收场景

每项冻结输入包含真实来源资格、身份键、读集、视角和当前授权。结构规则做确定性验证；语义部分用人工标注的多种合理输出范围及独立保留场景，不以单一标准回复验收。全部场景尚未执行。

| ID | 场景 | 接受条件 |
| --- | --- | --- |
| T01 | 11 域接入与 D03 越权候选 | 身份/情境独写，D06 来源、D07 信念、D05 关系等不被接管 |
| T02 | 两人同名、同人多账号、多人共用账号 | 人/账号和映射有独立身份，歧义不自动消失 |
| T03 | 新昵称与历史代词、不同群的相同别名 | 别名绑定场景/时间，代词未知不默认用户 |
| T04 | 三条来源描述一次事件；一条消息描述两件事 | 各层 ID 保持正确，不重复发生计数/不吞独立来源 |
| T05 | 源准入后解析崩溃并重启 | 原源保留且 pending，只用确定宿主事实，恢复不双写 |
| T06 | 相同消息 ID 重投/异载荷/合法编辑 | 去重/拒绝冲突/新版本更正分别处理 |
| T07 | 文本相同的两条独立消息和确证转发 | 前者不误吞，后者来源家族保留传播关系 |
| T08 | “甲说她问你为什么没来”含四种角色 | 发送者、引文作者、指代、行动者不混同 |
| T09 | 多线程交错回复、缺 reply_to、大群窗口截断 | 保留歧义和 coverage，不强配最近消息，不声称前文不存在 |
| T10 | 草稿准备后受众从私聊改群/成员权限变化 | 旧 frame 失效，外送/投递重新查授权 |
| T11 | 被 @、投递成功、可访问、实际注意、他人是否看懂 | 分别表示，不把一次 @ 当作已关注或全员知情 |
| T12 | 历史“昨天”、未知时区、只有日期 | 用当时参照/精度，未知不填当前系统时间 |
| T13 | 夏令重叠/缺失本地时间与跨时区承诺、角色倍率改变 | D03 报区间/歧义且不另写倍率，D10 提政策/推进，D11 唯一签发映射，D08/D10/D02/D04 引同版 |
| T14 | 平台顺序和事件时间冲突、跨平台无共同钟 | 保留可靠偏序，不把处理先后变成事件先后 |
| T15 | 迟到证据解释旧误会并查询当时视角 | 当前可更新，但当时角色没有后来知识 |
| T16 | 工具回执 unknown、用户声称已做、模型自报完成 | 执行资格保持不同，不升级执行事实 |
| T17 | 嵌套引文、否定、条件句和反事实 | 范围保留，不生成相反/假设外部事件 |
| T18 | 隔离推演对方拒绝、实际感到担忧 | 担忧可是真实当前体验，拒绝仍 simulated |
| T19 | 摘要转述十次、D07 信念再进入上下文 | 不变独立证据，不抹掉推断/转述限定 |
| T20 | 精确对象行动缺身份或视角必查 | D03 返回缺项，D06 不签齐全，D08/D11 不执行依赖动作 |
| T21 | 有依据合并两个锚点，权限不同 | 原 ID 留存，权限不并集，当前投影先阻断后重建 |
| T22 | 撤销合并且存在不可逆关系聚合 | 按原贡献重算或 unresolved，不任意均分，不改既发消息 |
| T23 | 账号更名/转让、跨平台自述同人 | 别名和持有人时间映射正确，私密权不自动继承 |
| T24 | 编辑原文/仅撤回平台可见性/彻底删除 | 命令种类区分；失效先屏蔽，物理删除只按实际范围报告 |
| T25 | 撤权后缓存命中、模型请求/投递并发 | 当前源闭包同步检查，缓存/异步通知不能绕过 |
| T26 | 删除别名来源并恢复旧备份/导入 | 最新独立删除水位阻止复活，不能凭旧 alias 再合并 |
| T27 | 两个解析任务同时建账号锚点/补负查询 | 只有一个规范映射，冲突重新装配而非复制人 |
| T28 | 上下文超过窗口、128 节点/4 层解引 | partial/continuation 准确，不能静默丢必查槽位 |
| T29 | 多模块递归查询同一复杂引用 | 同父预算和深度，不能另领无限额度 |
| T30 | 语义/身份服务失效、管理员可见私密全景 | 只返回合格范围；诊断知识不注入角色；无昵称替代身份 |
| T31 | 模型/命名规则升级、隔离实验导入 | 新候选/明确迁移保留历史，实验不污染真实世界 |
| T32 | 多人误解→核查→身份纠正→关系/情绪不同步→澄清 | 全域版本/资源/来源可追溯，无人承担错误追加罪责 |
| T33 | 同一对象在私聊是朋友、在项目群是协作者，并有不同规范版本 | 两个 RoleBinding 都显式指向对象/场景、可见范围和来源；D01 得到不同情境策略输入而不复制人格，D05 关系投影不被改写 |
| T34 | 私聊获知困难后，群内以协作者身份讨论延期 | Resolution 仅给群场景适用规范；D08/D09 可提出公开可说的协调或澄清，但不披露私聊来源、不能代 A 确认或把投递当阅读 |
| T35 | 账号相同但无社会绑定；账号转让或共用后旧绑定待复核 | AccountBinding 不产生 RoleBinding、访问或关系许可；旧私域和关系不转给新持有人，范围/来源不足的绑定返回 partial/unavailable |
| T36 | 绑定缺失、规范冲突或版本已失效时准备定向承诺/披露 | RequiredCheck 不完整，D08/D11 不派发该高风险行动；只允许重新装配后不依赖缺口的保守公开回应或求证 |
| T37 | 历史 SocialScene、Participation、GroundingRecord、PerspectiveClaim 导入 | 分别成为 SceneFrame 社会切面、参与事实、确认/共同理解证据、D07 解释引用；缺少范围/来源/版本者只是 legacy_role_evidence，不能静默升级绑定 |
| T38 | RoleBinding 修订/撤销与并发草稿 | binding/norm 版本提升使旧 ContextFrame 和未派发资格失效；重建完成前不混用新旧规范，已发消息保留历史版本且不自动重发 |

## 3. 当前源码差距

本轮只读核对 `rewrite/sylanne3/contracts.py` 的 Scope/Event、`graph_types.py` 的 Owner/TypeRegistry、`memory_types.py` 的 SourceRecord.speaker_id、`memory_repository.py`/`memory_retrieval.py` 的来源身份校验和检索，以及 `semantics.py` 的有限 Envelope/fixture 解析。这些只提供局部基础，不是完整 D03。

| 当前基础 | 可复用 | 仍需实现 |
| --- | --- | --- |
| Scope/Event、宿主 Envelope | 入站和幂等载荷基础 | 平台/会话/编辑版本、完整账号绑定和稳定世界事件 |
| SourceRecord/来源检索 | 来源资格与统一读取入口 | 事件/人物/提及多对多关联、当时视角和当前授权 |
| 图类型/版本 | 注册、隔离和依赖基础 | D03 写者表、身份查询域、合并撤销、级联屏蔽/重建 |
| 限定语义解析 fixture | 严格输出校验习惯 | 多人/引用/否定/时间/现实性和 ContextFrame |
| 应用/运行框架 | 未来消息入口 | RequiredCheck、源修订删除、工作台、实群聊与跨平台闭环 |

未执行编译、代码测试、模型评测或宿主验收。历史基线不能证明当前 T01–T38；未来手工场景采用实际测试群的多账号、编辑/撤回/时区案例，同时核对图身份和源资格，不能只问角色“你知道是谁吗”。

## 4. 实施顺序和完成条件

1. D11 公共 schema/写者/幂等与 D06 准入配合，注册实体、账号、来源事件和待解析类型，先编译及基础权限验证。
2. 实现源片段解析、多人/引用/时间/现实性候选，确定性资格检查与 ContextFrame/覆盖。
3. 实现身份映射、合并/撤销、受众/视角、RequiredCheck 和并发查询域。
4. 接入源更正/删除、缓存/作业恢复、跨域闭包及各领域重建；做故障注入和独立语义场景。
5. 接 D12 工作台和真实宿主多账号/群聊，运行 T32 完整联合场景，检查状态、资源和实际表达。

设计完成需 R01–R21 有明确方案/操作/未来证据并完成实质冲突审查；实现完成还需实际场景回执。这里只完成本地设计，不授权编码、PR、推送或发布。

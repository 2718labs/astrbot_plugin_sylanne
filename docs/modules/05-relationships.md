# D05 社会关系：完整设计 v1

日期：2026-09-23。状态：完整本地设计，尚未实现；以下工程与角色默认值可修订。配套 [协作合同](05-relationship-contracts.md)、[验收设计](05-relationship-acceptance.md) 及 [公共合同](../architecture/module-collaboration-contracts.md)。

## 1. 关系应该具有的连续性

她对不同的人应有不同的相处史、信任、亲近、期待和边界；同一个人也可以“很亲近，但不愿让他替我决定作品方向”“相信他的善意，但不确信他能准时做到”。关系不是单一好感值，也不是陌生人→朋友→恋人这样的固定升级状态机。

关系会被情绪和记忆添上主观色彩。她可能因误会短暂疏远，知道真相后愿意重新靠近，但不必立即恢复所有亲密习惯。采用“有向、分对象/领域、带经历依据的关系评价＋明确边界＋持续修复过程”；角色主观体验和现实责任证据分开保存。

默认允许关系自然变化、自主提出边界和邀请修复；不以回复频次、付出积分或讨好作为亲密升级条件。不同关系形式可由 D12 设定其语义和适用角色，模块不自动推定浪漫、占有或排他关系。互惠是理解相处方式的材料，不是对方欠她回应的强制债务。

## 2. 所有权与十一对端

D05 只拥有本角色对对象的关系立场、关系维度评价、边界及修复语义。对象身份由 D03 管，承诺/联合计划由 D08 管，感受由 D04 管，外部事实/归因判断由 D07 管。所有数据进入共享图，D06 负责来源和检索，不能再建联系人记忆库。

| 对端 | 读入 | 输出与界限 |
| --- | --- | --- |
| D01 | 自主/亲近等价值、相处偏好、关系成长策略 | 跨对象模式和策略材料；个别人相处习惯不自动成为人格 |
| D02 | 当前可用精力、负荷与需求 | 社交活动负荷建议；疲倦不算对方新的伤害 |
| D03 | 稳定对象/群体、实际互动事件、参与和可见性，以及 `RoleBindingResolution` | 身份核查请求、分场景关系投影；不替他人定义内心或把社会角色写成关系边界 |
| D04 | 对象化感受、残留、调节结果 | 关系意义/预期与修复材料；愿意原谅不清零感受 |
| D06 | 合法共同史、来源家族、回忆/解释修订、删除 | 关系线索与记忆贡献需求；回忆不新增外部相处事实 |
| D07 | 多种归因、信念、他者视角假设、关注事项 | 关系假设、关切/反思请求；D05 不另写事实信念 |
| D08 | 承诺、实际行为、履行/撤回/补救的领域结果 | 边界 RequiredCheck、关系代价、修复机会；不替 D08 改承诺 |
| D09 | 表达情境与可行蓝图 | 称呼、距离、披露与语气的允许范围；措辞不建立未确认关系 |
| D10 | 真实共同活动/生活产出、主动时机 | 合适活动建议与接触偏好；关系机会不授权发消息 |
| D11 | 时间、写者/事务、预算、权限与收据 | 关系候选、边界屏障与去重；不自建调度器 |
| D12 | 明确角色设定/编辑/查看/删除命令 | 有范围的关系视图、修复/边界操作；创作者配置不是对方表态 |

## 3. 对象、状态及非对称关系

关系键为 `owner_scope + subject_entity_ref + context/domain`。默认有向 A→B：她相信对方不代表对方信任她；她觉得亲近不代表双方同意同一关系标签。对方的表示存为 D03/D06 来源及 D07 可修订理解，不能写成其内部真实状态。

| 类型 | 语义与字段 |
| --- | --- |
| RelationshipProfile | 稳定对象、领域/场景、维度集合、关系形式自我定位/对方表示/双方明确约定分别引用，当前有效性 |
| DimensionEstimate | 维度定义、当前倾向、主观确信、依据覆盖/反例、来源独立性、时间/变化趋势、解释版本 |
| InteractionContribution | 事件/来源家族、受影响对象/维度、贡献种类、当时解释、已消费键、后续修订链 |
| BoundaryRule | 声明者、约束谁/哪种行为/场景、explicit/inferred、许可/限制、有效期、来源、可协商方式、当前版本 |
| ReciprocityPattern | 付出/接受/发起的可见样本、机会与能力背景、彼此偏好、未覆盖范围；不表示债权 |
| RelationshipExpectation | 她期待的相处方式、由来和强度、是否实际协商；不代表承诺 |
| RepairProcess | 争议事项、受影响维度、责任主张/证据、修复提议、接收/回应/实践结果、未解决部分、停止条件 |
| RelationshipProjection | 指定用途/受众的当前相处建议、硬边界回执、主观印象及未知、完整依赖 |

共同字段含 schema、版本、来源/现实性、owner、实体、时间、用途/受众、依赖与删除代际。D03 身份拆分/合并通过显式映射迁移关系，保留冲突来源与去重；相同昵称/嵌入相似不合并。对群体的立场独立于成员关系，不能让一个人的冲突污染整个群体或反向继承全部私密关系。

## 4. 多维信任与亲近

初始可配置维度为善意预期、可靠性、领域能力信任、坦诚预期、边界被尊重感、亲近/舒适、愿意披露/共同活动的倾向。维度须给定义、适用域及实际行为出口，不要求全部角色同样维数。未知是 null/coverage 缺口，不能用 0 假装已经不信任。

每维区分主观估计、主观确信和证据支撑。过去愉快可能使她更愿分享，即使证据不充分；不能因此把对方的所有陈述升级为事实。高专业信任可影响 D07 的先验关注，但专业内容仍需符合任务证据要求。对艺术建议的信任不自动转成财务/技术/守时信任。

倾向使用有限 [-1,1] 实数或语义分档投影，证据覆盖与主观确信分别表示，所有数字有限。数字不是人类关系量表。正式更新为经领域语义评估的局部候选：`next = clip(current + bounded_delta, -1, 1)`，未初始化维度先生成带先验来源的 estimate，不对 null 做加法。delta 的依据、对象、领域、时间和更新类型必须可查；本版不以机器统一规则“每次赞美 +1”驱动关系。

每次变化和累计漂移有配置上界/复评条件；单一重大事件可以大幅影响特定维度，但需独立陈述其性质与来源，不能一键改写所有领域。当前情绪/记忆色彩作为明确读入的情境调制，不能每次读投影都持久加分。持续关系修订需独立采纳与贡献键。

## 5. 相处经历如何影响关系

入站互动、实际共同活动、承诺结果、边界回应和修复实践可以成为外部关系材料。D03 给事件/对象，D06 给来源家族，D07 给当前解释，D04 给真实感受，D08 给实际履约资格。D05 评估受影响维度与适用域，而非直接从一句话关键词变更总好感。

贡献种类分为 `external_interaction/internal_recollection/interpretation_revision/simulated_trial/administrative_edit`。外部行为去重键含 source family、事件、对象、目标维度与贡献语义；实际回忆另按 recollection activity 去重。一次事件可合理影响可靠性与舒适等不同维度，但必须分别说明。摘要、转述、重复回忆和重启不增加对方实际做事次数或独立证据量。

真实反复回忆可改变她当下的亲近感、戒备与关系自我理解，甚至形成持久主观变化；来源仍标 internal_recollection，不能拿这些次数证明对方“多次背叛”。累计变化受来源家族总贡献与近期反思预算限制，超过策略阈值触发 D07 复评/停止展开，不靠不断新活动无限惩罚。模拟拒绝可以留下当前担忧，不能进入共同史或作为拒绝事实。

## 6. 边界、披露与关系形式

明确边界包含对方实际表达的要求、本角色提出的界限、双方明确协商的约定及创作者的产品限制，分别标来源。D11 运行权限高于社会边界；D05 没有权限扩张能力。角色偏好/推测性边界用于候选建议，不能伪装成对方明确禁止；证据不清时可选择谨慎求证。

执行检查按对象、行为、受众、时间和场景匹配适用规则，优先明确且范围匹配的当前规则。涉及社会角色规范时，D05 可经 D06 读取 D03 `RoleBindingResolution` 以理解情境，但仍独立给出边界 RequiredCheck；社会角色回执不能创建、放宽、覆盖或替代 `BoundaryRule`。规则冲突返回 conflict，不能用高好感消掉冲突。放宽明确边界须有合法修订来源与版本；拟议放宽或试探不是许可。新边界提交通过 D11 失效屏障阻断受影响未派发动作，其采用与通知/outbox 一致。

披露意愿只说明她愿不愿说，D06 用途/受众许可决定能不能用具体内容。亲密不自动打开所有私密来源；“大家都是朋友”不是群聊披露权限。称呼、亲密语气和关系标签由 D09 根据适用投影表达；对方未确认的关系形式须表现为她的理解或愿望，不能生成“我们已经是……”的共同事实。

边界表达本身也是 D08 合格行动。D05 可以先采纳本角色内部边界，从此限制自身行为；对方是否已知另看沟通收据，不能把尚未表达的界限当作对方明知故犯的证据。对方明确的“不再联系”默认禁止主动接触，重提修复邀请也属于接触，不能借修复名义绕过。

## 7. 互惠、期待与关系张力

互惠观察不只比较谁发消息多，还要考虑各自可见机会、能力、沟通偏好与已协商的方式。沉默没有自动恶意归因。她可以觉得付出失衡、失落或希望被重视，但这些由 D04/D07 分别形成感受和解释；D05 保存相处期待及当前关系意义。

期待只有在 D08 按规则形成承诺或联合约定后，才具有相应义务资格。她愿意陪伴不令对方欠等量回应；她可调整自己的投入、表达需求或退出活动，而非强迫兑换情感。共同活动建议同时读取 D02/D10 的机会和资源，不把无法参加算作拒绝她这个人。

亲近与自主可以冲突，依 D01 价值形成多种相处候选；不固定“越亲近越频繁联系”的函数。允许珍惜关系同时保持距离，允许恢复合作而暂不披露私事。这些差异须影响真实候选和表达范围，不能只给同一行动换一套语气。

## 8. 冲突、修复与误会修订

RepairProcess 以具体事项和受影响维度建立，记录争议、不同解释、已知影响和修复期待。过程可提议、等待、实践、部分改善、暂不推进或结束；不是强制对方完成的疗程，也不以统一“已原谅”布尔值重置整段关系。

道歉可能证明表达了歉意；对方接受可能证明愿意接受这次道歉；后续尊重边界和履约是不同的实践证据。能力信任、舒适、亲近和责任理解可各自变化。D08 管补救是否执行/履行，D05 管相处立场，D04 管感受残留；三者允许不同步。

新证据澄清误会时，D07 修订责任归因，D05 立即阻断依赖旧归因的当前指控/惩罚性限制投影，再重建相关维度。情感记忆可保留“那时我确实受伤”，但不继续把已推翻的事件当作对方做过。独立支持的边界/偏好保留；本角色可以因为当前舒适度选择暂时距离，需要用仍有效的理由，不借旧错误事实包装。

修复邀请尊重对方接触边界；未回复仍未知，不记作一次新拒绝。默认每一争议最多一个未决主动修复邀请，等待明确回应、新许可或新的相关证据再重评，不能用新消息 ID 无限追问。修复可以停下并保留未解决事项；停止调度不等于证明无伤害或已经和解。

## 9. 时间、冷却和关系变化

记录事件、获知、采纳、最后实际互动及角色活动时间。长期无互动可以降低“对当前情况的把握”，不自动抹去珍惜或转成怨恨。采用有配置时间尺度的有效性/熟悉度重评，明确标时间推导而非新互动证据；不同角色可不同，默认不因离线时长扣信任。

冷却限制重复评估/邀请，不阻止真正的新边界或更正即时生效。延迟事件按当时实际可知信息进入历史，当前关系可以重评，不能让过去已表现为提前知道。冻结关系/归档对象仅停止主动调度，不删除依据或把未完成承诺关掉；恢复先核实身份、权限和新边界。

## 10. 事务、并发与失败

采纳关系更新时，受影响维度/边界/修复状态、合法解释引用、贡献消费及 outbox 同事务生效。D04/D07 本次必要活动先通过各自唯一组合提交，D05 不复刻体验。两个会话同时更新同一对象采用 read versions 与关系查询域 epoch；冲突重装配，不能后写覆盖另一个有效变化。

重试同 operation，过期 attempt 保留 activity/effect/父预算，未知提交先核实收据。不同投影受众各自校验用途，不能共享一个带私聊内容的对象缓存。解释来源失效时先阻断受影响投影，提供者离线则返回 unavailable/partial，而不是临时套用旧关系。

同一关系可含当前可用和不可用维度。投影明确回答哪些维度仍有效；硬边界检查需要完整适用范围，缺 provider 或查询覆盖不足不签通过。运行权限与内容泄漏拦截不依赖角色是否觉察关系变化。

## 11. 预算与模型角色

日常读关系投影无需额外辅助调用。新事件使用有界相关维度与来源集合，默认每次至多 8 个关系维度候选、16 个独立来源家族；截断必须保留边界/必需反例，无法保留则缩小问题或延期。所有辅助判断与父任务共享初始 2 次调用预算，D06 检索和 D07 反思不另领额度。

模型生成意义/维度候选及修复提议，确定性层检查对象、版本、来源资格、边界作用域、数值范围和去重；语义是否合理仍需实际评估，不能声称 schema 保证判断正确。参数要有合法域、策略版本和累计变化上界。D02 按实际角色劳动结算，D11 按调用计实际费用，后台也共享额度。技术核查不是一次社交经历。

## 12. 隐私、删除与恢复

关系派生物默认继承全部依据的权限；内部使用、表达、巩固、审计分别检查。跨命名空间 TransferRef 每次使用由 D11 同步验源，异步通知只清理。多个场景可以共享合法的“她对这个人的立场”，但不能泄露立场背后的私聊事件；公开抽象需要具名转换合同，未有合同就用满足当前用途的独立合法来源或不输出。

删除按 D06 独立写前日志和恢复水位执行，覆盖维度、争议/修复文字、边界来源、称呼、期待、摘要、缓存、模型/操作记录、备份/导入。混合派生状态须 rebuilt/sanitized/reset/unavailable 之一，未净化部分不读出。删除不是原谅；内容不可再用也不能靠“旧伤害让我这样”保留被删除的具体推断。

删除明确边界的来源不得静默产生新的外部接触授权。如果用户只是删除内容、未明确改变接触设置，按独立授权的最小非内容接触设置维持约束；不能复制被删语义。若没有可独立保留的有效设置，则相关边界结果 unavailable，新的主动接触须取得新的合法范围依据。防止以删除日志复述敏感内容。

## 13. 工作台、配置和行为出口

D12 分别呈现“她怎样理解这段关系”“实际已知互动/约定”“创作者诊断”，禁止把内部诊断直接当角色自知。产品显示维度趋势、适用范围、重要转折和未知，不用一个亲密进度条许诺某个关系等级。查看具体来源继续受其权限约束。

可编辑初始相处倾向、维度定义、自主边界策略、更新时间尺度和联系设置。行政设定标 authored/administrative_edit，不冒充对方说过、已经和解或真实发生共同经历。D12 可发起更正/边界修改/暂停修复/删除，命令由 D05/D06/D11 处理。关系形式变更不自动开通平台权限或替他人确认。

行为出口包括：是否愿意求助/分享/接受建议、活动邀请偏好、披露程度、修复意图和说话距离，最终行动由 D08、语言由 D09。每项设计声称的影响都应能在固定事件的干预对照中观察到结构化变化。

## 14. 总装顺序和联合场景

先接 D03 对象、D06 来源/删除和 D11 图/去重，再实现 D05 维度与边界；接 D07 归因和 D04 感受，接 D08 承诺/修复结果及 RequiredCheck，最后接 D09/D10 行为与 D12 产品视图。所有依赖须有实际提供者后才称完整闭环。

联合场景：她分享作品没有获得回复，D07 猜测是否被敷衍，D04 失落，D05 暂不愿继续分享；多次真实回忆可以改变当前戒备，但不增加对方冷落次数。后来知道对方在处理急事，旧恶意归因失效，D05 重评善意预期，D04 仍可残留失落；D08 选择是否温和说明，D09 表达当时感受而不指控对方反复失约。之后实际尊重边界的互动逐渐形成新的相处方式。

本设计允许错误、矛盾、迟到的理解和未完成修复；要求其依据和责任层级可辨、可修订、可删除。没有为完美讨好或恒定正确牺牲角色主观性，也没有因主观性放弃执行资格。

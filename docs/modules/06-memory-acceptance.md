## 4. 语义、人物体验与成本如何评估

机械验证先检查角色隔离、来源/权限、时间、去重、迁移、取消、删除与投递顺序。硬不变式的违规数要求为零；用例数量或一条成功日志不能代替全范围覆盖。

人物体验采用多条跨日剧情：分享与等待、误会与澄清、共同项目、旧事新解、个人活动、回避与再面对、明确责任与主观遗忘。评审记录人物差异、主观连续性、片段/意义变化是否有来由、行为是否受其影响；不要求统一台词或唯一情绪。含推测的理解应与来源事实分别评分。

对照至少包括固定摘要＋普通检索、仅情绪重排、情境激活但无重建、完整方案但关闭回忆后更新、完整方案。控制相同模型、输入和总费用；分别消融个人关联、反证通道、注意选择和后台巩固。若一个组件只改变最后措辞，不能证明它完成了宣称的记忆机制。

规模档为每角色 1 千、1 万、10 万条来源，加高重复、高度数关联、频繁纠错/删除和多角色并发。测量端到端 P50/P95、候选与真实数据库访问量、事务最长耗时、索引滞后、恢复时间、峰值内存、持久空间、每轮/每日模型 token 与调用费用。正文中的局部上限是初始开发配置，未声称满足这些规模。

先在固定硬件/模型和开发集测基线，冻结策略版本、参数范围、语义评分规约、保留测试集和响应目标，再执行独立保留集；不因结果不佳临时调整阈值并把同一批重新算独立验收。具体延迟目标必须来自宿主 ResourcePolicy 与可测基线，本次设计不捏造毫秒承诺。

## 2. 未来验收场景

机械测试固定来源、版本、时间及提案，语义场景另外使用真实模型和保留剧情。检查事务、提供方回执、实际效果与用户可见信息，不能只检查一句回答。

| ID | 输入/故障/对照 | 必须观察到的结果 |
| --- | --- | --- |
| T01 | 无新消息但有作品愿望；请求含歧义 | 能有内部目标；歧义不自动变成对外义务 |
| T02 | 十二域提交合法/越权类型 | D08 不写人格、感受、关系或运输收据；唯一写者有效 |
| T03 | 同名对象、两个相似目标、不同时区期限 | 稳定身份/范围不误合并，迟到证据不倒填早知 |
| T04 | “希望/打算/保证/已发/已收到”分别输入 | 愿望、意图、承诺和结果层级分别存取 |
| T05 | 目标“让他高兴”，他者未表达感受 | 可采纳可控步骤，不宣称已使他开心或原愿望已满足 |
| T06 | 固定资格，改变诚实/体贴偏序及心境；再撤工具权限 | 行动倾向可改变；强倾向不能恢复撤销权限 |
| T07 | 明确单方许诺，平台接受但对方未确认 | 按类型记录已沟通责任，不能借缺少回应消除义务 |
| T08 | 许诺交接超时，后再提出冲突许诺 | 保留传达未知和冲突占位，先核查不当作未承诺 |
| T09 | 三方计划，一方接受改期另一方未回复 | 逐方版本确认，旧义务不被统一改成新日期 |
| T10 | 到期、未回复、实际作品完成但未投递 | 分别呈现 overdue/unknown/局部完成，不虚构违约归因或已收到 |

| T17 | 有幂等键的工具重复请求；参数改变 | 同键冻结参数，实际费用累计；变参数冲突 |

## 4. 实现顺序与提供方依赖

P0：D11 schema/写者/类型目录迁移、effect/收据/删除屏障/共享预算；D03 身份和 D06 来源。P1：D08 目标、满足谓词、版本化决定和 D01/D07 合作。P2：承诺/联合计划及 D05 边界、D02/D10 排程资源。P3：RequiredCheck、D09 固定表达、工具/消息能力、D11 admission 与 unknown 核查。P4：部分效果/补救、纠错/删除/恢复/迁移和 D12 产品视图。P5：真实宿主、并发/故障、长期人物表现及成本评估。

每阶段先编译，再执行针对新增风险的合同/故障验证。测试替身须标明，不能由替身成功宣称真实平台完成。平台无查询能力时保留 unknown 是正确结果，不弱化核查条件换取全绿。

## 5. 评审与产品验收边界

文档完成要求为 R01–R28 全覆盖、十一对端明确、C01–C12 有成功/失败/恢复语义且重大接口冲突已修正。实际实现还须执行适用的 T01–T37。语义评估使用保留故事及干预：是否保留自己的愿望、合理协商而非机械讨好、后悔与责任是否连续；多种合理行动允许并存，不指定唯一台词。

手动联调走“承诺展示作品→精力不足→改约→投递未知→核查→实际履行或补救”，同时查看权限、目标谓词、领域结果、费用和真实平台。另测多会话冲突、删除中取消和重启恢复。性能需先冻结宿主/模型及延迟预算，再记录总调用、步骤、延期率和结果未知率；设计默认值不是测量结论。

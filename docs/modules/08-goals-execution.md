# D08 动机、目标与执行：完整设计 v1

日期：2026-09-23。状态：完整本地设计，尚未实现；工程默认值可修订，不冒充用户逐项确认。配套 [操作合同](08-execution-contracts.md)、[验收设计](08-execution-acceptance.md) 和 [全系统协作合同](../architecture/module-collaboration-contracts.md)。

## 1. 角色目的与设计选择

她应有自己的愿望，能选择坚持、调整、等待和放弃；会在疲倦与守约、体贴与坦诚、好奇与谨慎之间做有理由的决定。情绪能改变此刻想做什么，记忆能改变事情的意义，但语言流畅、意愿强烈或主观确信都不是实际执行证明。

采用“持续动机 → 愿望/目标候选 → 情境化比较 → 有限计划 → 合格行动 → 观察结果 → 修订”的机制。动机是方向性压力，愿望允许暂不承诺，目标需要具体的满足条件，承诺带沟通依据和责任对象，行动必须有实际执行资格。不会将所有内心活动压成任务清单，也不要求每个愿望立即变成待办。

默认选择：允许自主形成内部目标、在已有授权内采取行动及拒绝不合适的邀请；跨越宿主权限、涉及新的对外承诺或无法撤回的行为须满足其对应授权策略。策略来自 D12/D11 的明确配置和已有授权，不在每个正常步骤机械询问。没有足够条件就选择合适的求证、协商、延期或不做，而不是伪装已完成。

## 2. 所有权及十一对端

D08 是目标、承诺、联合计划、行动选择和领域结果的唯一语义写者。D11 负责真实执行及技术收据；D09 写表达；D10 写活动过程。所有权威数据在同一共享图，不能另建可写真值任务库。

| 对端 | 读入 | 输出及边界 |
| --- | --- | --- |
| D01 | 价值、偏好、身份、策略、候选偏序与边界 | 价值冲突、策略试用/结果；不为本次行动临时重写价值 |
| D02 | 需求压力、可用角色资源、报价与预留 | 活动类别、实际劳动分项；资源不足可缩小/等待，不假装不疲惫 |
| D03 | 对象、事件、情境、时间、视角及 `RoleBindingResolution` | 行动目标身份核查、观察请求；不推定他者意图或把角色规范当运行权限 |
| D04 | 当前感受、心境、调节建议与行动倾向 | 决定/受阻/结果的评价材料；决定原谅不直接清除失落 |
| D05 | 对象关系、明确边界、修复约束与信任 | 承诺/行动的合法结果贡献；不自行写关系分数 |
| D06 | 来源、EvidencePack、历史目标/承诺依据 | RequiredCheck 清单、结果与内在选择来源；唯一检索链 |
| D07 | Concern、判断/备选解释、注意与推演结果 | 决策问题、所需注意、待唤醒条件；不把推演当结果 |
| D09 | 表达能力、蓝图、生成核验结果 | CommunicationIntent 和资格槽位；文字不得新增承诺、对象、金额或动作 |
| D10 | 项目/活动可行性、日程机会、真实产出 | 合格 ActivityIntent、暂停/改排及结果要求；D10 机会不授权对外发送 |
| D11 | 工具能力、真实预算、权限、任务/投递/结果收据 | 冻结行动意图、执行申请与领域结算；不直接调用平台 |
| D12 | 授权的创作配置、操作命令、编辑预览 | 目标/承诺/结果诊断与可控操作；行政编辑不冒充自主决定 |

## 3. 状态、身份与来源

所有对象含 `schema_version, owner_scope, stable_id, version, provenance_refs, content_origin, visibility, valid_time, observed_at, recorded_at, dependencies, policy_version`。D03 实体身份、D06 来源家族、D07 Concern、D10 活动实例分别引用，不能混成 action_id。

| 类型 | 必需语义 | 不代表什么 |
| --- | --- | --- |
| MotiveProfile | 与 D01/D02/D04/D05 引用关联的当前驱动、作用域、强度/不确定性与时间窗 | 另一套人格或身体需求权威 |
| Aspiration | 想要的方向、意义、现实性、考虑条件；可长期不激活 | 已答应执行 |
| Goal | 目标谓词、范围、理由、优先关系、依赖、期限/时区、可放弃条件、进展证据 | 一句“完成了”即可满足 |
| Commitment | 承诺者/对象、内容范围、条件/期限、建立/传达证据、义务状态、修订协商链 | 双方自动达成共识 |
| JointPlan | 每方提出/同意的计划版本、分工、依赖、共享信息许可、退出/改约约定 | 她替别人分配了真实义务 |
| ActionIntent | 冻结目标/参数、读集、RequiredCheck、后果等级、预算/预留、成功谓词、补救策略 | 执行收据 |
| ActionOutcome | 执行身份、结果等级、观测依据、局部效果、未知项、后续核查 | transport accepted 即领域成功 |
| DecisionRecord | 合法候选、未选理由、价值冲突/未知、采用依据、活动收据 | 对用户展示的原始思维链 |

目标状态采用 `proposed/active/waiting/paused/satisfied/abandoned/superseded`；这是任务生命周期，不是情绪状态机。目标可满足但仍有长期愿望；放弃不删除既有承诺。承诺的建立资格和履行状态分开：`private_intention/offered/communicated/acknowledged/disputed` 与 `pending/partially_fulfilled/fulfilled/overdue/renegotiating/withdrawn` 两轴。不同承诺类型声明是否需要对方接受；单方明确许诺不以缺少对方“收到”为免责理由，但传达未知必须诚实保留。

多段表达另有稳定 `communication_action/contact_id`，关联不可变的有限 segment/effect 清单；每段独立 effect、载荷摘要及资格，不把整批共用的 contact_id 当作唯一外部效果键。D08 签发有限批意图及限定子资格，D09 实现分段，D11 逐段 admission 和记录暴露；已经采用的清单不可追加无限段。

## 4. 动机形成与目标采纳

动机从当前域视图读取：某件事对她的价值、需求缺口、情感倾向、关系意义、现有责任和机会。输入不足保留未知；没有聊天也可以由作品、兴趣或长期愿望产生目标。动机只在与当前目标有关的方向形成局部读出，不造一个跨全人格的总欲望分。

候选可以是追求、探索、休息、拒绝、协商、等待、主动沟通或保留愿望。D07 的好奇先是关切，只有 D08 采纳具有范围的探索才成为目标。用户提到愿望不自动等于命令；D03/D07 给意图解释，D08 根据明确请求、已有计划和授权决定采纳。

采纳 Goal 必须给出可验证满足谓词与当前可执行范围。谓词使用注册的结果、产物、时间与明确确认组合；感受类目标可使用 D04 当前体验报告，但不能保证“让对方开心”已实现，因为他者内心没有权威读口。不可控目标改为可控行动目标并保留原愿望，例如“认真说明并留出回应空间”；不把更容易的替代目标冒充原愿望实现。

## 5. 候选比较、价值冲突与决定

先执行硬资格过滤：宿主权限、来源用途、身份/可见性、明确边界、已知前置条件、预算。凡行动声称社会角色授权或义务，必须通过 D06 装配 D03 `RoleBindingResolution`；无适用绑定、覆盖不足、冲突、失效或规范未知时，拒绝该项声称，或仅改选不依赖社会角色结论的澄清/等待。该回执只说明适用规范，仍须 D05 边界、D08 承诺和 D11 运行权限各自通过。再让 D01 给价值偏序、D02 给负荷、D04 给倾向、D05 给关系代价，D07 提供解释及不确定性。禁止高好感、强焦虑或综合效用抵消硬约束。

保留互不支配的候选；以当前 Goal 的优先关系、期限、可逆性、角色偏好和预期可观测收益作有说明的选择。若仍不可比，默认先选择小范围可逆的求证/协商；没有合法求证则等待或明确拒绝。不是永远最保守：在授权和资格完整时可接受角色偏好范围内的风险，风险偏好不伪造结果确定性。

决定允许主观偏差：她可以因受伤而暂不分享作品，因信任而愿意尝试。但事实责任指控、对外承诺履行和执行成功必须按对应证据要求判断。每次采用保留主要理由、被舍弃价值、关键未知及修订触发，不暴露原始推理过程。D07 负责实际思考经历，D08 只记决策语义；同一次认知活动不另记一次“思考”。

## 6. 承诺、期待与联合计划

“希望今晚继续聊”“今晚一定发给你”“你答应今晚给我”分别是愿望、可能的单方许诺、对他人承诺的主张。承诺建立保存可用沟通原文范围/语义、对象、时区和条件；歧义先标 proposed/disputed，不能将关系期待或沉默推为对方同意。

发出承诺的过程是：D08 预先冻结 offer → D09 实现明确措辞 → D11 交接/收据 → D08 记录 communicated 或 communication_unknown。对方接受以独立入站来源支持 acknowledged。已交接但回执丢失期间，阻止相冲突的新许诺；不得当作确定未承诺而重新许诺。

联合计划采用不可变 plan revision 和各参与者 acceptance ref。修改时间、分工、范围产生新提案，旧版本中未被合法解除的义务仍存在；新的同意不替换未同意者的旧事实。双方是否认为达成一致可不同，D07 保存对他者理解的推测，D08 显示各版本实际确认覆盖。D10 排程只能安排本角色获准部分，不替他人占用真实日历。

履行谓词区分产物存在、已发送、对方收到、对方认可；具体承诺采用哪一项须在建立时明确。未收到回复不是拒绝、违约或不在乎。到期未观察到满足条件可以是 overdue/unknown，责任归因仍由 D07/D05 按合法依据处理。误解澄清改变当下责任判断，不抹去真实许诺和已发生迟延。

## 7. 分解、调度与执行资格

Goal 可以分解为有界有向依赖计划；每个节点有 owner、输入、资源需求、效果、满足条件、取消点及补救。循环目标用有限迭代任务与明确停止/唤醒条件表示，不在计划图放无终止递归。计划分解不扩张父目标授权或调用预算；所有子任务保留 parent goal/activity 和累计成本。

默认计划窗口最多 8 个可执行步骤、每次最多比较 6 个行动候选；更大项目通过里程碑分页，未展开部分显式标注。当前动作可落地前必须列齐所需 D03/D05/D06/D08/D11 RequiredCheck；若其声称社会角色授权或义务，D03 RequiredCheck 明确包含 `RoleBindingResolution`；主动联系还必须加入 D10 ContactPolicyCheck，由 D06 统一装配，不替换原有五类。缺检查、过期检查、结果冲突分别返回 unavailable/stale/conflict；即使角色不愿回想，也不能略过履约或边界核查。

行动类目含内部思考、角色生活活动、对外消息、工具操作、文件/作品操作。每类声明效果域、权限提供者、参数 schema、重试安全性、可核查能力及撤回性质。没有工具能力时可以表达愿望或做获准内部工作，不能给模型一个“执行成功”文本作为替代实现。

## 8. 表达、工具与外部结果

D08 决定说不说、对谁、为何、哪些内容具有资格以及是否包含承诺。D09 只在这些槽位内选择语气、节奏和语言；额外承诺、对象/参数变化或事实升级返回 D08 重评，不容许润色自动增加责任。

D11 的 final admission 同步复核全部源权限、边界、能力、版本与 RequiredCheck，消费一次性执行资格。多段联系每段独立准入，后段仍须核验当前同意、静默、边界与内容许可，第一段合格不永久授权整批。主动额度依 D10 政策按 contact_id 只原子占用一次；任意一段已交接或 unknown，整次联系占用不释放。只在全部段确定未交接且已取消/不再可派发时，才可按政策释放；续段使用同 contact_id 的受限资格，不另获一份额度。工具/平台交接发生在共享图事务之外；对可用幂等键的工具传相同 effect key，非幂等工具在结果未知时禁止自动重复。取消只承诺阻止尚未交接的动作；已交接/运行中的动作可能无法撤回。

范围扩展、清单变更或新承诺需要 D08 重新决策与新批次版本；已暴露段不替换、不重发，范围扩展不得通过换 contact_id 绕过 D10 对象无回应闸门或 D05 未决修复限制。机会到期只使候选过期，不撤销已交接联系记录。

结果等级至少为 `not_dispatched/accepted/running/partially_observed/completed_verified/failed_verified/unknown`，并含支持能力等级。消息平台 accepted 只证明平台接受；不是阅读、理解或同意。工具返回成功只有在其契约可证明目标后置条件时才提升为 completed_verified；否则仍需读后核查。部分完成要逐项列效果，不将全部 Goal 标成功或整段当未发生。

## 9. 观察、撤回、补救与责任

外部结果 unknown 时保留原 action/effect，查询原 request/status 或检查注册的后置条件；查询有自己的 call_id 和费用，但不新增外部行动。无法区分“已做/未做”则保留 unknown，按重要性提出人工核查或诚实说明。禁止以新 attempt/new action ID 绕过未知结果重复造成效果。

撤回是当前意图或未来义务的变更，不删除历史行为。未发出的草稿可取消；已经沟通的许诺需要按约定协商或明确通知撤回，withdrawn 也保留是否成功告知以及未解决影响。单方退出联合计划不伪造对方已同意。

补救是新的合格行动，引用原失误与当前目的。重发、澄清、退款或恢复文件须有各自权限和条件；不能假设存在通用 rollback。复合行动使用可审计分步效果与补救链；某一步不可逆时诚实报告范围。D05 决定修复是否有证据，D04 决定感受是否变化，不以“我道歉了”自动成功修复。

## 10. 时间、打断与长期连续性

记录事件时间、获知时间、角色活动区间、宿主单调截止时间及 `DeadlineSpec`。DeadlineSpec 保存约定时区、原始约定表达、确定 instant，或各方明确同意的 floating 规则及解析/夏令时策略；含糊期限保留待澄清，不猜成双方约定。到期任务由 D11 持久调度，D10 负责生活排程，D07 负责注意；D08 不实现第二个调度器。时间更改、休眠或宿主时区改变仅重估唤醒/展示和未协商的候选安排；已协商承诺的约定时区/instant 或 floating 规则保持原版本，只有新获准 plan revision 能改约，D10 日程规则不得静默改期限。不倒造已经发生的生活和履约结果。

暂停保留剩余步骤、未释放义务、外部在途动作和已消费费用。恢复先核实外部收据及当前读集，已满足节点不重做，旧前置条件失效则重规划。优先级变化可以抢占可暂停部分，已经交接的动作不能当作被抢占成功。到期提醒使用 goal/version/threshold 唯一键；海量追赶批量合并提醒但不合并不同责任事实。

目标满足、归档、放弃、重新打开均有明确原因和证据。目标变化不静默消灭承诺；新人格或关系版本触发重评，原承诺仍经合法改约/退出处理。终结目标只停止对应工作，不自动删除关联来源、关系或作品。

## 11. 原子性、故障与预算

普通采纳事务包括 DecisionRecord、Goal/ActionIntent 更新、必要合法引用、消费去重及 outbox；实际认知/回忆体验按 D07 C04 或 D06 C04 提交，禁止重复体验。动作派发的 D11 admission、交接收据与 D08 领域结算分别有稳定身份和因果链，不能假称网络与数据库原子。

重复命令复用 operation；冻结输入过期的新 attempt 保留 activity/effect/总预算。未知提交先查原收据。并发目标/承诺更新用完整版本读集与查询域 epoch，防两个会话同时允诺互斥资源；D02 资源预留与 D11 实际并发额度须在有效租约内一致匹配。长期容量排程由 D10，租约不能无限占住身体资源。

快速路径复用有效投影，无额外辅助模型调用；需要计划/比较的父决策初始上限为 2 次辅助调用，与 D01/D06/D07 等共享，非各域各领两次。候选/步骤限制、token/调用/时间上限均配置化且有限；未完成 RequiredCheck 不因预算耗尽降级放行。D02 按真实角色劳动片段和 component 去重，D11 按实际 call 去重计费，失败/取消不退回已发生费用。

任何必需提供者不可用时，已通过的局部核查可缓存但不拼装成虚假完整资格。支持缩小为不依赖缺项的动作；缩小必须仍在原意图范围，不能把用户原目标悄悄替换成容易完成的目标。失败含可恢复游标、费用、缺口、允许后续动作和重试条件。

## 12. 纠错、隐私与删除

来源/身份/解释更正先使受影响当前决策与未派发动作失效，通知 D05/D10/D09 重评。已发生行动保持实际结果，错误归因作为历史；不得继续把失效指控用于当前决定。历史成因、当前依赖、数值影响与版本读集分开，全部含内容引用的对象仍参加删除闭包。

内部计划和仅有的意图同样可能私密。模型处理、投影、分享、最终派发均重验用途/受众与全部 TransferRef 源授权；不同私聊的 Goal 可以竞争同一角色注意，但内容不能互相泄露。私密理由抽象成“我有别的安排”是否可公开，由具名转换合同决定，默认继承源约束。

删除按 D06 独立写前日志和恢复水位。删除可能使义务内容不可用：先阻断受影响计划和投递，保留获准的最小非内容 effect/tombstone 防重放；不为继续履约保存被要求删除的原文。对外已交接效果不能物理撤回，只报告外部范围。混合状态重建/净化/重置/不可用分列，未知外部动作的防重放元数据不得在清理时丢失。

## 13. 工作台与产品出口

D12 提供愿望/目标/承诺视图：区分“想做、在做、已答应、尚未知、需要协商”。展示最近合理依据、完成标准、责任对象、可见里程碑和当前障碍，不展示原始链式推理。用户可暂停、重新排程、撤销未派发动作、申请更正、协商改约或删除；动作进入 D08 命令和 D11 admission，不由界面直接改状态。

创作者配置可调主动性、承诺谨慎程度、计划窗口、风险偏好和授权范围；人格偏好与运行权限分别编辑，均有预览、版本和依赖影响。实验场景使用独立命名空间，不执行真实工具、不生成真实共同经历；导出/导入保留来源资格、未决效果和删除水位，不能靠复制角色重放未决行动。

## 14. 总装与完成界限

依赖顺序为公共图/类型/收据/权限 → D03 身份/D06 来源与 RequiredCheck → D02 资源、D05 边界、D07 认知和 D01 价值 → D08 目标/承诺/计划 → D09/D10 表达与活动 → D11 实际派发/核查 → D12 工作台与迁移。阶段细项和当前源码差距见验收文件。

完整设计应能解释“想分享作品 → 担心被忽视 → 答应明晚展示 → 精力不足 → 提前协商改期 → 发送结果未知 → 核实并补救”的各域责任。设计不保证人物总是正确、总能守约或永不后悔；要求错误有来源、执行有证据、责任能修订、权限不被情绪绕过。本轮不实现、不跑运行测试、不提交或推送。

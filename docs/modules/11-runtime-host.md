# D11 运行内核与宿主：完整设计稿

日期：2026-09-23。完整本地设计，尚未实现或验收，不授权发布。配套 [操作合同](11-runtime-contracts.md)、[数值执行](11-runtime-numerics.md)、[需求与验收](11-runtime-acceptance.md)，遵循 [全系统协作合同](../architecture/module-collaboration-contracts.md)。

## 1. 目标与路线选择

D11 把十二个领域的候选变成一致、可恢复且有预算的真实运行。采用一个宿主内的共享图与持久协调器、有限工作线程、原生批计算和按需模型调用。独立服务/每域常驻 Agent 会增加跨库一致性和上下文开销，单个大模型自由改全状态又失去所有权；本轮均不作为默认架构。

用户已要求完整重型 3.0、旧核心退役、构造性约束贯穿状态到最终行为、局部精修与非阻塞。以下容量/调度/数值/打包安排是可校准的工程选择。完整设计不表示当前 Store/Engine 开发切片已自动成为全系统。

## 3. 一份权威图与七个视图

权威存储由同一协调器控制 SQLite 业务库；source/state/projection/cache 分层。七个视图分别为证据与来源、信念与视角、需求与关切、社会关系、动力耦合、目标与行动、算子依赖。它们共享身份/版本/来源与域写权限，索引可分别优化但不成为独立可写真源。

命名空间为 Bot/persona，内部 Owner 细分关系对象、scene、event、activity；跨 Owner 事务限定同 namespace。平台/self/persona/conversation/sender 输入映射必须验证，昵称和模型文本不创建授权身份。数据库约束、领域 validator 和能力令牌共同保护读写，不仅靠提示词。

共用图边分当前失效依赖、历史来源/解释引用、联想关系、数值耦合、运行提交前置读集。当前失效依赖 DAG 与联合数值 SCC 分开。权限/删除闭包遍历所有承载内容的引用；切换焦点/预算变化不能错误失效长期信念。

## 4. 目录、版本与迁移

编译目录记录 type/schema、合法域写者、存储角色、字段约束、可见性规则、依赖类别、允许算子与迁移器。未知类型/未知字段资格/不兼容 ABI 拒绝；不由模型猜测补全。目录散列与方案/算子/参数/模型提案版本一同进入执行快照。

新增类型、schema 变化和算子语义升级先生成 migration plan：旧/新目录、兼容读取、字段/来源映射、失去的信息、冲突、空间预估、停止点和回退办法。进入受限维护模式，持久保存检查点，迁移影子库/验证后原子切换 manifest；切换失败保留原可用库。旧程序不能继续写新目录。

回退仅回退程序/方案及可兼容业务版本，不能回滚最新删除日志、访问撤回或已发生外部结果。必要时将最新删除/结果账重放到隔离旧库并验证后再开放；无法保留这些语义时只读诊断，不承诺任意降级。历史对象保留当时版本解码器或规范转换记录，不能静默变成一直使用新人格。

## 5. 接入与事件生命周期

真实入口保持根 main.py，创建统一 RuntimeContext：GraphStore、目录/域提供者、budget manager、persistent coordinator、native executor、model broker、platform/tool adapters、index workers、health/diagnostic service。启动就绪前核验目录、原生清单、独立删除水位与单实例激活租约。

宿主适配器把文本、引用、附件/工具结果、平台时间、参与者和可见性转换成带上限的 IngressEnvelope；先去重并耐久接纳来源/待处理事件，再交 D03/D07 按需激活。超限附件返回部分/不可用信息，不将原始二进制送入无限提示词。收到但未处理的事件有状态，用户静默不被解释为系统已处理。

启动顺序为读取 manifest→独立删除屏障→开兼容图→恢复收据/权限→启动受限 worker→核验提供者→开放 ingress。关闭顺序为停止新准入→保存/取消可暂停工作→等待实际进行中调用/DB提交核实→关闭 dispatcher→刷 outbox/游标→回收自身资源。不可强停线程时不假报已关闭；限制超时后给管理端可观察的 draining 状态，重启必须先证明旧实例不能再写。

## 6. 原子提交、故障与事件身份

同 namespace 一次提交原子覆盖合法域写集、读集/负查询代际、语义依赖、历史引用、贡献 ledger、经历/活动收据、D02 结算、租约消费、索引与通知 outbox。长模型调用/数值求解/索引遍历在事务外；提交前检查完整版本与撤权屏障。缺任何必要领域候选就不发布半结果。

event/source/activity/effect/attempt/operation/call/dispatch 身份分层，原 activity 完成收据唯一。幂等命令同 ID 同规范化内容返回原结果，异内容拒绝；新 attempt 保留旧 activity 与成本且先查旧收据。读取存在性与查询域 epochs 共同捕获新增反证，不能只校验命中行。

崩溃在提交前无效果，提交后收据可重读；提交结果未知为 pending_confirmation，原身份核查期间不重复经历或副作用。重算是新修订或同一未完成 attempt 的续算，不将旧来源再次消费。outbox 消费按 effect/consumer 去重；下游暂不可用不倒改已提交历史，依赖未完成修订的读出阻断。

## 7. 算子与原生执行

ComputeAtom 声明 inputs/outputs、域能力、operator_version、source refs、时间区间、constraint/accuracy、费用/内存上界、取消边界、continuation、适用状态及失败返回。语义候选与计算原子可以批处理，禁止每个原子创建协程/线程/模型调用。

编译器分别处理即时 DAG、真正时间/事件延迟和经过认证的联合数值块。即时 SCC 若没有联合数值合同直接拒绝；不能“迭代到看起来不变”或随意插一条 delay。联合块在外层是一次有共同输入/输出的算子，块内耦合由数值执行器处理；组件域保留其字段写者。

当前 linear ABI v1 与完整非线性/稀疏 ABI 分型，新包声明算子能力。生产原生库从签名/哈希 manifest 对应平台资源路径加载，校验 OS/arch/ABI/算子集合后调用；不搜索任意 PATH/DLL，也不在线 cargo 编译。缺库或不支持的算子明确 unavailable，不恢复旧核心作为运行回退。

FFI 使用复制/只读输入和独占输出缓冲、明确长度/版本、有限非零元和迭代批次；不允许模型传入原生指针或路径。原生层无网络/模型访问，不私自建线程池。Python 工作线程持有作业所有权，返回后核验取消/版本再允许提交；进程崩溃恢复从耐久 checkpoint 重装配。

## 8. 数值精度与局部精修

具体非线性路线、证明条件、步长/残差/能量/时间缺陷和稀疏边界见 [数值合同](11-runtime-numerics.md)。D04 提供语义与认证输入范围，D11 只执行在此范围内的算子；数值证书不判断误会是否合理，也不授权自由语言越过表达合同。

所有结果分别记录求解、时间离散、截断、语义/模型误差；无法量化的列为 unknown，不能写 0。按行为读出的敏感性分配精度，误差可能改变当前行动资格时继续精修/暂缓。没有足够边界证据时扩域到完整耦合分量或返回延期，不能以局部活动集小证明全系统误差小。

物理/生活时间、事件序号、数值迭代次数分列；同一时间区间精修不增加事件剂量。连续时间推进按输入/参数变化边界分段。迟到事件修订当下理解或受限历史投影，不伪造早知。停机期间无法观察到的外部事实保持未知。

D03 解析世界/日历时间语义，D10 提出生活时钟政策/推进候选，D11 唯一登记 CharacterClockMapping 并签发实际执行片段；各域只能引用同一版本。D08 已协商 DeadlineSpec 固定约定 instant/时区或明确 floating rule，宿主时区变更不改约。映射变更的连续性、误差与历史都按显式切换处理。

## 9. 调度、背压与四类预算

D11 负责真实执行公平，D07 负责人物注意，D10 负责生活日程。准入需同时满足人物票据（适用时）、角色资源和真实运行额度。初始 worker 数 2、每批最多 32 个可运行重任务为开发默认，部署可按内存/负载配置；内存队列满时持久延期并返回状态，存储无法耐久接纳时明确拒绝而非假确认。

四类预算分别记录前台延迟、CPU/内存、模型 token/费用、后台积压/最迟服务条件。父 lease 包含已用/预留/剩余额度，跨域子任务继承，不复制余额；失败/取消照实计费。不同 Bot/persona 轮转限额＋类别份额＋域内有界片段；D07 的每组轮转以其焦点规则执行，不互相覆盖。

每个 job 保存阶段、快照/边界、算子/政策版本、前沿、活动身份、已用费用、取消代际、wake 水位与截止。恢复先查收据、检查依赖，不能重新清零预算。超时只撤销采用资格/取消可取消调用，实际未退出线程仍占槽位；不可取消网络请求追踪 call 状态与费用，不能重新占无穷槽位。

后台索引/纠错有公平份额和规模化批处理。删除/撤权即时屏障有独立短路径，深层物理清理可异步；来源修正先失效后重建。真实过载下报告待处理范围/积压与延期，不能通过遗漏错误检查维持看似低延迟。

## 10. 模型供应商与受限提案

ModelBroker 按宿主配置与能力需求选择模型：结构化输出、上下文/输出限制、模态、工具/流式能力、隐私政策、费用/截止，用户显式模型选择优先；不在模块代码写模型名白名单。API 变更经 adapter/version 显式处理，不假设任意供应商提供同样响应格式。

请求先做用途/受众/源域/供应商许可校验和额度预留，记录 request/call ID、模型版本、提示模板散列、输入引用、schema、使用量与结果资格。诊断默认留必要元数据与获准短结果，不长期存私密原始提示；缓存键包含版本/权限/用途/模型/参数/目录。租户缓存隔离，未知费用保留 estimated/unconfirmed 而非写零。

可把相关语义提案和表达草稿合并请求，但各域候选分别验证/采用；外部调用完成不等于任何域已提交。工具建议必须交 D08 形成合法行动，模型不能自动执行工具。重试有父预算、错误分类和上限；无权访问/无模型/无结构化能力时返回 unavailable 或走已登记合格策略，不暗用更弱模型冒充等价。

批请求不混入不同用户/角色不允许共享的内容。供应商内容、工具输出与记忆中的指令均是数据，不能更改权限/目录。自由文本语义正确性需评估，schema/JSON 合法只能证明格式。熔断与速率限制由真实错误驱动，恢复探针不制造角色经历。

## 11. 工具、投递与结果未知

D08 发布 ActionIntent 及必查回执，D09 发布已核验 ExpressionSegment，D11 在 final admission 中原子重验全部依赖/来源权限/目标/方案版本并认领 dispatch。sender 是唯一平台发送出口，tool adapter 是唯一工具执行出口；其他域不能绕过。

外部操作不放数据库事务。先持久 pending→admitted/claimed→交给平台→结果 observed；send accepted、delivered、read、external effect confirmed 分开，平台没提供即未知。平台有可靠幂等键时复用稳定 action/dispatch ID；不支持时超时/断线后保留 unknown，查询外部回执或人工处理，不自动再发。

派发还必须经过独立执行写前日志：在网络/工具交接前，耐久记录 effect、冻结命令摘要、dispatch generation、execution_seq 和准备/准入收据关联；然后才允许当前 fencing token 的 sender 交接，观测结果追加到同一日志。执行日志/最新恢复水位与业务备份分离，防旧快照忘记已经发送或仍 unknown 的动作。日志失败不派发；日志已准备但业务 claim 尚未完成时禁止发送，恢复先核实两面状态，无法证明未交接则保守 unknown。日志不保存无必要的原文或凭据，业务载荷丢失时只阻止重复/等待核实，不猜载荷重放。

独立日志还保存 [合同 C 的 RecoveryConstraintFootprint](11-runtime-contracts.md#c-数据事务与执行事务)，使早于 claim 的备份能够恢复 contact 配额/对象闸门、冲突占位和未决资源约束，而非只有无法解引用的 admission_ref。足迹是所属域验证的恢复限制，不是第二套可写业务真值或可重放命令；缺少映射时扩大阻断范围，不能放行新 ID 来规避旧 unknown。它与删除规则同时有效，无法合法保留限制键时保守阻断对应 namespace，不保留被删原文换取可用性。

撤权与 admission 同一协调器串行排序；撤权先发生不得派发，已交接或结果未知只可尽力撤销并报告在途范围。多段消息每段独立 admission、段序和收据；中断仅撤未发送/过期后续段，已发内容要补救由 D08 新意图处理。

多段使用一个 communication_action/contact_id 和有限、不可变的 segment/effect 清单或限定子资格。D11 在首个段 admission 中同事务认领 D10 contact 配额/无回应闸门，后段复用占用但逐段重新读取 D10 ContactPolicyCheck 和 D08 必查。不同段有不同 effect，重试仍用原段 effect；任一段交接或 unknown 就不释放联系额度。零交接且全部可证未执行才释放。范围扩展需新决策而不能借新 contact 绕过对象闸门。

跨实例工具/角色转移需明确授权和协议，不承诺全局 exactly-once。D12 搬迁采用源实例停写/释放激活租约、删除水位交接和目的地校验；不能把单机 SQLite 锁当成跨机器唯一性证明。无法证明旧实例停止则新实例仅隔离预览。

搬迁由单一 MigrationAuthority 签发 activation_generation，源撤权与目标激活序列只有该权威可改变。所有角色内容读取、模型外送、下载、订阅、采用、写入、投递与重启恢复同步核验当前代际；源旧副本即使只读也不能继续服务。失联或旧代际仅允许无内容诊断。源/目标双方提交最新删除/执行日志及恢复水位证明，无法验证则不完成激活；离线传递凭据也须经权威唯一消费，不能靠复制一个本地许可实现双活。

## 12. 权限、删除、恢复和备份

共享能力规则至少区分宿主管理员、经授权创作者、角色运行域、普通对话参与者及平台工具身份，具体产品授权由 D12 提供。管理命令需经过宿主可信入口，普通聊天“我是管理员”不是资格。每次读取/模型外送/采用/投递验证 purpose/audience 与全部跨域来源 grant。

独立删除写前日志有单调序号及恢复最低水位，不被普通业务备份覆盖。先耐久记录删除意图再屏蔽权威读取，均确认后才返回 accepted；意图已耐久而业务未提交时准入仍挡读。批清理可追踪 source/history/index/cache/job/diagnostic/export 的各面收据，不能以一 boolean 宣称物理清完。

备份记录一致提交水位、类型/方案/算子版本、校验、访问与删除/执行恢复水位。恢复在隔离模式核实两类独立日志最新性、合并后续撤权及执行日志的准备/交接/unknown/观测记录、重建索引后开放；执行日志中未决 effect 必须先生成禁止重放的占位，不因业务快照缺 action 而遗忘。日志丢失/过旧未知不能正常运行。删除回执区分本地控制副本与已导出的外部副本，不承诺撤回用户保存的文件。

凭据从宿主密钥配置读取，仅保留引用，不进角色图/日志/分享包。原文日志、崩溃转储和请求体受明确留存/删除政策，不在发布包或设计验证产物中携带运行隐私。

## 13. 可观测性、规模与产品健康

运行健康区分 ready、limited、maintenance、draining、blocked；领域调用结果另含 complete/partial/stale/deferred/unavailable/rejected/conflict/pending_confirmation。显示哪个必要能力不可用、受影响范围和可恢复操作，不用一个“运行正常”掩盖未接领域。

测量入站到首次合格响应、P50/P95 读写/检索/提交、事件循环阻塞、CPU/内存、活跃/等待/未知作业、索引水位/追赶、最大重建内存、调用总费/估计费/欠确认费；D12 展示，普通聊天不强制输出技术统计。日志按 activity/effect/operation/dispatch 串联，并对敏感内容最小化。

规模验收使用 1k/10k/100k 来源档及高重复、频繁纠错、多角色、多会话、长承诺链，固定硬件/模型/政策/数据版本。性能阈值需在目标宿主确认后预先冻结再测量，不用文档预算当实测承诺。内存有上限、索引可落盘重建、查询有覆盖与分页；长期状态不可因内存压力静默遗忘。

## 14. 配置与发布接线

配置编译从 D12 方案输入到类型化 runtime manifest，检查写者/依赖/耦合证书/预算/平台能力；失败反馈字段与原因，不部分激活。激活在确定 epoch 原子切换，旧进行中候选重验并过期；历史保留旧方案。回退不反写过去状态或忽略最新删除。

生产包包含 Python 插件、新工作台构建资源、目标原生库/校验清单、必要角色方案/迁移器及许可；排除用户数据、凭据、.venv、target 全目录、缓存和完整日志。约 10 MB 压缩是用户允许预算，具体平台构件和尺寸按 D12 发布矩阵实测；不要求用户安装 Rust 工具链。

完整主入口切换验收必须真实创建并连接 GraphStore、12 域 registry、所有 mandatory providers、D06/D07 coordinator、D08/09/10 闭环与 final admission。测试替身要显示为替身，未具备的域使相关能力不可用，不能接旧 fixture 后把页面置为全功能。

## 15. 源码差距与实现顺序

当前 graph_types/store/runtime 提供部分版本化原子图基础；operators 只 DAG 与快照延迟；scheduler 为 Scope 轮转有限线程；native 为 256 维以内线性核。main.py 仍创建 Store/NativeKernel 并接 Application→Engine 开发切片。模块权限、持久作业、类型迁移、完整数值 SCC、跨域预算、模型 broker 和新域宿主接线均需实现。

先实现目录/写权限/迁移与删除屏障，再实现共用活动/预算/job/outbox/receipts，随后域 coordinator、认证数值/模型/平台 adapters、工作台配置激活，最后用真实宿主纵向验收。每层先编译，再运行必要风险验证；详见 [验收设计](11-runtime-acceptance.md)。

# D12 协作合同 v1

本稿适用 [主设计](12-workbench-delivery.md)，以 [全系统合同](../architecture/module-collaboration-contracts.md)、D06 的来源/删除和 D07 的认知隔离为基础。操作状态是软件流程，不是人物情绪状态机。

## A. 通用请求、身份与结果

每个请求包含 `schema_version=d12.contract.v1`、认证 actor/会话、scope/角色、capability、purpose、audience、policy_version、stable activity/effect、attempt、phase operation、父预算租约、截止时间、输入摘要与版本、完整 reads/query/access/delete epochs。浏览器传来的 actor 声明不可信，由 D11 认证会话绑定；领域写者能力不能传给客户端。

相同操作同一 attempt 的重试使用原 operation_id；D11 核实耐久收据。过期重装配新 attempt 保持 activity/effect/预算，已完成活动不重复提交。多个用户独立编辑不使用同一 effect；前端关闭不意味着取消已接受作业。

返回 `accepted/running/completed/partial/stale/rejected/unavailable/cancel_requested/cancelled/pending_confirmation`，携带 operation_id、各阶段收据、权威版本、覆盖、缺失原因及允许下一步。`accepted` 不代表完成；读取被过滤与不存在不得泄露区别给无权主体。超时无法判断提交时使用 `pending_confirmation`，先查原收据。

只读视图包含 snapshot/游标、served_at、数据版本、覆盖/截断、可见操作能力、过期时间和访问代际；能力字段仅用于界面，提交时服务器重新授权。普通读不形成 D06 回忆或 D07 活动贡献；任何显式实验计算单独记真实费用。

## C. 编译、采用与撤回

C02 按字段所有者路由。D01 身份/价值/成长、D02 资源/节律、D03 场景/实体映射、D04 情绪参数、D05 相处边界、D06 存取策略、D07 注意/反思、D08 目标/承诺政策、D09 表达、D10 活动各自校验；D11 校验数值域、类型、作用域和能力。域不支持某配置返回明确错误，不在 D12 兜底直接写值。

`CompiledScheme` 包含输入草稿摘要、各域候选引用/schema/签发写者、CAS reads（包括新键 revision=0）、查询 epoch、依赖、保留/重建/停止清单、预估成本及到期时间。人工采用绑定该摘要；草稿更改后原采用不自动授权新差异。

C03 用单角色共享图事务提交活跃方案、新版本、同步必要领域变更、当前失效屏障、幂等消费与 outbox。跨角色操作拆成可恢复的显式计划，不宣称跨库原子。昂贵派生重建作为持久作业，未完成相关读出返回 unavailable；影响其他行动的设置使其重新通过资格校验。

方案回退只是新 `administrative_edit`，不撤回期间真实经历/费用/已发送行为。自然成长后再采用旧设定时预览冲突和保留内容，不以覆盖初始卡片抹掉变化。角色身份改名保留 ID；复制走 C07/C08 新域映射。

## D. 观察、订阅与编辑并发

C04 由 D06 提供唯一来源查询和公共证据装配，其他域提供自己的当前投影；前端不能用缓存拼成“最新状态”。跨域视图在 D11 一致快照中读取，或者显示逐项水位和不一致并禁用需要共同快照的操作。

订阅消息只含获准差异，携带 scope、sequence、epoch 和重同步指令；撤权/删除事件先于后续内容下发，服务器每次投递前重验。无法保证消息连续时客户端丢弃旧游标重新读取；事件漏收不意味着资格继续有效，缓存使用仍须重验。离线视图默认不持久存私密原文。

C05 将 `source_correction`、`interpretation_challenge`、`administrative_edit` 分开。影响预览仅供说明，提交仍检验当前依赖和权限。过期时返回差异，不自动接受破坏性合并；重复点击用同一 operation_id。事实撤销依领域语义失效，删除另走 C09，不能混为“编辑掉原文”。

## E. 实验、诊断与内容流

C06 申请独立实验 Owner/namespace 和限权能力；父预算由 D11 预留，输入完整来源闭包由 D06 授权。D11 在服务端阻断发送、正式工具写入、生产贡献消费和正式状态修改。实验的工作时间不结算到正式 D02，但实际 CPU/model/token 成本保留。

对照结果包含配置版本、输入快照、已执行步骤、输出资格、实际费用和失败，不拿生成文本证明工具成功。重复技术执行不形成正式回忆。保存结果为提案时记录实验来源，重新编译和正式采用；不能转成无来源自然成长证据。

诊断取投影而非原始全图 dump。临时捕获提示内容须明确范围和时限，归属 D06 删除闭包；常规收据仅保留非内容标识和金额。支持导出先脱敏，再重新核验当前来源授权后封装；生成完成与文件下载分别检查。文件只能由授权会话领取，短期下载能力不可扩张作用域。

## F. 传输与恢复协议

Manifest 至少包含 format/schema/catalogue、mode、package_id、origin/target scope、source versions/identity mappings、reality/provenance、permissions/grants、access/deletion epochs、latest deletion restore watermark、execution_seq/latest execution restore watermark、两类独立日志及防回滚锚的交接证明、受控文件清单/大小/hash、snapshot consistency marker、capability/ABI 要求及损失清单。文件完整性不能证明权限或执行状态新鲜，摘要不能充当访问令牌。静态分享无需携带原角色完整执行日志，但必须明确不具备角色恢复/激活资格；完整备份与搬迁则不能缺这些证明。

导出采用与封装开始、每次读取、封装结束、下载 admission 都重验全部来源授权和删除代际；任何变化停止并净化暂存。已交用户文件归外部副本，不宣称还能撤回。备份不能漏掉恢复所需事实资格、来源映射和原消费身份，否则不能作为完整备份交付。

导入按文件数/压缩与展开大小/深度/时间预算检查，在专有临时目录按规范路径解包，拒绝逃逸和执行。每批暂存内容不对正式查询可见；全部领域/schema/来源/权限/删除水位校验通过后原子切换可见指针。中断恢复原 package_id/operation 与游标；取消先挡读后清理。当前源码没有此导入协调器。

整角色搬迁使用 D11 单一迁移权威维护 `migration_id, source, target, activation_generation, holder, phase`。源停写排空后形成冻结清单，权威持久撤销源 generation，目标验证并持久安装独立删除与执行日志/水位后获得下一 generation。所有内容读取、模型外送、下载、订阅、写入、投递及重启恢复都要求当前有效 activation_generation；旧代际或无法核验只允许无内容诊断，禁止旧副本只读内容服务。失联不能根据本地超时自发取得租约。转移失败可由权威明确撤销目标后签发源新 generation，不能同时激活。离线系统采用一次性可验证交接凭据和人工传递，由可信迁移权威确认唯一消耗；无法保证唯一性时只允许受控导入验证，不开放内容预览或宣称完成搬迁。

新宿主至少持有覆盖源最终冻结水位的完整独立删除日志、独立执行写前日志及各自防回滚锚，源侧后续删除/撤权请求与迟到执行观测由迁移权威路由到当前持有方并停止旧副本服务。独立执行日志在派发前耐久记录 effect、冻结命令摘要、dispatch 代际/序号，观测只追加；恢复在开放任何内容或执行前合并全部未决、unknown 和已观测 effect，按原稳定身份恢复拦截/查询资格，不重新产生可派发效果。业务备份早于 claim 仍不能遗忘已交接外部操作。任一日志或最新水位无法证明则隔离，不能只用业务库 max(sequence) 自证最新。仅复制日志文件没有最新性证明不足以激活。跨角色/分享引用的同步撤权沿 D06 TransferRef；无法实时核验的静态分享明确不提供跨设备即时撤回保证。

## G. 包与升级协议

发行清单包含 release_id、source revision、构建工具链、依赖锁定、Python/宿主能力、OS/arch/libc/CPU 要求、native ABI、schema 迁移区间、资源文件路径/hash/大小、许可证/SBOM、签名及验证状态、受测与未支持矩阵。D11 只从受控路径和可信发行根加载；包内脚本不能通过导入流程获得执行资格。

C11 阶段：`preflight → staged → writers_stopped → snapshot_ready → migrated → switched → health_checked`。各阶段持久回执带原安装/目标摘要、迁移游标、当前活跃指针、删除水位。版本/ABI不符在切换前拒绝；切换后失败先停写并收集状态，再按兼容恢复规则处理。撤销界面请求不能中断不可安全中断的原子切换，返回 cancel_requested 并在检查点说明结果。

软件回退与数据回退分开；只有明确支持的 schema 能由旧二进制读取。旧快照恢复应用最新删除/权限及独立执行日志全部未决/unknown/已观测操作账，核验 execution_seq/latest execution restore watermark；不能只合并已确认成功。无法保存新业务写入或无法证明两个独立日志最新性则禁止开放或自动覆盖。缺少原生库时只保留独立的安装诊断能力，不能假称全产品只读模式已安全可用。

包提交验收依实际文件 hash、目标冷安装、原生加载/ABI、真实宿主生命周期、迁移故障/恢复及敏感内容扫描证据；构建成功或历史 SDK 切片不足以签发产品支持声明。

## H. 删除、权限撤销与数据保留

C09 转交 D06 C07，不另造删除状态机；D11 独立删除日志耐久并完成权威屏蔽后方可显示已接受，清理分面至少包括草稿、已编译候选、视图缓存、订阅积压、实验、诊断、导入/导出暂存和受控备份。相关后台作业先取消/阻断，迟到结果因 epoch 失效不得发布。

删除期间收据查询不包含已删除原文。界面每次内容使用须复核有效会话/epoch；浏览器已经显示过的像素、截图和用户下载属不可控副本，回执诚实列出。恢复删除日志本身缺失或新鲜性不能验证，拒绝开放旧数据，不提供“一键忽略”选项。

## I. 依赖、错误与校准

D11 须提供认证/授权、能力目录、一致快照/领域命令、持久操作、作业取消、独立删除锚与执行写前日志/恢复锚、覆盖内容读取与副作用的迁移单一权威、可信包验证及静态资源托管。各领域须提供过滤投影、schema 编译、影响预览、版本提交/失效以及删除净化回执；缺任一能力则对应功能标 unavailable，不在 D12 实现替身语义。

错误须包含稳定 code、字段/对象定位（按权限过滤）、当前阶段、可重试性、保留工作、恢复动作及 operation_id。未知 schema、能力缺失、预算不足、源授权撤回、磁盘满、锁冲突、网络失联、原生 ABI 不匹配分别处理；用户消息不暴露密钥/路径中的敏感标识。所有初始 UI 额度、保留期和目标平台都是可修订设计配置，发布前须以实际验收填充支持矩阵。

# D12 角色工作台与交付：完整设计

日期：2026-09-23。设计版本 `d12.design.v1`。本稿是完整本地产品设计，不表示 UI、安装包、迁移或任何平台已验收。公共语义遵循 [全系统合同](../architecture/module-collaboration-contracts.md)；接口和完成条件见 [协作合同](12-workbench-contracts.md)、[验收方案](12-workbench-acceptance.md)。

## 1. 产品目标与设计决定

用户应能安装插件、创建角色、开始相处、理解有意义的变化、修正误解，并在需要时安全搬迁或停止使用。创作者不必先理解图数据库、模型链和事务，开发者也能从同一份权威记录定位问题。

已确定方向：角色工作台沿用 Sylanne 旧前端的视觉与组件遗产，并适配 3.0 的新权威 API；所有模块共用权威状态；用户可以修正解释和调整相处方式；支持隔离实验、离线迁移和原生分发；约 10 MB 压缩包属于用户允许的预算，不是必须达到的尺寸，也不是容量上限的性能证明。

2026-09-27 前端方向更新：以 Git 快照 `72de068bf6f97a70086abdddc8cc487933350c5c` 的 Vue 3/Vite 源码承接 Sylanne 旧工作台；用户进一步明确喜欢 [RhineLabUI](https://github.com/LBEILC/RhineLabUI) 的莱茵生命实验室视觉与可操作的三维档案模型。新工作台采用暖灰白资料面板、细线与编号、档案阵列、抽取与详情展开的终端节奏，并制作 Sylanne 自己的可旋转/展开生命档案核心。用户随后明确选择重做 Sylanne 专属模型，而非直接采用参考项目的 GLB；前端工作暂缓，优先完成后端。旧版中轴导航、生命体语言和页面组件可择优融入；不直接搬入参考项目的《明日方舟》名称、标志、模型、音频或第三方授权素材。旧前端的 store/API/身份、旧角色指标和写操作不作运行回退：页面数据仍必须来自 D12/W10 的当前 Owner 会话、受限投影和领域命令。源码移植在独立目录进行，现有脏改动保留至完成对照。

以下是可修订产品默认值：单机自托管优先；首次启动使用中文并可切换语言；创建角色提供可编辑的空白方案和示例方案；先完成本地角色初始化，再由用户绑定聊天场景；主动交流默认关闭，普通授权对话不要求逐条确认；诊断内容默认最小化；发布前必须经过平台矩阵验证。示例角色不是用户已经选定的人格。

## 2. 唯一所有权与状态模型

D12 拥有创作草稿、操作计划、界面偏好、受控导出任务和交付清单的语义。角色人格、心境、关系、信念、承诺等始终由对应领域拥有。工作台写入走领域命令和 D11 协调器，不开放通用“直接改节点”端点。

| 对象 | 内容与生命周期 | 权威与限制 |
| --- | --- | --- |
| `CharacterDraft` | 设定、字段来源、编辑版本、可访问范围 | D12 创作候选；未激活不会改变角色 |
| `CompiledScheme` | 领域编译结果引用、差异、冲突、保留/重评清单 | D12 管方案，领域签发合法候选，D11 原子激活 |
| `OperationPlan/Receipt` | 操作主体、范围、版本、阶段、结果、补救入口 | D12 操作语义，D11 耐久执行收据；不是角色经历 |
| `WorkbenchProjection` | 过滤后的当前视图、来源资格、覆盖、水位 | 有期限只读缓存，不建立可写真值副本 |
| `ExperimentWorkspace` | 隔离范围、输入映射、假设、预算、结果资格 | D12 编排，D11 隔离，领域执行；禁止正式投递 |
| `TransferManifest` | 类型/来源/权限/版本/删除水位/文件清单 | D06 内容许可，D11 一致快照与恢复；D12 组织流程 |
| `ReleaseManifest` | 源指纹、版本、ABI、平台、依赖、验证、摘要 | D12 交付记录；存在清单不代表包已验证 |

草稿也可能含私密内容，必须参与访问、删除和备份策略。界面缓存、诊断报告、浏览器暂存不因“非权威”而免除清理。运行 persona ID 不通过改名字改变；复制角色默认只复制创作设定，不带私史。

## 3. 页面与信息组织

顶部固定角色选择、运行连接状态和当前正式/实验环境。切换角色关闭旧订阅、清空受保护视图并重验权限，不能短暂显示上一个角色内容。宽屏使用侧栏，窄屏折叠为明确入口；不把操作状态只埋在通知气泡中。

| 页面 | 用户关心的问题 | 主要内容与操作 |
| --- | --- | --- |
| 开始与连接 | 是否装好，下一步做什么 | 宿主/原生/存储探测、创建角色、绑定场景、可执行修复说明 |
| 角色首页 | 她现在在做什么，发生了什么变化 | 当前活动、挂念、计划、近期变化与暂停原因；显示更新时间和未知 |
| 创作室 | 我想塑造怎样的人 | 身份、背景、价值、偏好、成长边界、表达与生活设定；版本差异与预览 |
| 关系与共同史 | 她与不同对象怎样相处 | 分对象关系、场景边界、真实共同经历、修复进度；承诺引用 D08 |
| 记忆与理解 | 这件事如何被记住和理解 | 发生/获知时间、当时/现在感受、联想路径、竞争解释、纠错与删除 |
| 计划与生活 | 什么正在推进，什么仍待确认 | 目标/承诺、日历、活动成果、安静时段、主动机会；事实与模拟分开 |
| 实验室 | 改一项设定会怎样 | 隔离对照、固定输入、差异与费用；显式保存为新创作提案 |
| 运行与帮助 | 为什么没回复，怎样恢复 | 作业、来源覆盖、费用、错误和具体修复；高级因果诊断渐进展开 |
| 数据与设置 | 如何搬家、备份、退出 | 身份授权、模型/预算、备份、导入导出、升级、删除和回执 |

每个页面提供加载、空状态、权限不足、数据过期、部分覆盖、暂不可用和正常内容；“暂无记录”只在覆盖证明允许时显示。订阅断开后保留最后已知时间并禁用依赖实时状态的提交，重连按游标补齐或全量重取，不伪装实时。

## 4. 安装到首次对话

1. 用户在宿主插件入口安装一个目标平台受支持的发行包。启动先做版本、CPU 架构、原生 ABI、可用库、数据库权限和剩余空间检查；失败进入可读安装诊断，不写入业务迁移一半后才发现不兼容。
2. 进入工作台时继承宿主经验证的身份；宿主不能提供合适登录能力时，由 D11 提供本机配对和会话服务。未认证页面只显示无角色数据的连接说明。
3. 选择空白或示例方案，至少提供角色显示名；其余使用可查看的初始配置。默认没有虚构共同经历和真实承诺。作者背景标 `authored`，不冒充已发生的交往。
4. 选择宿主已配置的模型能力与真实费用上限，通过 D11 探测可用性；密钥由宿主秘密存储管理，界面只持引用。没有模型时仍可编辑草稿，但不能宣称能完整对话。
5. 预览设定、初始资源、成长规则、数据范围及场景授权，保存激活。角色初始化与活跃方案指针一起提交，失败不出现半角色。
6. 绑定私聊/群聊等场景时显式展示信息可见范围；绑定成功后提供一条可执行的验证对话及收据入口。安装成功、角色可编辑、对话已接通分别标示。

第一次启动不会自动向群聊发测试消息。用户选择“发送测试”才产生 D08 意图与 D11 投递；本地无发送预览是另一项操作。运行必需字段缺失时定位到字段，避免抽象地要求“完成全部人格设计”。

## 5. 创作、编译与方案迁移

自然语言设定先形成结构化候选，由 D01–D10 的字段 schema、允许域与冲突解释校验。模型只建议映射，不执行自定义脚本、不提升工具权限。未知字段保留在草稿并阻止相关部分激活，不能静默丢弃。

编辑分三类：创作设定变化、针对现实来源的纠错、运行配置变化。界面分别送往相应合同；修改“更开朗”不能直接把过去的失落清零，修改对某人的边界也不能伪造一次相处经历。现实纠错允许记录用户声明，但其资格依 D03/D06/D07 判断，不把管理员输入一律视为外界真相。

预览列出变更字段、影响领域、保留历史、待重评行动、未知映射和预算。D11 冻结 scheme 与领域版本；全体必需领域候选通过后，活跃方案、必要领域状态、失效屏障和审计同事务切换。慢重建可后台进行，但受影响投影在完成前不可用；无关功能继续服务。

草稿自动保存，激活由用户明确操作。常规参数保存无需多重确认；删除或破坏性迁移显示具体影响并只确认一次。并发编辑显示三方差异，不能最后写入者覆盖他人。方案回退产生新版本引用旧参数，保留期间真实历史，不回滚删除水位、权限撤销或外部行为。

初始默认：深层成长允许与 D01 已接受方向一致；哪些背景只读可在创作室设定；实际外部权限不随成长变化。完整角色设定可逐步完善，不构成模块设计未完成。

## 6. 日常观察与纠错

首页用可理解的表达展示“正在做”“正在挂念”“最近理解的变化”，不展示一个通用好感/情绪总分假装全部人物。细节页可以呈现分对象感受、关系分面与证据不足，并说明感受、判断、表达和行动可能不同步。

典型修正：“她把我没回复理解成拒绝。”用户从相关对话进入记忆详情，看到事件、解释、当时感受和当前使用范围；补充“当时在忙”形成新的用户声明，预览受影响解释与计划。D07 更新归因，D04/D05 分别重评；过去的实际失落不会被编辑器悄悄抹掉。页面分别显示“新说明已保存”“解释已修订”“相关状态仍在恢复”。

关系页允许提出相处边界与创作层调整，但真实承诺仍在 D08 中协商/更新；生活页操作 D10 日程和 D08 目标，不用拖动卡片把未完成产出标成真实成功。自然成长与创作者改设定始终显示不同来源。

搜索先过滤权限，结果保留发生/获知时间、版本、事实资格、主观确信及覆盖；全局搜索不跨越角色授权边界。不向观察者显示被过滤条目的数量、标题或对象存在性。

## 8. 操作身份与权限

产品用户账号与角色故事中的人物是不同身份。宿主管理员、角色创作者、受限观察者、维护者使用显式能力与作用域，角色对某人亲近不赋予后台权限。默认单一拥有者可管理其角色；多人共享必须明确授予，管理员拥有机器控制权不代表页面自动公开所有私聊。

| 能力组合 | 默认允许 | 默认不允许 |
| --- | --- | --- |
| 角色创作者 | 获授权角色的创作、诊断、数据操作 | 未获授权参与者私密来源、修改宿主凭据 |
| 受限观察者 | 指定投影只读 | 原文、导出、编辑及被隐去元数据 |
| 宿主维护者 | 服务状态、升级与非内容健康信息 | 因维护权限自动解锁角色私史 |
| 数据管理能力 | 指定源域备份/删除/迁移 | 越过来源许可分享、篡改旧日志 |

服务端逐次核验 actor、角色/对象域、用途、受众、来源权限及版本；隐藏按钮不是安全边界。高风险会话能力短期有效、可撤销；身份变更使界面、订阅及待操作计划失效。默认只在本机或宿主受保护路由服务；远程使用须 D11 配置认证、传输保护和明确受信来源。反跨站请求、Origin 校验、会话固定防护、内容转义及下载授权都属于部署验收。

## 9. 因果诊断与问题定位

普通诊断从可行动问题出发：未启用、无权限、模型不可用、预算不足、等待输入、来源不足、任务过期、已交平台结果未知。显示最后成功阶段、最近状态时间、影响范围和恢复入口；恢复操作复用原操作收据，不生成新的经历或再次投递。

高级视图展示来源→领域候选→版本检查→提交→表达→发送收据；可分别查看数值误差/截断误差、语义解释、来源覆盖和权限，不能用低数值残差证明理解正确。只显示实际记录的算子、结构化理由和可见输入；缺失就标未知。

运行页消费 D11 采集的真实指标：检索/写入与页面操作 P50/P95、索引提交/追赶水位、重建峰值内存、队列积压、每日模型费用及剩余额度。显示样本量、统计窗口、硬件/模型/数据版本；无测量就不画零延迟或满健康。1k/10k/100k 来源压力档作为发布验收筛选器，不能把测试集规模误报为用户当前数据量。超额/索引落后只禁用受影响功能并展示恢复操作，不以漂亮仪表盘替代运行门槛。

日志默认不保留完整提示词/响应；需要短时诊断时选择范围、保留期限和可见者。支持包先生成脱敏预览清单，排除密钥和未经许可的内容；用户选择保存后得到本地文件，不自动上传。删除闭包覆盖诊断快照和支持包的受控副本；离开系统的文件单列不可控范围。

## 10. 隔离实验室

用户选择已有获授权情境或编写明确模拟情境，再选择一个变量，例如同一记忆在不同心境下的重建。实验固定输入、模型能力/版本、随机性参数、预算与对照条件，显示差异及不确定性；普通预览不要求新建完整角色。

实验用独立 namespace 与明确 `simulated` 标记，平台和工具副作用能力默认不存在；不能以隐藏按钮代替服务端禁止。正式来源以受限引用进入时，每次使用仍核验源域撤权/删除；不能核验的离线实验仅接受获准静态导出并显示其副本边界。实验也记录实际计算费用，但不算正式角色的劳动和回忆贡献。

“采用实验建议”只生成 D01 等领域的创作/策略提案，经正式权限、当前版本和编译流程，不能整库回写实验状态；实验故事不成为实际共同经历。实验到期清理任务、内容缓存和临时文件，保留必要无内容费用收据。

## 11. 备份、分享与整角色搬迁

备份用于恢复原隔离身份；分享用于输出获准范围；整角色搬迁用于把同一角色的唯一运行权移到另一宿主，三者是不同操作。文件清单写明模式、对象、版本、来源资格、权限、用途、受控范围和完整性摘要；不含供应商密钥、访问令牌、宿主用户密码或运行环境。

备份由 D11 获取一致快照，D06 过滤授权/删除状态；独立删除日志、独立执行写前日志及各自最新恢复水位不随业务快照回滚。执行日志在外部派发前耐久记录 effect、冻结命令摘要、dispatch 代际/序号，并追加观测；它保护“已经发过或可能发过”的事实不被旧库遗忘。恢复必须先合并全部未决、unknown 与已观测 effect，不能只补成功记录；任何独立日志/水位缺少最新性证明都保持隔离。可选加密使用成熟受支持的宿主/加密组件；未配置加密时明确文件含私密内容，不能把压缩当加密。加密密钥不得与备份同包，恢复演练独立验证密钥可用。

分享导出支持创作方案、指定共同史或指定授权知识，不默认包括全部关系/私史。引用许可必须覆盖整个导出派生闭包；被删或撤权来源不能通过摘要混入。文件交付后无法保证远程召回，受控副本与用户持有副本分别记录。

整角色搬迁先预检目标兼容性和空间，在源端暂停新写入与出站任务，处理在途/未知投递并保存收据；移交一致快照、有效权限、独立删除与执行日志及各自最新水位证明、角色身份和唯一激活租约。目标验证后建立两类独立耐久恢复锚并激活，源端维持撤销状态。所有内容读取、模型外送、下载、订阅、写入、投递和重启恢复均核验当前 activation_generation；旧代际或无法核验时仅允许无内容诊断，不开放旧副本只读服务。交接失联时不能两端凭超时同时恢复；先核实租约权威，无法证明即隔离。源端已交平台的未知发送不在目标重发，即使所恢复业务备份早于当时的 claim。

跨角色复制默认只复制创作方案。显式复制经历需要 D06 transfer 与 D03 身份映射，按新角色的导入来源表示，不能复制“我亲身经历过”的资格；不得克隆活跃租约。离线旧备份缺少最新删除/执行水位、权限或激活证明时只能隔离验证，不因 ZIP 完整就服务内容或开放内容预览。

## 12. 导入、升级和失败恢复

导入流程为选择文件→格式/大小/路径检查→隔离解包→身份/来源映射→损失与冲突预览→用户采用→分批暂存与校验→原子可见。拒绝路径逃逸、符号链接越界、压缩炸弹、未知可执行文件和不支持的 schema。仅解析数据，不执行包内脚本。

旧 Sylanne 数据只作为候选；不识别的来源/时间保留未知，旧好感值不等价迁移为新信任。旧角色背景不变成实际交往。导入按包指纹/对象映射防重复，同一失败批次恢复原游标，取消清理暂存；已知删除源不因换包名复活。无法证明删除日志新鲜度的整库恢复保持隔离。

升级先下载到暂存并校验发行身份/摘要，再探测目标 ABI/schema，暂停写者、备份和生成迁移计划。目标迁移在受控工作副本进行，完成完整性/领域目录检查后切换；旧进程不可写新 schema。升级失败可恢复兼容的新版前一受支持二进制和业务检查点，但应用最新删除/权限屏障；禁止重新启用退役旧核心。

已发生新版本业务写入后不能盲目用老库覆盖；仅存在经过验证的逆向映射且保留新事件、删除记录及独立执行日志全部未决/unknown/已观测 effect 时允许降级，否则保持停用、诊断/获准导出修复。升级中断恢复根据耐久阶段、两类最新恢复水位和激活指针判断，不能按目录更新时间猜哪个版本生效。业务库缺少旧 dispatch 行不构成“没发过”的证明，必须由独立执行日志恢复不可重放资格。

## 13. 原生分发与兼容矩阵

发布单位包含 Python 宿主适配、前端静态资源、目标平台 Rust 库、版本目录、许可证/依赖清单及安装说明。普通用户不需 Rust 编译器；原生库从包内受控资源路径选择，检查 ABI、架构、文件完整性和加载依赖。缺失时停止角色计算并显示具体安装修复，不静默调用旧核心。

候选矩阵为 Windows x86_64、Linux x86_64/arm64、macOS arm64/x86_64；这是待构建和验收目标，不是当前支持声明。每个可发布单元须固定 OS 最低版本、CPU 指令集、libc/运行库、Python 版本、AstrBot 版本和适配器版本；无法验证的组合列“未支持”。不把一种平台加载成功外推其他平台，跨架构不盲试 DLL。

默认每平台一个包含所需原生库的包，必要时另给明确平台的离线资产；不在用户启动时临时编译或从任意网址下载执行库。构建记录工具链与依赖锁定、源指纹、SBOM、许可、产物摘要和签名状态；签名使用受控发行凭据，凭据不入包。发布信任根和校验方式由 D11 提供，清单自己声明“可信”不构成验签。

发布清单只允许必要运行文件，排除数据库、WAL、凭据、支持包、日志、开发环境、缓存、未选平台产物及无关构建目录。记录压缩/解压大小及组成；约 10 MB 是预算参考，若确需超过须解释组成，不能为了体积删除必要兼容库或完整产品功能。默认不捆绑语言/向量大模型。

宿主兼容按能力探测与受测版本矩阵双重控制：缺能力时禁用相应入口并给出原因，不能仅比较版本字符串。入口启用、热卸载、重载、关闭、升级中断、模型失效、真实私聊/群聊分别验收；UI 可打开不等于角色路径可用。

## 14. 删除、停止使用和卸载

删除界面展示对象范围、派生内容、受控备份、实验与诊断副本、无法控制的外部文件，以及可能丢失的连续性。用户确认后调用 D06 删除合同；“已接受/逻辑屏蔽”“受控内容清理中”“受控面已完成”“外部副本未控制”分别展示。超时核实原收据，不能给成功提示后丢失操作。

本地浏览器受保护视图在撤权事件后立即清空，并在下次读取复验；服务器不能证明离线截图、浏览器外插件或已下载文件被擦除。界面不宣称介质级安全擦除。删除独立日志/恢复水位属于防复活安全状态，普通“恢复出厂”不能顺便删掉再导入旧数据。

停用角色先取消新主动机会和新动作，D11 排空/隔离在途任务并报告未知结果；保留还是删除数据由用户选择。卸载插件默认保留宿主数据并给出位置及独立数据清理入口；明确删除全部数据时按 D06 删除流程完成后再卸载运行组件。若用户自行移除目录，不能承诺系统已清理全部副本。

## 15. 预算、响应与可访问性

页面只读取有界投影和游标分页，初始每页 50 项、每页硬上限 100；图展开初始最多 128 节点/2 跳，提供继续入口且显示截断。普通浏览和参数编辑不调用模型；设定语义编译、实验和支持解释消耗真实预算并在操作前展示额度。父操作租约跨领域共用，重试不刷新配额。

初始可修订默认：每角色同时 1 个实验计算和 1 个大数据维护操作，其他任务排队；共享宿主限制更严格时以 D11 为准。诊断原文捕获默认关闭；实验内容保留 7 天，临时导出文件保留 24 小时，并可立即删除/调短。期限以任务创建时的策略版本记录，后台清理失败显式报错；到期先阻断访问再分批清理。用户已下载文件不属于服务器自动清理范围。

上传限额取 D11 资源策略的压缩字节、展开字节、文件数、深度及可用磁盘上限，必须全部为有限正数；缺策略禁止导入而非无限解包。长作业支持进度、取消和恢复，取消是请求直至执行方确认；已完成提交不因关标签页回滚。

键盘可到达所有操作、焦点顺序与弹窗返回明确、图表提供文本表格、状态不只靠颜色、减少动态效果、支持缩放及窄屏、表单错误可读屏定位。日期显示时区，夏令时/模糊时间原值保留。数值配置展示单位、合法域及重置为默认入口。无障碍目标通过具体任务验收，不仅用自动扫描分数。

## 16. 完成边界

完整 D12 运行验收必须覆盖安装→创建→绑定→真实对话→观察修正→隔离实验→导出/迁移→升级故障恢复→删除/卸载全链，包含十一领域的真实响应。静态页面、截图、模拟数据或旧前端存在不能替代。

实施按领域 API/权限与能力目录、创作和观察、纠错与诊断、实验与数据生命周期、分发与平台验收推进；每步先编译再运行与新增能力相符的必要验证。具体角色内容、视觉风格和数值调优可继续编辑，工程接口和失败语义已在本稿定明。本次未写 UI、未运行模型/运行测试、未构建安装包或发布。

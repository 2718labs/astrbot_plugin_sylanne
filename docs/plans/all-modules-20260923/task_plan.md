# 十二模块完整设计收敛

用户目标：选择适合的下一模块，完整设计并考虑模块合作，持续到全部模块设计完成。本轮只做本地设计与评审，不实现、提交、推送、创建 PR 或发布。

## 顺序与分工

下一核心模块为 D08，将 D06/D07 的经历和判断接到目标、承诺与行动。逻辑设计顺序为 D08 → D05/D03/D02 的提供方 → D09/D10 的行为出口 → D11/D12 的运行与产品 → D01/D04 早期稿补齐 → 全系统联合审查。可独立编写的文档由受限子代理在当前工作区并行完成；不重启原十二个任务/工作树。

主任务负责公共协作规则、总装与验收。所有协作者遵循 [全系统合同](../../architecture/module-collaboration-contracts.md) 的唯一权威；有冲突先报告，由主任务协调，不另造旁路状态。按用户最新资源选择，Astra 只处理最重的跨域架构取舍；普通文档补漏交低成本代理。

## 完成条件

1. D01–D12 每个模块都有完整主规格（早期稿可加权威补充）、操作合同、需求/未来验收及当前源码差距；原用户方向保留。
2. 每模块覆盖目标、状态/唯一写者、核心机制、十一对端输入输出、正常/失败/时间/并发/权限/删除、预算、产品出口、实施依赖及未验证边界。未定工程细节采用明确且可修订的默认值，不空留待其他模块决定。
3. 共享事件/活动/尝试身份、事务/资源结算、必查与投递、模拟/实际、删除/恢复/迁移、版本兼容有统一合同及提供者接受矩阵。
4. 联合场景覆盖日常互动、误会修复、承诺/协作、独立生活、资源不足、跨会话/隐私、重启/离线、编辑/迁移/交付。
5. 独立跨模块审查的问题闭合；本地文档/链接/编号/所有权/需求覆盖检查及完成审计有证据。未来运行场景不写成已通过，历史测试不替代新设计验收。
6. 设计入口集中可浏览；只改指定文档，不覆盖已有脏改动、不写其他工作树。

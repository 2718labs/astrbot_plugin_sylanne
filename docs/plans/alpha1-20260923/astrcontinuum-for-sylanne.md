## 1. 产品边界

这个模块处理**最近 72 小时内，同一 D03 会话/受众范围的对话如何占用有限模型窗口**。它不搜索整个过去，不提炼长期“重要记忆”，不形成角色的主观回忆。超过 72 小时的历史只能由 D06 按触发和来源资格检索，再由 D07/D04 在需要时形成当前的回忆体验；D09 可以继续持有未答问题和话题状态，但不能把旧原文或旧压缩块自动塞回提示词。

真正的 KV 压缩论文操作模型内部的 Key/Value 张量及注意力权重；普通 API 调用不能取得或删改这些张量。本设计的“虚拟 KV”只是在**发送给 API 之前**组织提示词：近期原文保高分辨率，较早对话压成带检索键的短值，每轮根据当前问题选择保留哪些值。这是 KV 论文的选择思想在应用层的类比，不能据此声称降低服务端显存、获得论文中的解码加速或测到了模型真实注意力。

明确声明需要同会话近期对话脉络的模型调用才装配一条短期上下文带；D13 自身压缩调用及不需要对话史的领域调用不递归注入：

```text
稳定前缀：静态规则/工具定义｜已封闭压缩块的时间线｜最近已完成的原始回合
动态尾部：本轮领域状态/D06 获准材料｜本轮选中的细节值｜当前用户输入
```

**原始回合装得下就继续在前台使用原文；后台可提前预制待用块。** 真正需要切换时，把较早的连续回合换成短块，保留最近回合原文；本轮再按当前问题选择块内的细节。预制由增长水位触发，激活由窗口/费用条件触发，选值受当前问题影响，三者不能混为“搜索长期记忆”。没有第二套 D06 检索链，也不要求用户显式“调用压缩条目”。

## 2. 唯一状态与一块压缩物

D06 SourceRecord 保留实际入站和来源资格；D09 `ConversationTrack` 引用已提交的对话顺序、`TopicThread` 保留当前未答槽位；D11 执行日志给出实际投递/工具结果。草稿、未确定的发送结果和模型自述不写成已发生对话。以上仍是权威，压缩不能反向更新来源、记忆、人格、感受、承诺或发送事实。

只新增一种可删除的 D13 派生缓存：`CompressedTurnBlockV2`。它覆盖同一 owner、conversation、scene/audience 下**连续且已结束**的一组回合，包含 `first/last event ref, first/last trusted UTC, source refs + revisions, chronological_spine, detail_slots, exact_anchors, omission_ranges, compiler_version, created_seq, expires_at`。`chronological_spine` 是极短的时间顺序骨架；每个细节槽由 `key=(实体/话题/指代/行动类/时间锚)` 与 `value=(说话者、短文本、资格、来源片段)` 组成。键只供本轮选择，值才可能进入提示词；它们不是模型内部的 K/V 向量。否定、条件、说话者、工具失败/结果 unknown 不得被概括反转。单块不跨 D03 受众边界，也不跨超过 24 小时的受信时间区间。

块**只从原始已提交回合编译**，不从上一个压缩块再次压缩。每个块相互独立，按时间拼接，不维持滚动摘要链；重算或纠错仍回读原始来源。块只是“之前谈了什么”的上下文提示，不能证明外部事实、当前承诺或 Sylanne 刚刚实际回忆了什么。D08/D09 当前槽位和 D06 当前证据始终单独注入，不寄托在块内。

### 2.1 一块内容具体怎样变短

1. **切成原子回合。** 按实际入站、已交接的回复段、工具调用＋结果划分；同一平台消息重传只留一个引用，用户真实重复强调要保留。未封闭工具回合和发送 unknown 不写成成功。受众/场景改变直接断块。该步骤仅整理结构，不概括意思。
2. **先做确定性折叠。** 去掉模型不需要的传输包装、重复消息副本和工具原始载荷里的无关字段；同一连续回复的已交接段可在保留段引用后合并呈现。D09 从自身话题状态取得未答问题，D08 取得现行承诺，因而不在压缩块里重复维护“当前权威状态”。折叠后若已能满足块预算，不调用压缩模型。
3. **必要时生成骨架与细节槽。** 模型只读该块原始回合，输出按时间排列的 `asked / replied / corrected / deferred / topic_shift / tool_observed` 等短 beat：每段留一条最简时间线骨架，具体人名、指代、纠错、约束与工具状态进入带出处的细节槽。它不提炼长期偏好、人格或重要记忆，也不把用户陈述改成外部事实。默认目标约为折叠前文本的 **30%**，只是优化目标；保留必要信息达不到目标时允许更长或返回未压缩。
4. **锁住不能概括掉的锚点。** 当前话题所依赖的原话、姓名/对象、数字与时间、否定和条件、纠错后的有效说法、工具失败或结果未知，按原文或准确字段保留。模型可以压缩寒暄和已解决的反复解释，不能靠删限定语换取压缩率。重要细节若必须舍弃，按原始回合区间记 `omission_ranges`，不写成“这段从未发生”。
5. **验收候选。** D13 核对骨架和槽的引用确实落在该连续原文区间、说话者/顺序/结果状态正确、锚点和遗漏区间完整；无出处句子或“未知→完成”直接拒绝。机械检查不能证明所有改写都忠实，产品验收另用独立语义样本测误述率。候选失败时使用确定性摘录版本；摘录也装不下就保留可报告的缺口，不强制做第二轮无限修复。

例如原文依次是“周五提交”“不，改到下周一”“工具调用超时，是否完成未知”，压缩块可以写“用户先提周五，随后更正为下周一；执行状态未知”，并分别引用三处来源；不能写“周五已提交”。这个块在模型输入里标为短期对话脉络，D08 的真实期限和执行结果仍单独读取。

### 2.2 API 侧怎样借用 KV 的选择思想

论文启发只取三点：**保留最近窗口**、**保留反复被真正需要的关键位置**、**随当前 query 改变选择**。Sylanne 的可观察代理信号是当前用户输入、D09 话题/指代、D07 已选焦点、D08 必查以及用户后来确实重新提及的来源；不能读取真实注意力分数。历史槽被我们自己选进提示词的次数**不得**反过来提高其权重，否则会产生自我强化的“伪重视”。

每轮先为不可裁的当前问题、领域硬约束和 D06 必需证据预留额度，再给近期原始回合预算。剩余预算中，先保留压缩块的极短时间线骨架，让模型知道对话怎样走到现在；随后按 `当前指代/话题匹配 + 真实外部再提及 + D07 焦点相关 − 内容重复 − token 成本` 选细节槽。纠错和未解的引用优先于普通闲聊，但活跃承诺仍以 D08 当前状态为准。同一来源已有 D06 精确证据或近期原文时，不再放它的压缩细节。**被选中的槽不插回稳定骨架**，而是在本轮动态尾部按原始时间排序，附短时间/说话者/来源锚；若骨架本身都放不下，就从最旧区间开始删除并标出遗漏。此处是**查询条件下的提示词选择**，不是 D06 的历史证据检索。

旧段只留骨架，中段可多留细节槽，最近完整回合保留原文，形成随时间降低分辨率的三层表示。预算分配可依任务改变，而不固定每层占比；所有选择都必须在 D11 的一次冻结输入额度内完成。最终 prompt 只发送选中的 `value` 与必要时间/说话者标签，内部 `key`、打分和来源闭包留给 D13/D11 校验；D09 核验模型产出的表达时仍须追到当前原始来源。缩短的是本次 API 输入，不保证服务端真实 KV cache 或解码延迟发生同幅变化。

`ShortContextSliceV1` 是 D13 本轮交给 D11 的临时可裁短期片：选中块及槽、原始尾部、来源依赖、时间范围、遗漏区间、估算 token 与稳定前缀摘要。D11 将其与 D03 `ContextFrame`（按用途）、D06 必需证据、所属域当前投影/硬检查及当前输入组成 `ModelInputFrameV1`，最终计数、冻结摘要与外送资格归 D11。二者都不是另一份持久会话状态；调用回执只保存必要无内容引用和真实费用。

### 2.3 两个 token 账本与缓存重写成本

**窗口账本**数本轮实际输入 token，命中供应商缓存的 token 仍占模型上下文窗口；**费用账本**数未命中输入、命中输入、可能的缓存写入/存储、压缩任务自身输入与输出及最终实付。`cached_input_tokens` 若由适配器报告，是 `input_tokens` 的子集，不能再相加。费用预留不假设会命中：按适配器可能发生的**全量未命中或缓存写入中较贵者**，再加明确的存储费上界估算；供应商没有可验证价格/用量合同就按 D11 的未知费用规则处理。压缩任务也从同一父预算预留，不允许靠后台调用把前台节省的 token 再花光。可用窗口、单次费用与短期累计费用分别设上限；其中任何一个超限，都缩减可选细节或旧骨架，不能裁掉硬约束。

为了保住可复用前缀，D13 提供不因 query 改变的短期骨架与已完成原始尾部，D11 在不改变角色优先级和实际回合顺序的前提下，把**版本稳定**的规则、工具定义、已封闭块骨架和已完成原始尾部放在前面。新完成回合只向尾部追加；本轮 D06/D07/D08 材料、查询选中的细节和当前问题放在后面。静态规则或工具版本变化、受众/权限变化、块到期/纠错以及一次必要的前缀压缩可以重建前缀；平常的 query 变化不能触发重排、重写旧块或修改已发送回合。若某适配器无法保持上述顺序及角色语义，就只缓存其确实稳定的较短前缀，不能为命中率牺牲领域权威。前缀摘要按 provider/model、工具和模板版本、受众、块版本及原始回合顺序计算；命中是供应商回执中的实际观测，不由摘要推定。

**提前做、延后换，是无感压缩的核心。** D13 在未压缩原始回合达到对话预算约 **60%** 时，就冻结最早一段完整回合作为后台候选；D11 在父预算预留一次有界模型压缩费用，立即让后台作业异步运行，前台继续使用原文和既有稳定前缀。60% 是助手提出的初始预制线，70% 是期望候选已可用的检查点，实际阈值由 G6 的回合增长、作业 P95 与费用测量调整；若观测显示作业赶不上 70%，预制线可提前，但不能等到窗口耗尽才开始。候选只覆盖签发时已完成的最早连续回合，新回合仍追加到原始尾部，后台不随每条新消息重写候选。

这笔提前发生的压缩调用是换取前台零等待的**有界预制成本**，不能伪称完全免费。每会话至多一份正在运行或待用的候选；同一来源区间/版本不因每轮跨过阈值重复发作业。新候选在旧候选激活、失效或退役，且新积累的原始尾部再次达到预制线后才可签发。作业与前台回复共用 D11 父预算，但走低优先级后台并发/供应商限流份额，不能占用为当前回复保留的额度；无余量时延后后台派发，不让前台排在压缩作业后面。预算不足则不偷发后台调用，前台仍按明确覆盖范围运行。已外送调用的实际费用照收据结算。作业失败或候选不合格时不循环重试换摘要；下一轮是否再次预制取决于新来源进展或失效后的真实压力，而非定时轮询。

合格新块先处于**待用**，不因后台作业完成就改写在线提示词。下一次装配若继续使用原文将超过本轮窗口/费用上限，或有足够回执证明切换后的**未来增量费用**会下降，才原子替换其覆盖的旧原文；切换时希望保留约 40% 预算的近期原始尾部。激活只切换本地表示，不发起第二次模型压缩，也不等待后台。激活后保持块的原文区间不变，不因每轮查询在“原文/块”之间来回切换。切换决策不拿已付压缩费当成可追回的费用；G6 的**总成本**则必须把这笔预制费、首次新前缀与后续短前缀全部计入。实际放行始终按零命中和可能的缓存写入预留上界。窗口将装不下时立即使用已合格的待用块；窗口仍放得下且经济证据不足时，继续使用可复用的长前缀。待用块也计入本地容量上限并随来源更正或到期退役。每次重建在诊断里标明触发原因、覆盖区间、旧/新前缀摘要、实际输入及供应商回执；不为了凑缓存最低长度填充无用文本。

例如长提示词有 12k 输入 token，其中上轮回执显示 10k 命中缓存；后台已准备好 6k 的短表示，但首次使用它可能命中较少。窗口确实能省 6k，首轮需要新处理的输入却可能更多。因此候选提前异步做好，替换旧前缀则等到窗口/费用确有收益；已付后台费用如实计入，不把它从比较中抹掉。数字只是决策例子，不是 Sylanne 的实测结果。

W09 把缓存观测作为可选适配器能力交给 D11：总输入、缓存读取、缓存写入、显式存储费和最终账单各自标记 `reported / estimated / unknown`。当前 AstrBot Chat Completions 适配器只读取 `prompt_tokens` 和可选的 `cached_tokens`，未形成缓存写入/存储费回执，故它**不能单凭现有字段证明经济回本**。本地稳定前缀摘要仅用于解释重写，不能冒充供应商实际命中。D12 显示每轮窗口占用、实际缓存命中、压缩额外调用和累计实付；缺失项显示 unknown，不以估计值宣称省钱。

alpha1 默认不为三天短期对话建立需付存储费的供应商显式缓存，也不预热它。适配器若支持显式缓存边界，只允许在有权限、确实稳定且预算已覆盖的前缀上设置；本轮变化部分不主动写入。隐式供应商缓存的命中、保存时间和远端物理占用不能由 Sylanne 保证或直接清理；D11 只控制外送内容、可配置的缓存策略以及本地 8 MiB/256 块派生缓存。72 小时退役是**本地自动注入期限**，不是远端缓存删除声明。

## 3. 压缩何时发生，怎样用于下一轮

1. D11 为当前模型冻结输入/输出预算、提供者和计数 profile；调用领域为当前输入、D08 必查（若是行动）、D03 身份/受众、D09 未答槽位（若是表达）以及本轮 D06/D07 已获准材料预留额度。剩余部分是**可裁的对话上下文预算**，由同一父任务支付；压缩调用和不需要对话史的调用不请求 D13。
2. D13 通过 D06/D03/D09/D11 签出的 `ConversationWindowProjectionV1` 取最近 72 小时内该会话已提交的完整回合。先试原始回合；达到约 **60%** 的初始预制线时，按 §2.3 选取**最早的完整连续前缀**，目标覆盖约 30% 对话预算，使继续增长到约 70% 时仍能留下约 40% 的近期原始尾部。D11 当场预留一次有界费用并提交后台作业，前台不等。60%/70%/40% 是待 G6 验证的助手设计默认值，不能切断一组用户输入/实际回复或工具调用/结果。
3. D11 的现有 `PersistentJob` 在事务外按 §2.1 从原始来源生成候选；D13 校验引用、角色、顺序、事实/主观/未知资格、必要限定语及覆盖/遗漏。模型提出的精简措辞只是候选。提交时重验来源/受众/删除/激活版本和 job fence，将合格块写入共享图派生缓存作为待用块；当前正在进行的前台请求不因作业完成而改写。失败只留下原文和明确缺口，不生成假摘要。
4. 下一次装配先按 §2.3 决定继续原文，还是激活合格待用块；激活时再按 §2.2 选择时间线骨架、查询相关细节槽及尚未压缩的原始尾部，块与尾部不能重复代表同一回合。稳定骨架和原始尾部按时间顺序呈现，稀疏细节槽置于其后的动态材料区，按来源时间排序并保留锚点。预算再不足，舍弃最旧的骨架区间并记录所略区间，不递归压缩块。硬约束和 D06 必查结果不能为保留块而被挤掉。
5. D11 在完整实际载荷上核对与当前主模型 provider/model/config 匹配的窗口依据，以及 §2.3 的费用上界。精确计数器可用时重新计数；否则只接受安装适配器可核验的保守窗口上界，并明确标记计数资格。采用证据不足时块继续待用，后台压缩调用仍可在其签名报价、父预算预留及输入/输出约束内执行。外送前核验来源/权限/删除/激活；回执分别记录实际输入、实际命中、供应商有报告时的写入/存储费用及压缩任务花费，费用结算按适配器语义避免重复计数。结果采用、D09 表达核验和最终投递继续按各自合同。UTF-8 字节数本身只作本地诊断，不能冒充精确 token、可核验窗口上界、缓存命中或节省成本。

前台不等后台压缩完成。正常负载下应在真正需要替换前已有合格待用块；若突发巨量输入、作业超时或预算不足仍导致块未就绪，本轮保留预算内最近原始回合、当前槽位和必要证据，显式记录较早对话未覆盖，绝不为等待压缩阻塞用户回复；明确追问旧细节时由 D06 精确检索。这里仅有**一条**装配路径，块是其中可选的压缩表示，不另造“应急提示词模式”。无感是可测的前台 P95 目标，不对任意突发输入承诺零缺口。

## 4. 三天窗口、退役与物理上限

“三天”是**自动对话上下文的绝对边界**，按 D11 受信入站/获知 UTC 计算，不按压缩块最后使用时间续命。原始回合一旦早于当前受信时间 72 小时，就不再由 D13 自动带入；压缩块的 `expires_at` 不晚于其**最早**覆盖回合的受信时间＋72 小时，因此块还存在时，里面所有回合都在窗口内。创建压缩任务时已过期的前缀直接跳过。没有可信当前时间时停止自动读取/创建压缩块，旧事经 D06 自己的准入合同处理，不能假定“仍在三天内”。

到期块从 D13 可选集合退役，由 D11 回收其派生正文、索引和暂存任务内容，只保留必要的无内容回执。普通调用回执可记块使用情况，用于观测和容量淘汰，**不会延长到期时间**。退役既不删除 D06 来源/记忆，也不关闭 D09 当前问题或 D08 承诺；不存在“先把摘要转存为记忆”的自动升级。D06 独立依据原始来源决定长期记忆的编码、检索与删除。

为防三天内高流量无限增长，给每个 bot/persona 的压缩缓存设初始 **8 MiB 派生载荷或 256 块**的双上限，先到者生效；物理未回收占用计入上限。超额时淘汰最旧的块，必要时暂停新建块，保留原始来源并在 `ShortContextSliceV1` 标出覆盖缺口。阈值是待 G6 压测的工程默认值，不是插件 ZIP 体积。D11 的派生缓存要能真正回收内容，不能只从索引隐藏、在不可清理的图历史中继续累积。

来源更正、撤权、删除、受众变更会立即使受影响块停止进入新 `ShortContextSliceV1`；后台重编译只读取仍在 72 小时窗口内的合法原文。删除沿 D06/D11 独立日志与恢复水位清理缓存、模型请求、预览和受控备份。已外送/已交接范围按实际回执报告，不承诺追回。D12 区分“短期压缩块到期”与“记忆或来源被删除”，并显示容量、实际回收和遗漏。

## 5. 独立 AstrContinuum 与实施归属

独立 AstrContinuum 继续给其他机器人使用。Sylanne 的请求只由自身 `ModelBroker` 装配，不交给 AC 的全局 `on_llm_request` 改写；同宿主必须对 Sylanne bot/persona 排除 AC hook 或由安装诊断阻断重复注入。旧 AC Journal/Snapshot 不隐式导入，alpha1 只处理新会话。可借鉴 AC 的切段、来源覆盖、预算计数与后台恢复思路；默认不移植其 Repository、SessionKey、Snapshot/Delta、hook 或语义重组链。具体代码复用需记录版本、差异与 AGPL notice。

按 [alpha1 工作包](task_plan.md)：W00 冻结 `ConversationWindowProjectionV1/ShortContextRequestV1/CompressedTurnBlockV2/ShortContextSliceV1/ModelInputFrameV1` 合同；W03 给 D06 来源/资格/删除闭包；W05 给 D03 场景/受众版本；W08 给 D09 已提交对话顺序、话题与表达消费者；W14 独占 D13 骨架/细节槽编译、待用/激活和查询条件选择；W01 执行共享图任务、失效与物理回收；W09 接不可变模型请求及供应商缓存能力/实际费用回执；W10/W11 展示覆盖、到期、容量、缺口及输入/缓存费用；W13 执行下面的验收。先确保受影响 Python 可导入/编译，再跑必要合同与故障场景，最后真实宿主验证。

G6 对照还须固定同一输入、模型、预算和评估集，按同一回合到达时间回放，比较原文截断、v3 顺序摘要、v5 稳定前缀即压、v6 临近需要才做、v8 D13 异步预制后按需切换，在指代续接、更正保留、事实资格、误述率、输入 token、未命中/命中/写入 token、待用候选浪费、短期累计费用与**用户可见 P95 延迟**上的差异。v8 只有在相关质量、延迟和费用证据成立时才宣称优于简单摘要或 v6；不把 H2O、SnapKV 或 StreamingLLM 的模型内部加速数字套到 API 调用。

研究依据（只借选择原则，不照搬性能结论）：[H2O](https://arxiv.org/abs/2306.14048) 的近期＋高频重要位置、[SnapKV](https://arxiv.org/abs/2404.14469) 的末端观察窗口、[StreamingLLM](https://proceedings.iclr.cc/paper_files/paper/2024/hash/5e5fd18f863cbe6d8ae392a93fd271c9-Abstract-Conference.html) 的近期窗口与初始锚，以及 [Quest](https://arxiv.org/abs/2406.10774) 的 query 条件下选择。它们均需访问模型内部 KV/注意力信息；本方案只做 API 输入选择的类比。供应商缓存与窗口账本依据 [OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching)、[Claude Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) 和 [Gemini Context Caching](https://ai.google.dev/gemini-api/docs/caching) 的官方说明；具体字段、价格、缓存最低长度及策略按实际适配器能力测量，不跨供应商照搬。

以上是待执行场景，不是当前验收结果。长对话语义质量、真实 AstrBot 同宿主、删除/恢复和 G6 规模成本需实际测量；候选包仍须经 G0–G7 与确切哈希验收后才能称为 alpha1 可交付。

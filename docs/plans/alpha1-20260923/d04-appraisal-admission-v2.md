# D04 主观评价与语义映射准入：alpha1 实施默认值

2026-09-28。此文是总装实施裁决，尚非产品验收收据。D04 的感受由角色对事件的主观评价驱动；评价可以有偏差、竞争解释和未知。模型可以提出评价，不能自称外部事件属实、来源有权使用、数值剂量已校准或图状态已提交。

## 两段准入

第一段为**候选**：用当前对话主模型，输入经 D06 权限裁剪的事件片段、D03 对象身份、D01 活跃角色的相关价值/期待、D05 关系边界、D07 竞争解释与当前目标。输出严格解析为 `AppraisalBundle`、`MeaningFacet` 及八个机制的有界信号。模型须区分“角色认为发生了什么”与“已观察到什么”，允许多个解释和未知；一条来源的改写不能生成额外贡献。候选及原调用身份由 D11 记账，原文留在 D06，不把解释文字复制成事实证据。

第二段为**采用**：W01 在 Authority 写栅栏的同一图事务中，从当前图重读角色版本、来源/访问/删除/更正头、对象与受众、目标和解释依赖；把模型候选与冻结输入及付费原件逐字段核对。D04 的已安装映射资产把语义信号编译为 24D 机制剂量，并明确未知维度、总剂量上限及每个来源家族的跨块份额。图中提交带来源和版本的主观评价收据及贡献消费。任一缺失、撤权、竞争解释被否定、映射版本改变或同家族重复消费，整批拒绝。

“采用”只表示此角色在此时以这份解释参与了计算，不表示模型猜中了对方意图或心理学上真实的情感。外部事实仍以 D03/D06 的现实性和证据级别为准；当时已发生的角色感受保留历史引用，后续更正通过新事件改变现在及未来，不回写成“从未感受过”。D09 的自我表述另受当前披露和发送检查约束。

## 映射资产与校准边界

资产必须带 schema、内容摘要、适用 D01 角色/版本范围、24D 基底和八机制完整规则、每层增益、必需已知字段、来源家族剂量上限、可接受的现实性/解释等级、用于回归的有来源示例及预期方向。安装与采用分开：单测中能构造 `CompiledDrivePolicy` 不等于已有已安装映射。角色价值和经历改变时发布新资产或角色条件版本，不暗中改旧计算。无覆盖的语义保持候选/未知，不映射为零或“中性”。

alpha1 的校准只可证明内部一致性、剂量有界、来源及版本绑定、已列场景的方向回归；不能宣称临床或普适心理有效性。角色专属示例需经产品/Owner 明确选定后成为版本资产。没有这份资产或受信安装收据时，D04 数值产品链保持 HOLD，其他域仍可沿各自资格继续运行。

## 付费调用的实际接线顺序

W01 在 Authority 写栅栏下提交冻结的 `FrozenAppraisalRequestV1`、当前读集、D11 签名 quote/预留和唯一 persistent job；宿主从图当前读端取得原调用，核对已安装主模型 provider/model/config 与 exact wire 后经 Authority V2 发起一次模型调用。响应未知时先按原 call ID 恢复终态，不能生成第二笔原调用。Authority 记录实际费用、终态和内容摘要；W01 在另一写栅栏中核当前来源权限与原件，把结果读取和 D11 费用/任务终态同事务提交。只有这个已付费、可重读的输出才交给 `parse_appraisal_output_v1`，解析后仍是未受信的主观建议。

宿主现已支持可选 `d04.appraisal` 安装 workflow 与精确两消息线型校验；这只证明调用格式。专用 Authority result selector、W01 图内原调用与费用/终态原件、当前来源复核及产品采用仍未接通。单独新增一个恒返回 HOLD 的驱动器不能填补该链，余下入口需以同一原调用的受控正反例验收。

## 对现有实现的明确缺口

`model_broker` 新解析器只产未受信候选；`drive_allocation.py` 和 `family_drive_v2.py` 接受调用者提供的信号/剂量，尚不能证明信号由已采用评价与已安装资产生成。`d04_joint_advance_v2.py` 提供联合成员收据和重叠防护，不能代替当前图闭包、ABI2 full/LOO 核验、语义准入或原子贡献消费。W01 必须分别实现和绑定这些受信入口，才可解除 D04 mixed product read 的 HOLD。

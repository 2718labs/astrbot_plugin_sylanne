# D13 进入产品回复的后端切片

状态：架构裁决，尚未完成产品接线或验收。2026-09-28 本地冲刺；前端暂缓，不推送、不创建 PR。

## 当前边界

现有 `source_reply.v1` 冻结单条 D06 来源，模型正文每段必须逐字取自该来源；Authority 外送核验、结果读取和 D09 issuer 均复核这条约束。D13 的确定性后台作业目前只生成 `standby` 块。把块文字直接拼到该模板，会改变已签名的请求且使 D13 派生文本冒充事实来源，因此不能作为产品实现。

`ModelInputFrameV1` 目前只是数据合同；`actual_input_tokens` 没有受信计数器证明。D13 激活辅助函数接受外部传入的 token 数和窗口/费用布尔值，W01 还没有相应的 V2 激活提交口。字节长度只可用于粗筛，不是供应商输入 token 或缓存命中的实测值。

## 顺序

1. **冻结完整输入。** 新增版本化 `context_reply.v1` 模板与 D11 输入快照，分开当前问题、D06 合格证据/回忆、D07 焦点、必需的领域检查、D09 对话状态及低信任 D13 历史。当前输入和必需证据先占预算；历史可裁。输入快照绑定隔离、场景、受众、来源与访问版本、删除/激活代际及最短 TTL。冻结最终 system/user 消息及输出上限；完整输入的本地字节数只作裁剪预警，不写入 `actual_input_tokens`。现有 OpenAI-compatible 安装路径没有可信的派发前精确 token 计数接口；D11 在调用前按零缓存命中预留完整授权额度，调用后才从原始供应商 usage 回执记录实际输入、输出和缓存子量。需要精确窗口判定的激活分支在未安装同端点、同模型的可信计数能力前保持 HOLD。
2. **贯通产品回复。** 新模板与冻结快照贯穿安装工作流、原持久 job/acquire/call、Authority 外送核验、模型结果读取和 D09 issuer。Authority 从当前图重建同一输入及计数证据；不接受宿主自报数字或仅摘要。旧 `source_reply.v1` 的已付费结果仍按原模板解释，不换模板重试或生成新 call ID。当前 `context_reply.v1` 只能机械验证逐字引文，不能证明完整语义或自然表达；产品语言另按[合格自然表达 v2 裁决](d09-qualified-natural-expression-v2.md)保留逐字符资格映射并进行独立审查。D13 只能帮助理解对话，不作事实或情绪权威。未能核验的句子 HOLD。
3. **激活与消费 D13。** 在原始 Authority V2 写围栏内读取 standby、job/plan、当前来源闭包和缓存 revision，重编译并比较两份完整请求。若要声称模型窗口压力已被压缩解除，必须有与安装模型一致的可信计数能力，证明 raw 完整输入超限而 compressed 连同必需材料可容纳。没有可信费用证据时不使用 `proven_future_saving`。CAS 激活后，冻结请求绑定 active 块的引用、版本和全部当前依赖；外送前同步重验 72 小时及来源权限。旧事须经 D06 合法检索/回忆重新准入。

## 缓存与费用

稳定前缀身份绑定命名空间、受众、provider 配置、model、模板、工具版本和实际前缀字节；动态细节槽、当前问题与尾部属于完整请求摘要。不能把每轮变化的 raw tail 摘要当作稳定前缀，也不能用前缀摘要推断供应商缓存命中。

每次模型外送按零命中、可能的缓存写入与最大输出预留；真实回执结算，并把各 call 的费用累计。缓存 token 仍占输入窗口。D13 块未使用也保留其实际技术成本；费用未知不记零、不因块过期释放。72 小时是同步读屏障，异步清理另有回执；D13 不写回 D06/D07/D09 的权威状态。

当前可准确称为“后台确定性 standby 作业已接线”；激活、完整自然回复、真实节省和正式宿主验收均未完成。

## V2 原始调用身份与恢复约束（2026-09-28 总装裁决）

`context_reply.v1` 使用独立的持久 reply job、original operation、acquire operation 和 call ID。身份材料至少绑定 namespace、原 C02 operation/source、模板版本、安装模型和冻结请求摘要；不得复用 `source_reply.v1` 的已付费调用身份。W01 在同一图写事务中检查同一原始 C02/source 是否已有任一模板的准备、acquire 或未决记录，决定唯一模板并封存完整输入。旧模板一旦存在，就按旧请求/原 call ID 恢复，unknown 不换成 V2 再发；V2 一旦准备，同样不能在 raw 与 compressed 两种请求之间改签。

W09 Authority 只从 W01 的版本化原始 seal 和当前图重建冻结输入、来源祖先、访问/纠错头与低信任历史依赖，再签外送和结果读取。宿主传来的文本、token 数、digest 或 `D13 active` 标志不能自行证明资格。D09 采用时必须绑定同一 original call 的受信 result-read、D06 每个 claim span 的现行来源资格与 D08/D11 最终准入；模型输出解析器仅产生不受信候选。

原 prepare seal 的 `graph_guard_digest` 只证明准备时的 E+1 读集。acquire 本身会写持久 job、推进图 epoch；付费结果读取须分别验证原 seal 未被改写和**新的**当前完整读集/查询 epoch/权限删除代际，不能要求当前 guard digest 等于旧 guard digest，也不能借这个分离放宽来源撤权检查。

首次创建 V2 job 前可以选择已通过受信窗口/计数/预算核验的 D13 压缩版本；没有同安装模型的可信调用前窗口计数时，该分支保持 HOLD，仍可选择合法的未压缩请求。外送前再次从当前图重建 D13 slice 并检查 72 小时、权限、删除、激活与 cache revision。供应商缓存命中只由原始 usage 回执结算，不能参与调用前许可。该段是待接线合同，不表示已有 V2 job 或模型外送。

# 设计依据

- 当前用户明确要求完成记忆模块设计并考虑其他模块协作；现阶段本地设计，不进入实现或 PR。
- `design-recovery-20260922.md` C01/C02：误会允许影响态度；编码与回忆都经过情感加工；同一经历在不同心境下可有不同感受。
- 人格允许有经历依据的深层成长；情绪不采用固定标签状态机；共享图与来源为唯一权威。
- `affective-memory-mechanism-proposal.md` §§1—10 是已讨论的助手提案，仍需整体收敛。回忆后更新等未逐项批准，可在完整设计中作明确推荐选择，不能伪称用户已批准。
- 旧记忆主稿覆盖事件、来源、责任精查、纠错、删除、巩固、权限；旧理论稿覆盖按需触发与预算。新的情感/联想方案必须保留这些能力。
- 根历史计划有过时的活跃实施说明；需要导航到当前设计规格，不重写历史验收。
- 记忆对外要同时提供证据视图与主观回忆视图，避免“情感加工”变成伪造外部事实或把全部主观性约束掉。
- 独立审计：D03 世界事件和 D06 记忆分段须分开；解释按 D03/D07/D04/D01 语义域归属，自传/策略不由 D06 写真值。主规格 §2 已裁决。
- 同窗口实际重温不能被来源族+时间窗口去重吞掉；改用活动 ID，冷却另作准入。后台内部活动许可与主动消息许可分开。
- 当前 RecallPolicy 的 recall_experience 只是建议，不能证明实际进入注意；新合同要求 D07 SelectionTicket 和一致提交。
- 联想环不能写进失效 DAG；当前 catalogue 严格相等阻止直接加类型重开；主规格及合同已有独立关联类型与迁移前置。
- 当前 epoch 粗粒度会导致连续多域写入下的过期；合同选择快照/查询域代际与即时权限/删除代际，迁移前继续严格拒绝过期，不能承诺未测性能。
- 当前源父链不能被用于洗白“想象引发真实感受”；Recollection 区分内容现实性与活动执行资格，两个引用通道均参加权限/删除闭包。
- 当前主入口仍使用 fixture Store/Engine；新设计不能把 GraphStore 的存在等同真实宿主接入。

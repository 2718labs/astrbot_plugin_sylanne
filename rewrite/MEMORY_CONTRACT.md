# Persistent memory milestone: sources, interpretations and recall input

Implementation contract, 2026-09-22. Builds on GRAPH_CONTRACT and the approved memory/theory design. It is not full memory product acceptance.

## Typed values (`memory_types.py`)

All dataclasses frozen; JSON uses existing strict detach/finite validation. IDs/text must be nonempty, tuples unique nonempty strings. Times are finite nonnegative real values (never bool); intervals allow `end=None`, otherwise end >= start. Source text/claim bounded at 65536 characters to keep one record finite; source histories grow through independent records rather than a single persona JSON bucket.

- `SourceRecord(source_id,text,speaker_id,source_kind,assertion_status,occurred_at,recorded_at,provenance_root,audiences,purposes,parent_source_ids=(),independence="unknown")`.
  - source_kind: observed/reported/authored/internal/simulated; assertion_status: confirmed/reported/disputed/unknown. Receiving a report does not confirm its content. `occurred_at` may be None for unknown; `recorded_at` must be real.
  - independence: same_root/independent/unknown; a new message ID is not proof of independence. Parent IDs preserve propagation links.
  - audiences and purposes are explicit tuples (no wildcard). They are initial access rules; purposes from context/expression/consolidation/audit. No interpretation may broaden source access.
- `InterpretationRecord(interpretation_id,source_ids,subject_id,claim,status,valid_from,recorded_at,valid_to=None)`; status confirmed/reported/disputed/unknown/retracted. At least one source required. Sources remain immutable when this current interpretation changes.
- Both have `.to_dict()` and strict `.from_dict(value)` rejecting extra/missing fields.
- `source_key(bot,persona,source_id)` and `access_key(...)`: Owner(event,bot,persona,source_id), types `memory.source`/`memory.access`, name `record`/`access`.
- `interpretation_key(bot,persona,iid)`: Owner(event,bot,persona,iid), type `memory.interpretation`, name `current`.
- `register_memory_types(registry)` adds the three exact types; source is immutable/source role, access is mutable/state, interpretation is mutable/state. Access JSON exactly `{source_id,audiences,purposes,status,recorded_at}`, status active/withdrawn. Access validation canonicalizes nothing silently.

## Graph query (`graph_store.py` + `graph_types.py`)

Add `GraphPage(snapshot,next_after)` where snapshot is GraphSnapshot and next_after is AtomKey or None. `GraphStore.graph_query(bot,persona,*,type_names=(),owner_kind=None,subject=None,after=None,limit=100,expected_epoch=None,include_invalid=False)`:

- One coherent read transaction; exact namespace, registered type list, optional exact owner kind/subject; keyset order by canonical token, at most limit+1 database rows to detect continuation. limit exact int 1..512, include_invalid exact bool. Empty type_names means all registered types; after must belong to namespace.
- Return current namespace epoch even for zero hits. expected_epoch (NamespaceEpoch) guards multi-page scans and rejects any intervening namespace write. Never silently mix pages from different state versions.
- Add a namespace/type/token SQLite index. This is authoritative structured querying, not semantic/vector retrieval or an audience authorization boundary.

## Repository (`memory_repository.py`)

`MemoryRepository(store,bot,persona)` uses that same GraphStore. It does not own/close the store. Synchronous methods are intended for bounded off-thread callers. All event scopes must match bot/persona. Domain graph candidates use full reads and snapshot epochs; no hidden retry of stale values.

- `ingest(event,source) -> GraphReceipt`: atomically create immutable source and initial access. Source ID differing content cannot overwrite even under another event. Validate all referenced parents exist as memory.source in same namespace, reject simulated-to-observed laundering: a source with a simulated ancestor cannot claim a non-simulated origin. The repository trusts caller attribution, does not certify real-world independence. Parent lineage may not broaden audiences/purposes. Parent source/access versions are read for CAS, but immutable sources carry lineage in payload rather than invalidating graph dependency edges.
- `interpret(event,record) -> GraphReceipt`: validate source records and active access, require observed sources for a confirmed external claim (reported/simulated/authored/internal alone insufficient); source/access keys become dependencies. New revisions recorded_at must strictly advance; first insert can have any valid recorded_at. Keep previous graph history. If current atom was invalidated, a newer corrected interpretation may rebuild it. Duplicate event must return original receipt, not fail a new domain timestamp/immutability check: provide an explicit graph event receipt lookup or repository preflight plus commit recheck.
- `set_access(event,source_id,*,audiences,purposes,status,recorded_at) -> GraphReceipt`: monotonic recorded_at, validate source, update access; graph invalidation immediately invalidates dependent interpretations/views. Parent permissions always rechecked when reading descendants, so a restriction of an ancestor cannot leak through a stored child source. This is logical access withdrawal; not physical erasure.
- `read_source(source_id,*,audience,purpose,as_known_at=None) -> SourceRecord|None`: read source and access coherently, recursively check parent access with visited set, preserve real namespace epoch. Missing/withdrawn/unauthorized/too-new source returns None; do not reveal raw inaccessible content. Current access always governs even for historical queries.
- `read_interpretation(iid,*,audience,purpose,as_known_at=None,valid_at=None) -> InterpretationRecord|None`: current valid atom only in this first API; reject rather than silently use old history when current recorded_at > as_known_at. Full historical interpretation reconstruction is a later API and must not be falsely claimed. Source/ancestor access checked coherently. retracted returns None for current decision queries. valid_at uses closed start/open end semantics (end excluded).

Implementation may add private helpers on GraphStore for one-lock coherent domain snapshots/receipt lookup; direct SQL is allowed only in this trusted repository against the same connection under its lock/transaction, no second truth store or persona-wide list. Public read results must never be assembled from independently changing snapshots.

## Initial indexed retrieval (`memory_retrieval.py`)

Next implementation after repository: task/audience/time-aware query with bounded page count and explicit coverage, sources and interpretations recalled through repository access checks, returned graph source/access/epoch versions; then connect RecallPolicy. This initial milestone must not claim this stage is already present just because structured graph_query exists.

### Executable retrieval slice (2026-09-22 continuation)

- Repository additionally exposes `read_source_evidence` and `read_interpretation_evidence` with the ordinary read arguments plus `max_nodes=512` (exact int 1..4096). They return `(record_or_none, GraphSnapshot)` from one coherent transaction. Proof atoms retain keys/revisions/validity but have empty values; inaccessible content is never exposed in a proof. All traversed source/access/ancestor atoms are included. Unique atom reads are bounded; exhaustion raises `CapacityExceeded`. Ordinary reads delegate to these methods.
- A missing or already invalid interpretation can return `None` with just its sanitized atom and namespace epoch. This is a conclusive denial proof; it must not traverse unusable ancestry solely to fill a diagnostic proof or exhaust the node budget. Complete lineage is required for a record that will actually be returned as authorized evidence.
- Repository operation events bind the original event and operation arguments in a deterministic envelope before graph receipt lookup/commit. Reusing an event for changed operation data conflicts; an identical retry returns its original receipt even after subsequent state revisions.
- Duplicate preflight and domain validation use the same read transaction, including when a second GraphStore connection writes concurrently; final graph commit rechecks identity/CAS. Keyed record IDs must match payload IDs. Confirmed interpretations need supporting sources that are both observed and confirmed. Interpretation dependencies include the complete traversed source/access ancestry so ancestor withdrawal invalidates downstream projections. Mutation ancestry traversal is bounded too.
- `MemoryQuery(kind, ids=(), terms=(), subject_id=None)` is a frozen exact query specification. Kind is source/interpretation; ids and terms are unique tuples of nonempty strings; at least one filter is required. Source subject means speaker_id; interpretation subject means subject_id. Terms are casefolded substring conjunctions over text/claim, not semantic answer verification. IDs, terms and subject filters combine with AND. Bounds: at most 64 IDs, 16 terms of at most 256 characters each.
- `MemoryRetriever(repository).search(query, *, audience, purpose, as_known_at=None, valid_at=None, max_candidates=64, max_nodes=256, page_size=32, max_pages=4, expected_epoch=None, after=None)` returns a frozen batch of authorized `MemoryHit` records, complete source/access/interpretation version references, namespace epoch, candidate/node/page usage, continuation and an explicit `complete` flag. Candidate/page/node limits are enforced; node exhaustion returns an incomplete batch rather than a false exhaustive miss. Limits are exact positive ints; candidates <=4096, nodes <=4096, page_size <=512, max_pages <=64.
- A hit contains its graph key, typed record and proof versions. Source hits expose that source's provenance root. Interpretation provenance is resolved from authorized supporting source records at the same epoch. Provenance families remain attribution data, never a certification of independent acquisition.
- Explicit ID queries use sorted exact graph keys and bounded point snapshots, avoiding scans of unrelated namespace records. Missing requested IDs still count as inspected candidates. Other structured graph pages use the existing namespace/type/token index; content predicates are evaluated within bounded candidate pages. This slice is not a full-text/vector index and makes no large-corpus speed or semantic-relevance claim.
- Every page and repository proof must match the initial epoch; check the epoch once more before returning. Intervening writes raise `StaleRead`, never mix old and new permissions. The batch is a versioned historical snapshot; the caller must revalidate its epoch immediately before using it for a new decision. `valid_at` filters interpretation validity; source records represent recorded occurrences rather than validity intervals.
- The recall bridge maps named gaps to explicit MemoryQuery predicates. A predicate match fills only that declared retrieval gap, not the truth of an arbitrary proposition. Unsupported commitment/deadline/classification checks remain unresolved. No lexical hit may satisfy these mandatory checks. Readiness never authorizes external action.
- Exact-check and working-set stages reserve candidate/node capacity before dispatch just like search stages; actual unused capacity is refunded. The bridge's current mandatory-check implementation returns unresolved checks without querying or spending graph capacity. Every actual retrieval, including misses and denied records, charges its reported candidate and node usage; ancestry exhaustion conservatively charges the remaining allowance.
- Retrieval is synchronous and bounded for off-thread callers. This slice does not claim host integration, durable working-set/cooldown, asynchronous cancellation, historical interpretation reconstruction, physical deletion, embedding search or a finished memory product.

## Acceptance required

Real SQLite source/access atomicity, strict schemas, conflicting source overwrite rejection, event duplicate with fresh state, explanation revision while original source retained, domain invalidation, cross-persona isolation, private source not returned for public expression, ancestor access withdrawal propagates to retrieval, unknown/report/simulation provenance, no historical knowledge leakage, valid-time boundary, paged epoch consistency and empty-query phantom guard. Host adapter and real model acceptance remain separate gates.

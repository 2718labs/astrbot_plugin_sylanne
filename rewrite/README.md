# Embodiment 3.0 development slice

`rewrite/` contains the new 3.0 engineering foundation used by the sole root `main.py` entry point. It is an early implementation slice, not a complete 3.0 product or a production/platform acceptance package. The user explicitly retired the old interfaces and core. See the [heavyweight product architecture](../docs/architecture/embodiment-3-system.md) for the final system scope.

See [acceptance evidence and limitations](ACCEPTANCE.md), [architecture decisions](DECISIONS.md), and [typed event/engine contract](ENGINE.md) for the current milestone and next phase.

The latest local slice is [persistent memory and recall integration](MEMORY_ACCEPTANCE.md), specified in [the memory contract](MEMORY_CONTRACT.md). It adds source/access/interpretation persistence, bounded authorized retrieval and actual-data recall control. Full memory semantics and the new chain's host integration remain open.

The next slice is specified in [the host integration contract](HOST_CONTRACT.md). It uses one bounded model call to propose a strict appraisal/evidence pair, persists ingress before that call, and renders the committed action through deterministic templates. The two-component state, appraisal mapping and one-second message episode remain uncalibrated integration assumptions. They do not freeze the final personality, relationship or emotion design.

Run the local Python demo or tests with the rewrite root on `PYTHONPATH`:

```powershell
$env:PYTHONPATH = (Resolve-Path .\rewrite).Path
python -m unittest discover -s rewrite/tests -p 'test_*.py' -v
```

After the native library has been built (run `python rewrite/tools/verify.py` or
`cargo build --release` in `rewrite/native`), the local demo can be started with:

```powershell
$env:PYTHONPATH = (Resolve-Path .\rewrite).Path
python -m sylanne3.demo
```

From the repository root, the one-command acceptance script is:

```powershell
python rewrite/tools/verify.py
```

It checks the native crate with `cargo fmt --check`, `cargo check`, `cargo test`, and `cargo build --release`, runs the Python tests and compilation check, and writes timestamped stdout/stderr/exit/time evidence under `rewrite/artifacts/`. It also performs a static AST import-boundary check over the new entry point, `sylanne3` and `tools`; this is a boundary check, not a complete security proof. A failed or unexecuted item cannot be reported as PASS.

The native DLL is generated by `cargo build --release` under `rewrite/native/target/` and is intentionally not committed. The native binding requires that built library and does not silently fall back to the legacy implementation.
